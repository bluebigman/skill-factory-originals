| 维度 | 能做 | 不能做 |

| 对比维度 | 功能清单比对、定价档位归类、用户评价情感倾向提取 | 不进行财务建模、不预测市场走势、不评估专利风险 |
| 输出形式 | 生成 Markdown 报告、CSV 对比矩阵、JSON 结构化数据 | 不生成 PPT、不自动发送邮件、不连接外部数据库 |
| 分析深度 | 基于输入信息的客观归纳与差异点罗列 | 不进行主观臆断、不补充输入中不存在的"行业常识" |

**适用对象**：产品经理、市场分析师、创业者、投研人员，以及任何需要快速梳理竞品格局的个人或团队。

## 三、标准执行流程

### 3.1 前置条件

在执行前，请确认以下事项：

| 检查项 | 要求 | 不满足时的处理 |
|--------|------|---------------|
| 输入文件格式 | CSV / JSON / MD / TXT | 先进行格式转换，或手动粘贴为纯文本 |
| 文件命名规范 | 建议 `竞品名_数据类型.扩展名`，如 `产品A_功能.csv` | 自动按文件名首段识别竞品名，无法识别时使用 `未命名竞品N` |
| 数据字段完整性 | 至少包含：竞品名称、对比维度（功能/定价/评价任一） | 缺失字段在报告中标注 `[需核实:字段名]` |
| 数据量 | 单次建议 3-10 个竞品，每个竞品 5-50 条记录 | 超出时自动分批处理，输出汇总索引 |

### 3.2 执行步骤

**第一步：数据装载与校验**

1. 扫描当前目录下所有符合命名规范的文件。
2. 解析文件内容，识别竞品名称、数据类型（功能/定价/评价）。
3. 对每条记录执行字段完整性检查，缺失项标记为 `[需核实:字段名]`。
4. 输出数据装载摘要：`已装载 N 个竞品，共 M 条记录，发现 K 处字段缺失`。

**第二步：单样本试运行**

1. 选取第一个竞品的完整数据作为测试样本。
2. 执行完整的对比分析流程，生成该竞品的独立画像。
3. 核对输出字段是否齐全、格式是否符合规范。
4. 若发现格式异常，调整解析规则后重新执行。

**第三步：全量批量执行**

1. 确认试运行无误后，对全部竞品数据执行分析。
2. 生成三个核心输出：
   - **功能对比矩阵**：竞品 × 功能点 的布尔矩阵（支持/不支持/部分支持）
   - **定价档位分布**：按价格区间归类，标注免费/付费/混合模式
   - **评价情感摘要**：正面/负面/中性关键词统计，附典型引文
3. 基于上述输出，生成差异化建议清单。

**第四步：结果校验**

1. 随机抽取 20% 的输出条目，与源数据逐项核对。
2. 重点检查：竞品名称拼写、功能点归属、价格数值、评价引文准确性。
3. 发现不一致时，定位源数据并修正，同时记录修正日志。
4. 输出校验报告：`校验通过率：X%`，低于 95% 时提示重新检查源数据。

## 四、置信度门控机制

本 Skill 严格遵循"不编造"原则。当遇到以下情况时，输出占位符而非猜测值：

| 场景 | 输出占位符 | 后续处理建议 |
|------|-----------|-------------|
| 某竞品的某项功能未在数据中提及 | `[需核实:功能-{功能名}]` | 查阅该竞品官网或产品文档 |
| 定价信息缺失 | `[需核实:定价-{竞品名}]` | 访问定价页面或联系销售 |
| 评价数据不足（少于 3 条） | `[需核实:评价-{竞品名}]` | 补充更多用户反馈来源 |
| 数据文件命名无法识别竞品名 | `[需核实:竞品名-文件{序号}]` | 重命名文件后重新执行 |

**置信度分级**：

- **高置信度**：所有关键字段均有数据支撑，缺失率 < 5%
- **中置信度**：缺失率 5%-20%，或存在部分推断性结论
- **低置信度**：缺失率 > 20%，或关键对比维度数据不全

置信度评估结果将显示在报告末尾，供使用者判断分析可靠性。

## 六、常见陷阱与反模式对照

|----------|-------------|-------------------|
| P-01 | 将不同时间点的数据混为一谈，导致对比失真 | 在报告中标注每条数据的采集时间，不同时间点的数据分开展示 |

| P-05 | 差异化建议脱离数据支撑，凭主观经验发挥 | 每条建议必须引用对比矩阵或评价摘要中的具体数据点 |
