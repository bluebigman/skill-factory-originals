## 三、标准流程：从输入到输出

### 3.1 前置条件

| 条件 | 要求 | 不满足时的处理 |
|------|------|---------------|
| 竞品数量 | ≥ 2 家 | 提示"资料不足"，建议补充至少 1 家竞品资料 |
| 资料格式 | 支持 txt / md / pdf / docx / csv | 提示"格式不支持"，列出支持格式 |
| 信息完整度 | 每家至少包含 3 个维度的信息 | 缺失维度标注 `[需核实:维度]` |
| 敏感信息 | 输入文件中不得包含 API key 等 | 自动过滤，不写入报告 |

### 3.2 执行步骤

**步骤 1：资料接收与校验**

- 读取输入文件，识别竞品名称与数量
- 校验是否满足前置条件（≥2 家竞品）
- 扫描敏感信息并标记过滤

**步骤 2：信息抽取与分类**

- 按功能、定价、评价三个维度抽取关键信息
- 建立竞品-维度-信息的三层索引结构
- 对缺失信息打上 `[需核实:字段]` 占位标记

**步骤 3：多维对比矩阵构建**

- 功能维度：提取功能点，建立功能-竞品布尔矩阵
- 定价维度：解析价格数值、套餐层级、计费周期
- 评价维度：提取评分、正负面关键词、高频评价主题

**步骤 4：差异分析与机会识别**

- 计算各竞品的功能覆盖度与重合度
- 识别功能空白区（所有竞品均未覆盖的功能点）
- 分析定价区间分布，寻找价格空档
- 归纳评价中的共性痛点与未被满足的需求

**步骤 5：报告生成与输出**

- 按用户选择的格式（表格/报告/速览）生成输出
- 确保所有数据点均有来源标注
- 输出差异化建议清单（按可行性排序）

### 3.3 输出规范

**输出结构（完整报告模式）**

```
# 竞品分析报告：{赛道名称}
## 1. 分析范围与数据来源
```

## 六、FAQ 反模式对照

| 常见坑 | 反模式（错误做法） | 正模式（正确做法） |
|--------|-------------------|-------------------|
| 数据编造 | 竞品价格未知时，凭经验"估计"一个价格 | 标注 `[需核实:定价]`，并列入核实清单 |
| 样本偏差 | 仅凭 1-2 条评价就下结论"用户普遍认为" | 标注评价样本量，样本不足时提示"评价数据有限" |
| 维度遗漏 | 只对比功能，忽略定价和评价维度 | 至少覆盖功能、定价、评价三个核心维度 |
| 绝对化表述 | "本品完全优于竞品" | 使用"在 XX 维度上具有优势"的相对表述 |
| 忽略来源 | 报告不标注数据来源 | 每个数据点标注来源文件或页码 |
