## 三、标准处理流程

### 3.1 前置条件

| 条件项 | 要求 | 检查方式 |
|--------|------|----------|
| 输入文件 | 文件大小 ≤ 50MB，编码为 UTF-8 或 ASCII | 使用 `file` 命令或 `wc -c` 检查 |
| 输入目录 | 待处理文件已放入同一目录，命名含批次标识（如 `batch1_*.csv`） | `ls -la` 查看 |
| 输出目录 | 已创建 `output/` 目录，且具有写权限 | `mkdir -p output && touch output/.write_test` |
| 格式约定 | 用户已明确输出格式（JSON/CSV/Markdown）或接受默认 JSON | 与用户确认 |

### 3.2 执行步骤（分步编号）

**Step 1：输入确认**
- 列出所有待处理文件，确认命名规范一致。
- 与用户核对：输入类型（文件/URL/直接粘贴）、输出格式、是否需要批量。

**Step 2：单样本试运行**
- 取第一个文件执行完整流程。
- 核对输出字段是否完整、格式是否正确。
- 若发现问题，调整解析规则后重试。

**Step 3：批量执行**
- 确认单样本无误后，对全量数据执行。
- 保留原始文件备份（复制到 `backup/` 目录）。

**Step 4：结果校验**
- 随机抽查 10% 输出条目，核对关键字段与源数据一致性。
- 检查置信度标注是否合理。

**Step 5：输出交付**
- 将结果文件放入 `output/` 目录。
- 生成处理报告（含文件数、成功/失败数、平均置信度）。

### 3.3 输出规范

**默认输出格式（JSON）**：


## 四、置信度门控

### 4.1 置信度判定规则

| 置信度等级 | 判定条件 | 示例 |
|------------|----------|------|
| `high` | 字段值直接从源数据提取，无歧义，格式完全匹配 | 标准日期格式 `2026-08-18` |
| `medium` | 字段值经过推断或格式转换，存在轻微不确定性 | 从自由文本中提取的姓名 |
| `low` | 字段值缺失、冲突或需要人工确认 | 两个来源数据不一致 |

### 4.2 信息不足时的处理

当输入信息不足以确定字段值时：

1. **不编造**：绝不填充猜测值。
2. **使用占位符**：输出 `[需核实:字段名]` 作为字段值。
3. **标注置信度**：该字段置信度强制设为 `low`。
4. **生成警告**：在 `warnings` 数组中添加说明。

**示例**：

```json
{
  "fields": {
    "user_email": {
      "value": "[需核实:user_email]",
      "confidence": "low"
    }
  },
  "warnings": ["user_email 字段在源数据中缺失，请人工补充"]
}
```

### 4.3 二次确认机制

当出现以下情况时，暂停处理并向用户确认：

- 超过 30% 的字段需要占位符。
- 输入格式与用户描述严重不符。
- 用户指定的输出格式与数据内容不兼容。
