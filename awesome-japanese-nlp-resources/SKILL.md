## 六、FAQ 与反模式对照

### 常见坑 1：混淆库与模型

- **错误做法**：用户说"给我一个日语BERT"，但实际需要的是"使用 BERT 的库"。
- **反模式**：直接推荐 `transformers` 库，而不说明它需要配合具体模型权重。
- **正确做法**：区分"库"（如 `transformers`）和"模型"（如 `cl-tohoku/bert-base-japanese`），分别列出。

### 常见坑 2：忽略环境约束

- **错误做法**：用户要求"离线可用"，却推荐需要联网下载模型的方案。
- **反模式**：推荐 `fugashi`（需额外下载词典）而不提示离线安装步骤。
- **正确做法**：标注"离线可用性"字段，并给出离线安装提示。

### 常见坑 3：许可证混淆

- **错误做法**：将 GPL 许可证的资源用于商业项目。
- **反模式**：推荐 `MeCab`（BSD 许可证）时未说明其词典可能采用不同许可证。
- **正确做法**：明确区分"库许可证"与"数据许可证"。

### 常见坑 4：版本兼容性

- **错误做法**：推荐 Python 2 时代的库而不提示兼容性问题。
- **反模式**：推荐 `CaboCha` 时未说明其 Python 绑定可能需要额外编译。
- **正确做法**：标注"Python 版本兼容性"字段。

### 常见坑 5：语料规模误解

- **错误做法**：用户以为"小语料"适合训练，实际需要百万级数据。
- **反模式**：直接推荐小规模语料而不说明其适用场景。
- **正确做法**：标注语料规模（句数/词数），并说明建议用途。
