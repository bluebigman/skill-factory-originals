## 一、能力边界

### 1.1 能做什么

| 能力项 | 说明 |
|--------|------|
| 音频转写文本清洗 | 去除口语填充词（嗯、啊、那个）、重复片段、无意义语气词 |
| 段落与话题切分 | 根据语义转折、停顿特征、说话人变化自动切分段落 |
| 说话人标注 | 识别不同发言者，以`[说话人A]`、`[说话人B]`形式标记 |
| 格式标准化 | 统一标点、数字、时间格式，适配不同下游场景 |
| 摘要与要点提取 | 输出单段摘要 + 3-5 条行动要点 |
| 多场景模板输出 | 支持会议纪要、访谈稿、播客文案、课程笔记、字幕稿五种模板 |

### 1.2 不能做什么

| 限制项 | 说明 |
|--------|------|
| 不进行事实核查 | 转写文本中的事实错误、数据偏差不在本 Skill 处理范围内 |
| 不补充未出现在音频中的信息 | 所有输出内容必须来源于输入文本本身 |
| 不进行情感倾向判断 | 不输出"积极/消极/中立"等情绪分析结论 |
| 不翻译 | 如需翻译请使用翻译类 Skill |
| 不处理非中文音频 | 本 Skill 仅面向中文转写文本，暂不支持中英混合或纯外语文本 |

### 1.3 适用对象

- 会议纪要整理者
- 播客/视频内容创作者
- 采访记者与编辑
- 课程内容运营人员
- 需要将口语转书面语的学生与研究者

## 三、标准流程

### 3.1 前置条件

- 输入文本必须是**纯文本**格式（`.txt`、`.md`、`.docx` 提取后的文本均可）
- 输入文本建议长度 ≥ 200 字；少于 200 字仍可处理，但段落切分效果可能受限
- 如需说话人标注，输入文本需包含说话人标识（如"张三："），否则按单一说话人处理

### 3.2 执行步骤

#### 步骤 1：原始文本接收与清洗

- 去除时间戳残留（如 `00:12:34` 仅保留时间轴模式时使用）
- 删除重复标点、多余空格、乱码字符
- 口语填充词清除：`那个`、`就是`、`然后`（连续使用超过 3 次时保留首个）、`嗯`、`啊`、`对吧`（无实义时）

**清洗示例：**

```
清洗前：嗯...那个我们今天讨论一下，就是，然后关于新产品的，然后定价策略，啊对吧？
清洗后：我们今天讨论一下新产品的定价策略。
```

#### 步骤 2：段落切分与话题标记

- 按语义完整性切分段落，每个段落表达一个完整意思
- 段落间有明显话题转向时，插入`## 话题标题`（自动提取 4-8 字关键词）
- 单段长度建议控制在 80-150 字

#### 步骤 3：说话人识别与标注（可选）

- 输入文本含说话人标识时：保留并统一格式为 `[说话人A]`、`[说话人B]`
- 输入文本无标识时：根据语义推断，仅在有明确转折时标注`[说话人A]`，其余不标注

#### 步骤 4：格式标准化

| 项目 | 规则 |
|------|------|
| 标点 | 统一为中文全角标点，句号结尾 |
| 数字 | 保持阿拉伯数字，千位分隔符统一 |
| 时间 | 统一为 `HH:MM` 或 `HH:MM:SS` 格式 |
| 专有名词 | 保留原文，不擅自缩写或全称化 |
| 引语 | 直接引语用引号，间接引语不用 |

#### 步骤 5：模板适配输出

根据触发场景选择以下模板之一：

**模板 A：会议纪要**

```markdown
# 会议纪要：{会议主题}

- 日期：{日期}
- 参会人：{名单}
- 时长：{时长}

## 议题概述
{2-3 句概括}

## 核心讨论
### {议题1}
{要点}

### {议题2}
{要点}

## 决议事项
- [ ] {事项1}（负责人：{姓名}，截止：{日期}）
- [ ] {事项2}

## 待跟进
{未决事项清单}
```

**模板 B：访谈稿**

```markdown
# 访谈实录：{受访者姓名}

**采访者**：{问题}
**受访者**：{回答}

**采访者**：{问题}
**受访者**：{回答}

---

**本期要点**：
1. {要点1}
2. {要点2}
```

**模板 C：播客章节**

```markdown
# {播客名称} 第 {期数} 期

## 章节
| 时间戳 | 章节标题 | 内容简介 |
|--------|----------|----------|
| 00:00 | 开场 | {简介} |
| 05:30 | {话题1} | {简介} |
| 12:45 | {话题2} | {简介} |

## 本期金句
> "{精彩原话}"
```

**模板 D：课程笔记**

```markdown
# 课程笔记：{课程名}

## 知识结构
- 主题1
  - 子概念1.1
  - 子概念1.2
- 主题2

## 关键定义
- **{术语}**：{定义}

## 易混点
- {概念A} vs {概念B}：{区分要点}
```

**模板 E：字幕稿**

```markdown
00:00:01.000 --> 00:00:04.500
{第一句字幕}

00:00:04.600 --> 00:00:08.200
{第二句字幕}
```

### 3.3 输出规范

- 输出格式为 `.md` 文件风格，可直接保存为 Markdown
- 输出开头必须包含：原输入字数、清洗后字数、段落数、处理耗时（模拟值）
- 输出末尾附带 3-5 条行动要点（仅会议纪要模式）
- 所有输出内容严格来自输入文本，不新增外部信息

## 四、置信度门控

### 4.1 信息不足处理规则

| 场景 | 处理方式 |
|------|----------|
| 说话人身份不明 | 输出 `[说话人A]`，不猜测姓名 |
| 时间信息缺失 | 输出 `[需核实:日期]` 占位 |
| 专有名词拼写不确定 | 保留原音，输出 `[需核实:专有名词]` |
| 语义模糊段落 | 标注 `[需核实:此段语义不清晰]` 并保留原文 |
| 数字单位缺失 | 输出 `[需核实:单位]` 占位 |

### 4.2 禁止行为

- 不根据上下文推断缺失信息后直接填入
- 不修正说话人可能的语音错误（如人名、地名）
- 不删除存在疑问的段落

## 五、错误码体系

| 错误码 | 触发条件 | 提示话术 | 修正步骤 |
|--------|----------|----------|----------|
| `ERR-INPUT-EMPTY` | 输入文本为空 | "未检测到有效文本，请提供转写内容" | 检查输入文件是否为空，重新传入 |
| `ERR-INPUT-TOO-SHORT` | 输入文本 < 50 字 | "文本过短（少于50字），段落切分可能不准确" | 确认是否只输入了片段，补充完整文本 |
| `ERR-FORMAT-UNSUPPORTED` | 输入非纯文本格式 | "仅支持纯文本格式（txt/md），请先转换" | 将 Word/PDF 内容复制为纯文本后重新输入 |
| `ERR-LANG-DETECTED` | 检测到非中文主体 | "检测到非中文内容，本 Skill 仅处理中文转写" | 使用翻译工具或更换文本 |
| `ERR-SPEAKER-AMBIGUOUS` | 说话人标识混乱（超过5个无规则标识） | "说话人标识不规范，已合并为单一说话人" | 手动规范标识后重新处理 |
| `ERR-SEGMENT-FAILED` | 语义断点无法识别 | "段落切分完成，但部分段落可能不完整" | 检查原文本是否有遗漏，补充后重跑 |

## 六、FAQ 反模式

### 6.1 常见坑位对照

| 坑位 | 反模式（错误做法） | 正模式（正确做法） |
|------|-------------------|-------------------|
| 过度清洗 | 删除所有重复词，导致语义损失 | 保留表强调的重复（如"非常非常"） |
| 段落过度细分 | 每句话单独成段，失去逻辑联系 | 按话题完整性切分，80-150字/段 |
| 说话人猜测 | 根据内容猜测说话人身份 | 统一用 `[说话人A]` 等中性标记 |
| 时间戳遗漏 | 播客模式下忘记保留时间信息 | 播客/字幕模式必须保留时间戳 |
| 模板混用 | 会议纪要里插入字幕时间轴 | 明确触发模式，使用单一模板 |
| 补充内容 | 加入常识性补充说明 | 严格输出文本已有信息 |

### 6.2 反模式示例

**反模式：**

```
输入："我觉得这个方案不错，但是成本有点高。"
输出："[说话人A]（产品经理）表示方案可行，但成本过高需要优化。"
```

**正模式：**

```
输入："我觉得这个方案不错，但是成本有点高。"
输出："[说话人A]：我觉得这个方案不错，但是成本有点高。"
```
