## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 | 缺失时的处理 |
|------|------|-------------|
| 输入文本 | 必须为纯文本格式（TXT、MD、DOCX 内容均可） | 如有 PDF 或图片，请先转为文本 |
| 原始转写稿 | 允许包含时间戳、说话人标签、语气词、重复、错误断句 | 无需预先清理，本 Skill 直接处理 |
| 语言 | 中文为主，可处理中英混合 | 纯英文文本也可处理，但术语规范规则需单独说明 |
| 上下文信息 | 如知晓场景（访谈/会议/播客），请提前告知 | 未告知时，默认按通用对话格式处理 |

### 3.2 执行步骤

**Step 1：输入接收与场景确认**

接收用户提供的原始转写文本。如用户未说明场景，先询问一句：

> 请问这段转写的来源场景是？（播客 / 访谈 / 会议 / 其他）

**Step 2：文本粗清洗**

按顺序执行以下清理操作：

1. 删除全部语气词：嗯、啊、呃、哦、哎、那个、这个（当用作填充词时）
2. 删除重复词：如"我们我们" → "我们"；"就是就是" → "就是"
3. 删除自我修正：识别并删除"不对不对，我说的是…"中的"不对不对"及类似修正前缀
4. 删除口头禅：如"你懂我意思吧"、"对吧"（当每句都出现时）

**Step 3：句子边界修复**

- 将无标点长句按语义切分，每句控制在 15-40 字为宜
- 为疑问句补上问号（根据语气词"吗、呢、吧"及上下文判断）
- 为感叹句补上感叹号（仅当语气强烈且明确时）

**Step 4：段落结构重建**

- 按话题切换分段。判断依据：关键词变化、逻辑转折、时间推进
- 每段围绕一个核心意思，段内句子按逻辑顺序排列
- 如内容层次分明，可在段落前添加小标题（用 `###` 或 `**粗体**` 格式）

**Step 5：说话人标识与对话格式**

- 单人口述：无需说话人标签，直接输出连续文本
- 双人对话：使用 `**甲**：` 和 `**乙**：` 格式，或用 `[A]` / `[B]`
- 多人对话：使用 `[主持人]`、`[嘉宾1]`、`[嘉宾2]` 等角色标签
- 若原文无说话人信息但能通过语义推断，用 `[说话人1]` 等占位

**Step 6：术语与专名规范**

- 统一同一实体的不同写法（保留第一次出现的完整形式，后续用简称）
- 修正明显的同音错别字（如"泰裤辣" → "太酷了"，但需结合上下文判断是否为有意为之）
- 专业术语保持原文拼写，不强行翻译

**Step 7：输出规范检查**

对照以下清单逐项检查：

- [ ] 无语气词残留
- [ ] 每句话语义完整
- [ ] 段落主题单一
- [ ] 说话人标识清晰
- [ ] 术语拼写统一
- [ ] 原文核心信息全部保留

### 3.3 输出规范

## 六、FAQ 反模式

### 6.1 常见坑与反模式对照

| 常见坑 | 反模式（错误做法） | 正确做法 |
|--------|-------------------|---------|
| 过度润色 | 把口语化的表达改写成书面语，如"我说一下"→"本人兹阐述如下" | 保持口语的自然感，仅删除杂质，不改变表达风格 |
| 臆测补全 | 原文缺失时自己补写内容，如"我们去了[听不清]市"→"我们去了北京市" | 保留 `[听不清]` 标记，如实呈现 |
| 删除"重复"过头 | 把说话人有意强调的内容当重复删掉，如"非常重要！非常重要！" | 识别强调性重复（语气加重、间隔出现），予以保留 |
| 合并段落过度 | 把不同话题强行合并为一个段落 | 每个话题单独成段，宁可多分段也不要混话题 |
| 忽略上下文 | 单独处理某句话时误解原意 | 先通读全文再动手，保持全局视角 |
| 标准化过头 | 把个性化表达统一成固定句式 | 保留说话人的独特表达习惯，只做必要清理 |

### 6.2 用户常见疑问

**Q1：整理后文本变短了，是不是删了什么重要内容？**
不会删除任何实质内容。仅删除填充词、语气词和重复表达，所有信息点均保留。如果发现信息缺失，请检查原始输入是否完整。

**Q2：可以指定输出格式吗？比如只要纯文本不要 Markdown？**
可以。请在提交时说明"输出为纯文本格式"，本 Skill 会调整输出样式。

**Q3：整理后的文本可以直接用于出版吗？**
本 Skill 输出的是"可读性优化"的文本，但不包含出版所需的深度编辑（如风格统一、事实核查、版权确认）。如需出版，建议进一步人工校对。
