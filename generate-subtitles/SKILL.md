## 三、标准处理流程

### 3.1 前置条件

| 条件 | 要求 | 检查方法 |
|------|------|----------|
| 输入格式 | `.txt`、`.srt`、`.vtt`、`.ass` 或公开 URL | 查看文件扩展名 |
| 文件完整性 | 文件未损坏，可正常读取 | 尝试打开文件 |
| 工作目录 | 所有待处理文件在同一目录 | 确认路径 |
| 命名规范 | 同批次文件前缀一致 | 如 `ep01_raw.txt`、`ep01_audio.mp3` |
| 输出格式 | 明确指定（默认 SRT） | 用户说明或默认 |

### 3.2 执行步骤

#### 步骤 1：素材接收与校验

1. 接收用户提供的文件路径或 URL
2. 检查文件格式是否在支持列表中
3. 验证文件可读性（尝试读取文件头）
4. 确认文件大小不超过限制（单文件 ≤ 2 小时内容）

**校验参数表：**

| 参数 | 允许值 | 拒绝条件 |
|------|--------|----------|
| 文件扩展名 | `.txt`、`.srt`、`.vtt`、`.ass`、`.mp4`、`.mp3`、`.wav`、`.m4a`、`.flac` | 其他扩展名 |
| 文件大小 | ≤ 2GB | 超过 2GB |
| 时长 | ≤ 2 小时 | 超过 2 小时 |
| URL | 公开可访问 | 需要登录或付费 |

#### 步骤 2：内容解析与分段

若输入为音视频文件：

1. 调用语音转写引擎提取文本
2. 按语义断句，每句作为一个字幕块
3. 记录每句的起止时间戳（如转写引擎支持）

若输入为文本稿：

1. 按段落或句子拆分文本
2. 根据字数估算每段时长（默认语速：中文 4 字/秒，英文 3 词/秒）
3. 生成时间轴占位符

**分段规则：**

| 规则 | 说明 | 示例 |
|------|------|------|
| 单句不超过 42 个汉字 | 超出则拆分为两句 | 长句自动断句 |
| 单块时长 1-7 秒 | 过短合并，过长拆分 | 0.8 秒 → 合并 |
| 对话交替时独立成块 | 不同说话人分开 | A/B 对话分块 |
| 标点符号作为断点 | 句号、问号、感叹号 | "你好。" → 断点 |

#### 步骤 3：关键信息提取与标注

| 信息类型 | 提取方式 | 标注格式 |
|----------|----------|----------|
| 说话人 | 音色分析或文本上下文 | `[说话人A]` |
| 专有名词 | 术语表匹配 | `{专有名词}` |
| 置信度 | 转写引擎返回 | `[置信度:0.95]` |
| 需要人工复核 | 置信度 < 0.80 | `[需复核]` |

#### 步骤 4：格式组装

根据输出格式要求组装字幕文件：

**SRT 格式模板：**
```
1
00:00:01,000 --> 00:00:04,000
你好，欢迎观看本视频。

2
00:00:04,500 --> 00:00:08,000
今天我们来讨论字幕生成的技术细节。
```

**VTT 格式模板：**
```
WEBVTT

00:00:01.000 --> 00:00:04.000
你好，欢迎观看本视频。

00:00:04.500 --> 00:00:08.000
今天我们来讨论字幕生成的技术细节。
```

**ASS 格式模板（带样式）：**
```
[Script Info]
ScriptType: v4.00+
PlayResX: 1920
PlayResY: 1080

[V4+ Styles]
Format: Name, Fontname, Fontsize, PrimaryColour, ...
Style: Default, Arial, 48, &H00FFFFFF, ...

[Events]
Format: Layer, Start, End, Style, Text
Dialogue: 0,0:00:01.00,0:00:04.00,Default,,0,0,0,,你好，欢迎观看本视频。
```

**纯文本格式：**
```
你好，欢迎观看本视频。
今天我们来讨论字幕生成的技术细节。
```

#### 步骤 5：输出与自查

输出前执行以下自查：

| 检查项 | 标准 | 失败处理 |
|--------|------|----------|
| 时间轴连续性 | 无重叠、无大于 2 秒的间隙 | 自动修正 |
| 文本完整性 | 无截断、无乱码 | 重新转写 |
| 格式合规 | 符合所选格式规范 | 重新组装 |
| 编码正确 | UTF-8 无 BOM | 转换编码 |

#### 步骤 6：二次确认

1. 将生成的字幕文件路径返回给用户
2. 提示用户使用播放器（如 VLC、PotPlayer）加载字幕预览
3. 询问是否需要调整时间轴参数或重新生成
4. 若用户反馈问题，定位到具体字幕块并修正

### 6.1 常见坑与正确做法

| 常见错误（反模式） | 问题说明 | 正确做法 |
|-------------------|----------|----------|
| 直接处理损坏文件 | 浪费时间且结果不可靠 | 先校验文件完整性 |

| 处理超长文件 | 内存溢出或超时 | 分段处理 |
| 忽略音频质量 | 转写准确率大幅下降 | 先做降噪和音量标准化 |

### 6.2 反模式对照表

| 反模式 | 后果 | 替代方案 |
|--------|------|----------|
| "直接给我结果，不用检查" | 时间轴错乱、文本错误 | 先自查再交付 |
| "所有文件都按默认处理" | 不同格式需求被忽略 | 逐个确认需求 |
| "翻译完直接交付" | 专有名词错误 | 标注置信度，人工复核 |
| "一次处理 10 小时的内容" | 系统崩溃 | 拆分为 2 小时以内的片段 |
