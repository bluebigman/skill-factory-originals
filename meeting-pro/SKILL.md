# meeting-pro 技能手册

## 一、能力边界（速查卡）

本工具聚焦于会议全流程的自动化处理，从音频输入到结构化输出，覆盖以下环节：

| 能力维度 | 支持范围 | 不支持范围 |
|---------|---------|-----------|
| 音频输入 | 常见格式（m4a, mp3, wav, aac, flac），单文件 ≤ 2GB，时长 ≤ 8 小时 | 视频文件直接解析（需先提取音轨）、实时流式转写 |
| 转写引擎 | 中文普通话、中英混合、英文；支持自定义术语表注入 | 方言识别（粤语/四川话等需额外模型）、多说话人分离（仅标注分段） |
| 纪要生成 | 自动生成摘要、议题列表、决议记录、待办事项 | 情感分析、发言风格评价、自动翻译 |
| 行动项提取 | 责任人 + 截止时间 + 任务描述三要素解析 | 跨会议任务关联、自动排期到日历 |
| 校验能力 | 行动项完整性检查、格式合规性验证 | 业务逻辑正确性判断（如"这个任务是否真的需要做"） |

**适用对象**：需要频繁记录会议内容的产品经理、项目负责人、技术主管、行政人员，以及需要将会议结论沉淀为可执行任务清单的团队协作场景。

**不适用场景**：涉及高度机密内容的会议（建议本地离线部署）、需要法律效力的会议记录（本工具输出仅为辅助参考）、非语音类信息传递（如白板内容无法识别）。

## 三、标准处理流程

### 前置条件

1. 已安装 Python 3.9+ 环境
2. 执行 `pip install meeting-pro` 完成安装
3. 音频文件可访问，路径无特殊字符（建议全英文路径）

### 执行步骤

**步骤一：环境自检**

```bash
meeting-pro --selftest
```

预期输出：`[OK] 所有模块加载正常`，若出现 `[FAIL]` 请参照第五节错误码处理。

**步骤二：单文件处理**

```bash
meeting-pro process 会议录音.m4a
```

参数说明：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--lang` | string | zh | 语言代码（zh/en/zh-en） |
| `--term-file` | path | 无 | 自定义术语表文件路径 |
| `--extract-actions` | flag | 关闭 | 是否提取行动项 |
| `--output-dir` | path | ./results | 输出目录 |

**步骤三：查看输出**

处理完成后，在 `./results/` 目录下生成：

- `纪要.md`：结构化会议纪要，包含摘要、议题、决议、待办四段
- `行动项.json`：行动项结构化数据（若启用提取）
- `转写全文.txt`：完整转写文本（保留时间戳）

**步骤四：行动项校验**

```bash
meeting-pro validate 行动项.json
```

校验规则：
- 每个行动项必须包含 `owner`（责任人）、`deadline`（截止时间，格式 YYYY-MM-DD）、`description`（任务描述，≥ 5 字符）
- 责任人字段不得为空字符串或 "待定"
- 截止时间不得早于会议日期

### 输出规范

`纪要.md` 的标准结构：

```markdown
# 会议纪要 - {会议主题}

## 摘要
（3-5 句话概括会议核心内容）

## 议题讨论
### 议题1：{议题名称}
- 讨论要点
- 结论

## 决议
- {决议内容}

## 待办事项
- [ ] {任务描述}（责任人：{姓名}，截止：{日期}）
```

`行动项.json` 的标准结构：

```json
[
  {
    "id": "ACT-001",
    "owner": "张三",
    "deadline": "2026-09-01",
    "description": "完成新版本原型设计",
    "source_timestamp": "00:12:34",
    "confidence": 0.92
  }
]
```

## 四、置信度门控

当转写或提取过程中遇到以下情况，本工具不会强行编造内容，而是输出占位符标记：

| 场景 | 占位符 | 说明 |
|------|--------|------|
| 音频片段模糊无法识别 | `[需核实:音频片段@00:12:34]` | 保留时间戳便于人工回听 |
| 行动项责任人未明确提及 | `[需核实:责任人]` | 不猜测具体人名 |
| 截止时间未提及 | `[需核实:截止时间]` | 不假设默认时间 |
| 术语表外专业词汇 | `[需核实:术语@上下文]` | 保留上下文便于人工修正 |

**处理原则**：

- 置信度 ≥ 0.85：直接输出
- 置信度 0.60 - 0.85：输出内容 + 置信度标注
- 置信度 < 0.60：输出占位符，不进入最终纪要

**人工修正流程**：使用 `meeting-pro fix 纪要.md` 进入交互式修正模式，逐条处理占位符。

## 六、FAQ 反模式对照

| 常见坑（反模式） | 正确做法 |
|----------------|---------|
| 直接处理 2 小时以上的长录音，导致内存溢出 | 使用 `--chunk-minutes 30` 分片处理，或先剪辑关键片段 |
| 不配置术语表就处理专业领域会议 | 提前准备术语表，准确率可提升 30%+ |
| 忽略置信度标注，直接采用所有输出 | 人工复核置信度 < 0.85 的内容 |
| 行动项校验失败后手动修改 JSON 但不重新校验 | 修改后必须重新运行 `meeting-pro validate` |
| 批量处理时中断后从头开始 | 利用断点续跑功能，无需重新处理已完成文件 |

**进阶技巧**：

- 自定义术语表格式：每行 `原词,替换词`，如 `RAG,检索增强生成`
- 批量处理命令：`meeting-pro batch ./recordings/ --parallel 4`
- CI/CD 集成：在流水线中调用 `meeting-pro process` 并将 `行动项.json` 归档至指定仓库
