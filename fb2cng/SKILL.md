### 执行步骤

**第一步：输入确认**

1. 确认输入来源类型（数据 / 文件 / URL）
2. 确认输出格式要求（默认 JSON，可指定 CSV / MD / 自定义模板）
3. 确认是否需要置信度标注（默认开启）

**第二步：解析处理**

1. 读取输入内容，识别数据边界与字段结构
2. 按字段类型分类：文本 / 数字 / 日期 / 布尔 / 嵌套对象
3. 对每个字段执行清洗规则：
   - 去除首尾空白字符
   - 统一日期格式为 ISO 8601（YYYY-MM-DD）
   - 数字字段去除千分位逗号
   - 空值保留为 `null`，不填充默认值
4. 对不确定字段（格式异常、值域超界、缺失必填项）标记置信度

**第三步：输出生成**

1. 按约定格式组装结果
2. 字段顺序与输入顺序保持一致（除非用户指定排序）
3. 输出文件命名规则：`原文件名_converted.扩展名`

**第四步：自查校验**

| 检查项 | 标准 |
|--------|------|

| 格式正确性 | 符合所选格式的语法规范（JSON 可解析、CSV 列数一致） |
| 置信度标注 | 所有不确定字段均带 `confidence` 标记 |
| 数据一致性 | 抽查 5% 输出条目与源数据比对，关键字段一致 |

**第五步：二次确认**

- 当出现以下情况时，暂停输出并向用户确认：
  - 输入字段超过 50 个

## 四、置信度门控

### 置信度等级定义

| 等级 | 数值范围 | 含义 |
|------|----------|------|
| 高 | 0.90 - 1.00 | 字段值明确，无歧义 |
| 中 | 0.60 - 0.89 | 字段值可推断，但存在一定不确定性 |
| 低 | 0.00 - 0.59 | 字段值无法确定，需人工介入 |

### 触发条件

以下情况必须标注 `[需核实:字段名]` 占位符：

1. 字段值为空但输入中该字段存在
2. 字段值格式异常（如日期写成 "2024/13/45"）
3. 字段值超出合理范围（如年龄字段出现 200）
4. 输入来源为 URL 且页面结构解析失败

### 处理规则

- 置信度低于 0.60 的字段，输出值替换为 `[需核实:字段名]`
- 置信度标注不影响整体输出结构，仅作为辅助信息
- 用户可指定 `--strict` 参数，此时置信度低于 0.80 的字段直接置空

## 六、FAQ 反模式

### 常见坑 1：忽略置信度标注

**错误做法**：直接使用所有输出值，不检查 `_confidence` 字段。

**反模式对照**：

| 反模式 | 正确做法 |
|--------|----------|
| 把 `[需核实:字段名]` 当字符串写入数据库 | 人工核实后替换为真实值 |
| 置信度 0.50 的字段直接用于计算 | 设置阈值，低于 0.80 的字段不参与计算 |

### 常见坑 2：批量处理前不试运行

**错误做法**：直接对 1000 个文件执行批量转换，结果发现格式全错。

**反模式对照**：

| 反模式 | 正确做法 |
|--------|----------|
| 跳过单样本测试 | 先用 1 个文件试运行，核对输出字段与格式 |
| 不保留原始文件备份 | 批量执行前复制原始文件到 backup 目录 |

### 常见坑 3：自定义格式时字段映射错误

**错误做法**：自定义模板中字段名与输入字段名不一致，导致输出大量空值。

**反模式对照**：

| 反模式 | 正确做法 |
|--------|----------|
| 凭记忆写字段名 | 先查看输入文件的字段列表，再定义模板 |
| 模板字段大小写不敏感 | 字段名严格区分大小写，保持一致 |

### 常见坑 4：URL 输入不检查页面动态加载

**错误做法**：URL 页面内容由 JavaScript 动态渲染，直接抓取得到空数据。

**反模式对照**：

| 反模式 | 正确做法 |
|--------|----------|
| 直接抓取静态 HTML | 确认页面是否需等待渲染，必要时使用渲染模式 |
| 不检查返回状态码 | 先验证 HTTP 200 后再解析内容 |

### 常见坑 5：忽略输入编码问题

**错误做法**：输入文件为 GBK 编码，直接按 UTF-8 解析导致乱码。

**反模式对照**：

| 反模式 | 正确做法 |
|--------|----------|
| 默认所有文件为 UTF-8 | 先检测文件编码，或让用户指定编码格式 |
| 乱码后手动修复 | 在解析前统一转换编码为 UTF-8 |
