# ux-wise-agent 技能文档

## 一、能力边界速查卡

本技能定位为「体验设计领域的数据解析与结构化工具」，面向需要将非结构化设计资料（文档、截图、链接）转化为规范数据格式的使用者。

| 维度 | 说明 |
|------|------|
| **核心用途** | 将体验设计相关的文本、文件路径或URL解析为结构化JSON/Markdown结果 |
| **输入类型** | 用户直接粘贴的文本、本地文件路径（.txt/.md/.json）、可访问的URL |
| **输出格式** | 默认Markdown表格 + JSON双格式，支持自定义字段映射 |
| **处理上限** | 单次批量不超过50个条目；单条文本不超过5000字符 |
| **处理耗时** | 单条平均0.5-2秒，50条批量约30-90秒 |

### 能做（5项核心能力）

1. **结构解析**：从设计描述文本中提取关键要素（用户角色、场景、痛点、方案、验证指标）
2. **文件转换**：将本地设计文档（.md/.txt）按预设模板转换为结构化条目
3. **URL信息抽取**：从公开设计文章/案例页面提取标题、核心观点、设计策略
4. **批量流水线**：对同一目录下多个文件执行统一解析，输出合并结果集
5. **置信度标注**：对每条解析结果标注可信等级（高/中/低），低置信度字段明确提示

### 不能做（明确边界）

- 不执行设计评审或给出改进建议（仅解析，不评价）
- 不处理图片/PDF中的扫描内容（仅支持纯文本与可复制网页）
- 不访问需要登录验证的私有系统
- 不保证解析字段100%准确（依赖输入质量）
- 不存储或转发用户数据至任何第三方

### 适用对象

- 体验设计师：整理竞品分析、用户研究报告
- 产品经理：将用户反馈文本转为结构化需求条目
- 设计研究者：批量整理访谈记录、问卷开放题
- 学生：整理课程案例、论文参考文献中的设计信息

## 三、标准处理流程

### 前置条件

- 输入内容为可读文本（直接粘贴、文件路径或公开URL）
- 文件编码为UTF-8（避免乱码）
- 批量处理时，文件命名遵循统一规则（如：01_xxx.md, 02_xxx.md）

### 执行步骤

**Step 1：输入接收与类型判定**

接收用户输入，判定类型：

| 输入类型 | 判定规则 | 处理路径 |
|----------|----------|----------|
| 直接文本 | 长度>50字符且非URL | 进入Step 2 |
| 文件路径 | 以/或.\开头，或含.md/.txt/.json | 读取文件内容 |
| URL | 以http://或https://开头 | 抓取页面正文 |

**Step 2：关键信息识别**

对文本执行以下提取操作：

- 用户角色标识（如"新用户""老用户""管理员"）
- 场景描述句（含"在...时""当...后"等时间状语）
- 痛点/问题句（含"难以""无法""困扰"等负面词）
- 方案/建议句（含"应该""可以""建议"等祈使词）
- 量化指标（数字+单位，如"3天""50%"）

**Step 3：结构化映射**

按默认模板生成结果：

```json
{
  "id": "条目唯一编号",
  "source": "输入来源标识",
  "user_role": "提取的用户角色",
  "scenario": "场景描述",
  "pain_point": "痛点内容",
  "proposed_solution": "方案建议",
  "metrics": "量化指标",
  "confidence": "高/中/低"
}
```

**Step 4：置信度评估**

| 置信度等级 | 判定标准 | 输出处理 |
|------------|----------|----------|
| 高 | 字段内容完整且直接匹配提取规则 | 正常输出 |
| 中 | 字段内容存在但表述模糊 | 输出原文并标注"需人工复核" |
| 低 | 字段缺失或无法识别 | 输出 `[需核实:字段名]` 占位符 |

**Step 5：结果输出与自查**

- 输出Markdown表格（人类可读）+ JSON（机器可读）双格式
- 自查清单：字段完整性（无遗漏）、格式正确性（JSON可解析）、置信度标注齐全
- 若存在低置信度字段，附注说明原因

### 输出规范

## 四、置信度门控机制

当输入信息不足以支撑字段提取时，遵循以下规则：

1. **不编造**：绝不推测缺失字段的内容，统一输出 `[需核实:字段名]`
2. **明确提示**：在结果末尾附「低置信度说明」段落，列出所有需核实的字段及原因
3. **二次确认**：若低置信度字段超过总字段数的40%，主动询问用户是否补充信息或调整输入

**示例**：

> 输入："用户觉得加载慢"
>
> 输出：
> - user_role: [需核实:user_role]（未提及具体用户类型）
> - scenario: [需核实:scenario]（未说明使用场景）
> - pain_point: 加载慢
> - confidence: 低（仅1/5字段可确认）
