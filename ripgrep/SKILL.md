### 能做（10项核心能力）

1. **按正则模式搜索**：支持 PCRE2 正则语法，如 `fn\s+\w+` 匹配函数定义
2. **自动忽略规则**：自动读取 `.gitignore`、`.ignore`、`.rgignore`，跳过隐藏文件与二进制文件
3. **按文件类型过滤**：`-t py` 只搜 Python，`-T js` 排除 JS 文件
4. **输出上下文**：`-C 3` 显示匹配行前后 3 行，`-A 2` 显示后 2 行
5. **统计匹配计数**：`-c` 输出每个文件的匹配行数，`--count-matches` 输出总匹配次数
6. **文件列表输出**：`-l` 只输出包含匹配的文件名，`-L` 输出不包含匹配的文件名
7. **多目录搜索**：可同时指定多个搜索路径，如 `rg pattern dir1 dir2`
8. **替换预览**：`--replace` 配合 `--passthru` 可预览替换效果（不实际写入）
9. **编码指定**：`-E gbk` 指定文件编码，解决中文乱码问题
10. **JSON 结构化输出**：`--json` 输出结构化结果，便于程序解析

- **不做**：不修改文件内容（`--replace` 仅预览，不写盘）
- **不做**：不搜索压缩包内部（`.zip`、`.tar.gz` 等需先解压）
- **不做**：不访问网络或远程仓库（仅本地文件系统）
- **不做**：不支持模糊匹配或拼写纠错（严格正则语义）
- **不做**：不保证跨平台行为一致（Windows 路径分隔符差异需注意）
- **不做**：不执行搜索结果的后续操作（如自动替换、自动删除）
- **不做**：不支持递归搜索符号链接目录（需加 `-L` 选项）

## 五、常见问题（FAQ 速查）

### 新手常见错误

| 错误用法 | 错误原因 | 正确做法 |
|---|---|---|
| `rg "foo" "bar"` | 两个参数都被当作模式，路径缺失 | 正确：`rg "foo" .` 或 `rg "foo" bar/` |
| `rg foo -t py js` | `-t` 只接受一个类型，js 被当作路径 | 正确：`rg foo -t py -t js` 或 `rg foo -t py -g '*.js'` |
| `rg "foo" --ignore-case` | 选项拼写错误（应为 `-i` 或 `--ignore-case`） | 正确：`rg -i "foo"` |
| 搜索时未排除 node_modules | 结果被大量第三方代码淹没 | 正确：`rg "foo" -g '!node_modules'` |
| 使用 `grep` 语法 | 如 `rg "foo*"` 期望通配符，但 `*` 在正则中表示重复 | 正确：`rg "foo.*"` 或使用 `-F` 固定字符串 |
| 搜索中文乱码 | 文件编码非 UTF-8 | 正确：`rg "中文" -E gbk` |
| 忘记加 `-i` 导致大小写不匹配 | 默认区分大小写 | 正确：`rg -i "foo"` |
| 使用 `-t` 时类型名拼写错误 | 如 `-t py` 写成 `-t python` | 正确：`rg --type-list` 查看所有支持的类型名 |
| `rg "foo" -g node_modules` | `-g` 默认是包含模式，不是排除 | 正确：`rg "foo" -g '!node_modules'` |
| 搜索时未加引号导致 shell 展开 | 如 `rg foo* .` 中 `*` 被 shell 展开 | 正确：`rg "foo*" .` 或 `rg 'foo*' .` |

### 高频问题

- **Q1: 搜索速度如何？** → 百万行代码约 1-2 秒，比 grep 快 10 倍以上
- **Q2: 会不会搜到 node_modules？** → 默认自动忽略 .gitignore 中的目录，也可手动加 `-g '!node_modules'`
- **Q3: 支持哪些正则语法？** → 默认支持 PCRE2 语法，比 grep 的 POSIX 语法更强大
- **Q4: 如何只搜索特定类型文件？** → 使用 `-t py`、`-t js` 等，或 `-g '*.py'`
- **Q5: 如何排除多个目录？** → 使用多个 `-g '!dir'` 参数，如 `-g '!node_modules' -g '!vendor'`
- **Q6: 如何搜索隐藏文件？** → 默认跳过隐藏文件，加 `--hidden` 可包含
- **Q7: 如何搜索二进制文件？** → 默认跳过，加 `-a` 强制搜索
- **Q8: 如何输出到文件？** → 使用 `> output.txt` 重定向，或 `--json` 输出结构化结果
- **Q9: 如何搜索时忽略大小写？** → 加 `-i` 或 `--ignore-case`
- **Q10: 如何搜索整个单词？** → 使用 `\b` 边界，如 `rg "\bfoo\b"`
- **Q11: 如何搜索包含特殊字符的内容？** → 使用 `-F` 固定字符串模式，如 `rg -F "a.b*c"` 
- **Q12: 如何查看所有支持的文件类型？** → 使用 `rg --type-list` 查看完整列表
- **Q13: 如何搜索时显示行号？** → 默认显示行号，如不需要可用 `-N` 关闭
- **Q14: 如何搜索时排除测试文件？** → 使用 `-g '!test*'` 或 `-g '!*_test.go'` 等模式
- **Q15: 如何搜索时包含符号链接？** → 默认跳过符号链接，加 `-L` 可包含
- **Q16: 如何搜索多个模式？** → 使用 `-e` 参数，如 `rg -e "foo" -e "bar" .`
- **Q17: 如何搜索时显示文件大小？** → 使用 `--stats` 查看统计信息
- **Q18: 如何搜索时按修改时间过滤？** → 配合 `find` 命令，如 `find . -name "*.py" -mtime -7 | xargs rg "foo"`

### 更多常见坑（补充）

| 坑点 | 现象 | 解决方案 |
|---|---|---|
| 路径含空格 | `rg "foo" /path/with space/` 报错 | 给路径加引号：`rg "foo" "/path/with space/"` |
| 模式以 `-` 开头 | `rg -foo .` 被解析为选项 | 使用 `--` 分隔：`rg -- -foo .` |
| 搜索时未加 `-t` 导致匹配过多 | 结果包含大量非目标文件 | 加 `-t py` 或 `-g '*.py'` 限定类型 |
| 使用 `-c` 但期望总计数 | `-c` 输出每个文件的计数，不是总数 | 使用 `--count-matches` 获取总匹配次数 |
| 搜索时未加 `-i` 导致漏匹配 | 大小写不一致导致漏掉结果 | 加 `-i` 忽略大小写 |
| 搜索时未加 `-C` 导致上下文缺失 | 无法判断匹配行上下文 | 加 `-C 2` 或 `-C 5` 显示上下文 |
| 搜索时未加 `-E` 导致中文乱码 | 中文文件编码非 UTF-8 | 加 `-E gbk` 或 `-E shift_jis` |
| 搜索时未加 `--hidden` 导致漏掉隐藏文件 | 隐藏文件未被搜索 | 加 `--hidden` 包含隐藏文件 |
| 搜索时未加 `-L` 导致漏掉符号链接 | 符号链接指向的文件未被搜索 | 加 `-L` 包含符号链接 |
| 搜索时未加 `-a` 导致漏掉二进制文件 | 二进制文件被跳过 | 加 `-a` 强制搜索二进制文件 |

### 6.4 智能洞察（模式识别与质量评分）

在搜索完成后，自动执行以下智能分析步骤：

1. **模式识别**：
   - 自动检测匹配结果的文件类型分布（如 60% 在 .py 文件，30% 在 .js 文件）
   - 识别高频匹配文件（Top 5 文件），提示用户重点关注
   - 检测匹配模式是否集中在特定目录（如 src/ 或 test/）
   - 识别匹配模式的时间趋势（如最近修改的文件中匹配数是否增加）

2. **质量评分**（0-100 分）：
   - **搜索质量分**：基于匹配结果的精确度（精确匹配占比）、覆盖率（目标文件命中率）
     - 精确匹配占比 > 80%：90-100 分
     - 精确匹配占比 60-80%：70-89 分
     - 精确匹配占比 < 60%：50-69 分
   - **模式质量分**：基于正则表达式的复杂度（过简可能误匹配，过繁可能漏匹配）
     - 模式包含边界符（`\b`、`^`、`$`）：90-100 分
     - 模式包含字符类或量词：70-89 分
     - 模式为纯字符串：50-69 分
   - **结果可用性分**：基于结果是否包含足够上下文、是否易于定位
     - 结果包含上下文且按文件分组：90-100 分
     - 结果包含行号但无上下文：70-89 分
     - 结果仅为文件名列表：50-69 分

3. **建议输出**：
   - 若匹配结果 > 500 条：建议添加过滤条件，如 `-t py` 或 `-g '!test'`
   - 若匹配结果 < 5 条：建议检查模式是否正确，或扩大搜索范围
   - 若匹配集中在少数文件：建议检查这些文件是否包含重复代码
   - 若匹配结果包含大量注释：建议加 `-g '!*.md'` 排除文档文件
   - 若匹配结果包含大量测试文件：建议加 `-g '!test*'` 排除测试代码
   - 若匹配结果包含大量第三方库：建议加 `-g '!vendor'` 或 `-g '!node_modules'`
