## 一、能力边界（一页纸速查卡）

### 1.1 能做什么

| 能力项 | 说明 | 支持格式 |
|--------|------|----------|
| 文档解析 | 提取文本、表格、图片引用、标题层级 | PDF、DOCX、HWP |
| 结构转换 | 将源文档的标题、段落、列表、表格映射为 Markdown 语法 | 全部支持格式 |
| 批量处理 | 对同一目录下的多个文件依次执行转换 | 全部支持格式 |
| 字段校验 | 转换后抽查关键字段（标题、页数、表格行数）与源文件一致性 | 全部支持格式 |
| 试运行模式 | 先用单个文件验证转换效果，再决定是否全量执行 | 全部支持格式 |

### 1.2 不能做什么

| 限制项 | 说明 |
|--------|------|
| 不处理扫描件 | 纯图片型 PDF 无法直接提取文字，需先 OCR |
| 不保留复杂排版 | 页眉页脚、分栏、浮动文本框可能丢失或错位 |
| 不转换加密文件 | 带打开密码的文档需先解除密码 |
| 不处理超大型文件 | 单文件建议不超过 200MB，超过可能超时 |
| 不保证公式完美 | 数学公式、复杂符号可能转为近似文本 |

## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 | 检查方法 |
|------|------|----------|
| 文件完整性 | 文件未损坏、可正常打开 | 用系统自带阅读器试开 |
| 文件命名 | 建议统一命名规范，如 `2024_合同_甲方.md` | 目视检查文件名 |
| 目录结构 | 所有待处理文件放在同一目录下 | `ls` 或资源管理器查看 |
| 磁盘空间 | 至少保留源文件总大小 2 倍的空间 | `df -h` 查看 |
| 权限 | 对输出目录有写入权限 | 尝试创建临时文件 |

### 3.2 执行步骤

#### 第一步：准备输入

1. 创建输入目录 `input/` 和输出目录 `output/`
2. 将所有待处理文件复制到 `input/` 目录
3. 确认文件命名规范一致（如统一使用 `日期_类型_名称` 格式）
4. 记录文件清单，包含文件名、大小、修改日期

#### 第二步：试运行

1. 从 `input/` 中选择一个代表性样本文件
2. 执行转换命令：
   ```bash
   mdm-desktop convert input/sample.pdf -o output/sample.md
   ```
3. 检查输出文件：
   - 标题层级是否正确（`#`、`##`、`###`）
   - 表格是否完整（`|` 分隔符是否对齐）
   - 列表是否保留（`-`、`1.` 等）
   - 图片引用是否保留（`![描述](路径)`）
4. 核对关键字段：
   - 文档标题是否一致
   - 页数是否匹配（Markdown 中可通过段落数估算）
   - 表格行数是否一致

#### 第三步：批量执行

1. 确认试运行结果无误后，对全量文件执行：
   ```bash
   mdm-desktop batch input/ -o output/
   ```
2. 保留原始文件备份：将 `input/` 目录复制为 `backup_input/`
3. 记录转换日志，包含每个文件的转换状态（成功/失败/警告）

#### 第四步：校验结果

1. 随机抽取 20% 的输出文件（至少 3 个）
2. 对每个抽查文件执行以下核对：
   - 标题数量与源文件一致
   - 表格数量与源文件一致
   - 关键段落内容与源文件逐字比对
3. 将校验结果记录到 `verification_report.md`

### 3.3 输出规范

输出 Markdown 文件必须遵循以下结构：

```markdown
---
source_file: 原始文件名
converted_at: 转换时间
converter_version: 1.0.0
---

# 文档标题
```
