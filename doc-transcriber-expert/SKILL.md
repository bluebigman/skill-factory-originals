## 三、标准执行流程

### 3.1 前置条件

1. 确认输入材料已就位：文本已复制 / 文件已放入工作目录 / URL 可访问。
2. 检查文件命名是否符合 `[前缀]_[日期]_[序号]` 规范，不符合的先重命名。
3. 明确输出格式需求：默认 JSON，可选 Markdown 表格或 CSV。
4. 若需自定义字段映射，提前提供字段清单及对应规则。

### 3.2 分步执行步骤

**步骤 1：输入接收与校验**

- 接收用户输入，判断类型（文本/文件/URL）。
- 对文件执行存在性检查，对 URL 执行可达性检查（HTTP 状态码 200）。
- 若输入为空或不可读，返回错误码 `E1001`。

**步骤 2：内容解析**

- 文本类：直接作为解析对象。
- 文件类：按扩展名选择解析器（.txt 直接读，.md 去标记，.csv 按行分割，.json 递归展平）。
- URL 类：抓取 HTML 正文，去除 script/style 标签，保留纯文本。

**步骤 3：关键信息抽取**

- 应用内置字段识别规则（日期、金额、编号、人名、电话、邮箱）。
- 对每个候选字段计算置信度：
  - 规则完全匹配（如 `\d{4}-\d{2}-\d{2}` 日期格式）：置信度 0.9~1.0
  - 模糊匹配（如 "大约 5000 元"）：置信度 0.6~0.8
  - 上下文推断（如 "合同于去年签署"）：置信度 0.4~0.5，转为 `[需核实:签署日期]`
- 保留原始文本片段作为 `raw_snippet`，便于追溯。

**步骤 4：结果组装与输出**

- 按约定结构组装 JSON 对象。
- 若用户指定自定义格式，按模板渲染。
- 输出前自查：
  - 字段完整性：必填字段是否齐全，缺失的已用占位符标注。
  - 格式正确性：JSON 可解析，Markdown 表格列对齐。
  - 置信度标注：所有低于 0.6 的字段已替换为 `[需核实:字段名]`。

**步骤 5：二次确认（仅在必要时）**

- 当出现以下情况时，主动向用户确认：
  - 同一字段存在多个候选值且置信度接近。
  - 用户提供的自定义格式与默认结构冲突。
  - 批量处理中超过 20% 的文件解析失败。

## 四、置信度门控机制

### 4.1 置信度分级规则

| 置信度区间 | 处理方式 | 输出表现 |
|-----------|---------|---------|
| 0.9 ~ 1.0 | 直接输出 | 正常字段值 |
| 0.6 ~ 0.9 | 输出并附置信度 | 字段值 + `confidence` 标注 |
| 0.0 ~ 0.6 | 不输出猜测值 | 替换为 `[需核实:字段名]` |

### 4.2 信息不足时的处理

- **绝不编造**：当无法从输入中确定字段值时，一律使用 `[需核实:字段名]` 占位。
- **补充提示**：在输出末尾附注 `"以下字段需用户确认: [字段列表]"`。
- **可追溯**：每个占位符对应 `raw_snippet` 中的原始上下文，方便用户快速定位。

### 4.3 边界情况

- **空输入**：返回 `{ "error": "E1001", "message": "输入内容为空" }`。
- **无匹配字段**：返回空 `fields` 对象，附注 `"未识别到目标字段"`。
- **多值冲突**：取置信度最高者，其余值放入 `"alternatives"` 数组。

## 常见问题（FAQ）

**Q: 支持中文文件吗？**
A: 支持，内置 utf-8/gbk/gb18030 多编码容错。

**Q: 运行报错怎么办？**
A: 工具内置异常降级，错误会有明确提示；可先用 --dry-run 预览。

**Q: 如何确认功能正常？**
A: 运行 --selftest，全部通过即核心功能正常。
