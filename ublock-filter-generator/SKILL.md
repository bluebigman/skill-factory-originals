# uBlock Filter Generator — 广告拦截规则生成器

## 一、能力边界速查卡

本 Skill 的核心能力是将自然语言描述转换为可直接粘贴到 uBlock Origin 的自定义静态过滤规则。以下表格明确列出能力范围与限制。

| 能力维度 | 支持范围 | 不支持范围 |
|---------|---------|-----------|
| **规则类型** | 元素隐藏规则（`##`）、网络请求拦截规则（`||`、`\|`）、正则表达式规则（`/regex/`）、属性选择器规则 | 动态规则（`$important`、`$document` 等高级修饰符）、脚本注入规则（`+js()`） |
| **输入形式** | 中文自然语言描述、英文描述、混合描述、URL 片段、CSS 选择器片段 | 完整的 uBlock 规则语法（需逐条解析时建议直接使用官方文档） |
| **输出格式** | 单条规则、多条规则（以换行分隔）、带注释的规则组 | 完整的 uBlock 配置备份、规则列表文件 |
| **适用对象** | 普通网页中的广告元素（横幅、弹窗、视频贴片）、跟踪脚本、统计脚本 | 网页内嵌 iframe 的跨域内容（需额外处理）、动态加载的 Shadow DOM 内部元素 |
| **验证能力** | 规则语法合法性检查（括号匹配、选择器格式） | 规则实际效果验证（需用户在浏览器中实测） |

**适用对象**：使用 uBlock Origin 的普通用户、前端开发者、内容维护者、QA 测试人员。

## 三、标准操作流程

### 前置条件

- 用户已安装 uBlock Origin 浏览器扩展（Chrome/Firefox/Edge 均支持）
- 用户能提供目标网页的 URL 或元素描述
- 用户具备基本的浏览器开发者工具使用能力（用于复制选择器）

### 执行步骤

**步骤 1：收集输入信息**

向用户确认以下信息（按优先级排列）：

| 信息项 | 必填/选填 | 示例 |
|-------|----------|------|
| 目标网页 URL | 必填 | `https://example.com/news` |
| 广告元素描述 | 必填 | "页面右侧的推荐广告" |
| 元素特征（class/id） | 选填 | `class="ad-sidebar"` |
| 请求地址（拦截场景） | 选填 | `https://ads.example.com/track.js` |

**步骤 2：解析输入并生成规则**

根据输入信息，按以下逻辑生成规则：

1. **元素隐藏场景**：
   - 若用户提供 class/id：直接生成 `域名##.class名` 或 `域名###id名`
   - 若用户提供描述：生成属性选择器规则，如 `域名##[class*="ad"]`
   - 若用户提供完整选择器：直接使用并添加域名前缀

2. **请求拦截场景**：
   - 若用户提供完整 URL：提取域名生成 `||域名^` 规则
   - 若用户提供域名片段：生成 `||片段^` 规则

3. **正则表达式场景**：
   - 将用户描述转换为正则模式，生成 `/模式/` 规则

**步骤 3：输出规则并附带说明**

输出格式如下：

```
# 规则说明：屏蔽 example.com 页面顶部的横幅广告
example.com##.top-banner-ad

# 使用方式：打开 uBlock Origin 设置 → 自定义静态规则 → 粘贴以上内容 → 应用更改
```

**步骤 4：验证与调整**

- 提示用户粘贴规则后刷新页面验证效果
- 若规则无效，建议用户使用浏览器开发者工具检查元素实际结构

### 输出规范

- 每条规则独立一行，多条规则间用空行分隔
- 规则前必须附带 `#` 注释说明规则用途
- 输出末尾附使用说明（不超过 3 行）

## 九、使用注意事项

1. **规则作用域**：生成的规则默认限定在指定域名内，避免影响其他网站
2. **规则优先级**：uBlock Origin 中，静态规则优先级高于动态规则
3. **规则冲突**：多条规则同时匹配时，以更具体的规则为准
4. **规则更新**：网站结构调整后，原有规则可能失效，需重新生成
5. **性能影响**：避免生成过于宽泛的规则（如 `*##div`），影响页面加载性能
