# git-wiki Skill 文档

## 一、能力边界速查卡

本 Skill 面向需要快速搭建个人或团队知识库的技术人员、文档维护者。它帮助你将散落的 Markdown 文件、文本数据或网页链接，转化为一个由 Git 进行版本控制的轻量 Wiki 结构。

### 能做（核心能力）

| 编号 | 能力项 | 说明 | 输入示例 |
|------|--------|------|----------|
| 1 | 内容结构化 | 将用户提供的原始文本、文件路径或 URL 内容，解析为标题、段落、列表等结构化元素 | 一段无格式的会议记录文本 |
| 2 | 关键信息提取 | 识别输入中的标题、日期、标签、作者等元数据，并整理为 Wiki 页面属性 | 文件名 `2025-03-15-周会.md` 中的日期信息 |
| 3 | 格式规范化 | 将非标准格式（如纯文本、HTML 片段）转换为统一的 Markdown 语法 | 一段带 `<h1>` 标签的旧网页内容 |
| 4 | 批量处理 | 支持一次处理多个文件或 URL，生成对应的 Wiki 页面骨架 | 一个包含 10 个 .txt 文件的文件夹路径 |
| 5 | 自定义输出 | 允许用户指定输出目录、命名规则和首页索引格式 | 指定输出到 `./wiki_output/`，首页按日期倒序排列 |

### 不能做（明确边界）

- 不能直接部署或托管 Wiki 站点（需要用户自行配置 Git 远程仓库和 Web 服务）。
- 不能自动处理二进制文件（如图片、PDF）的内容解析，仅能记录其文件名和路径。
- 不能理解图片或复杂表格中的语义信息，仅能保留其原始引用或代码块。
- 不能替代人工校对，生成结果需用户确认后使用。

## 三、标准处理流程

### 前置条件

- 用户需提供至少一个输入源：本地文件路径、文件夹路径或可访问的 URL。
- 若输入为 URL，需确保网络可访问且内容为 HTML 或纯文本。
- 建议（非必须）用户已安装 Git 命令行工具，以便执行后续版本控制操作。

### 执行步骤

**步骤 1：输入接收与解析**

- 接收用户提供的路径或链接列表。
- 检查路径是否存在、URL 是否可访问。若不可访问，进入错误处理流程（见第五节）。

**步骤 2：内容提取与清洗**

- 对于本地文件：读取文件内容，识别编码（UTF-8 优先）。
- 对于 URL：抓取 HTML，去除 `<script>`、`<style>` 标签及内联样式，提取正文文本。
- 将内容统一转换为纯文本流，供下一步解析。

**步骤 3：结构化解析**

- 识别 Markdown 标题（`#` 至 `######`），生成页面内锚点。
- 识别列表（有序/无序）、引用块（`>`）、代码块（```）。
- 提取文件头部元数据（如 YAML frontmatter 中的 `title`、`date`、`tags`），若缺失则根据文件名或内容首行推断。

**步骤 4：Wiki 化处理**

- 根据文件名或标题生成 Wiki 页面名称（去除特殊字符，空格替换为 `-`）。
- 扫描所有页面内容，查找 `[[双链]]` 或 `[链接](相对路径)` 格式，转换为 Wiki 内部链接。
- 生成 `_index.md` 首页文件，包含所有页面的标题列表和简介（取每页首段前 50 字）。

**步骤 5：输出生成**

- 在用户指定目录（默认 `./wiki/`）下创建文件夹结构。
- 每个源文件对应生成一个 `.md` 文件，命名规则为 `页面名.md`。
- 输出文件包含：原始内容（清洗后）、自动生成的元数据块（来源、处理时间）。

**步骤 6：自查与报告**

- 检查生成文件数量与输入源数量是否一致。
- 检查首页索引是否包含所有页面链接。
- 向用户输出处理报告，列出成功、失败及跳过的文件清单。

### 输出规范

- **文件类型**：Markdown（`.md`），UTF-8 编码。
- **字段结构**：每个生成文件包含以下部分（按顺序）：
  1. `---` 包裹的 YAML frontmatter（`title`、`source`、`date`）。
  2. 正文内容（原始文本转换后的 Markdown）。
  3. 文件末尾追加 `<!-- generated-by: git-wiki -->` 注释标记。

当处理过程中遇到以下情况，本 Skill 不会强行猜测，而是输出占位符并提示用户。

## 六、FAQ 与反模式对照

### 常见坑 1：把 Wiki 当网盘用

- **反模式**：上传大量 PDF、PPT 等二进制文件，期望生成可搜索的文本页面。
- **正确做法**：仅处理 Markdown、TXT 等纯文本格式。二进制文件请使用外部链接引用。

### 常见坑 2：忽略 Git 初始化

- **反模式**：生成完文件后，不执行 `git init`，导致无法追踪版本。
- **正确做法**：生成完成后，在输出目录执行 `git init && git add . && git commit -m "initial wiki"`。

### 常见坑 3：文件名包含特殊字符

- **反模式**：文件名含空格、`#`、`&` 等字符，导致链接生成失败。
- **正确做法**：处理前自动替换为 `-` 或 `_`，并在报告中说明替换规则。

### 常见坑 4：过度依赖自动链接

- **反模式**：期望所有相同词汇自动互相链接，忽略上下文语义。
- **正确做法**：仅处理显式 `[[双链]]` 语法，普通词汇不做自动链接。

### 常见坑 5：忽略首页维护

- **反模式**：只生成页面，不更新 `_index.md`，导致新页面无法被发现。
- **正确做法**：每次新增页面后，重新运行本 Skill 或手动更新首页索引。

## 异常处理

| 异常情况 | 表现 | 处理方式 |
|---|---|---|
| 输入文件不存在 | 提示路径错误并退出 | 核对路径，使用绝对路径重试 |
| 文件格式不符 | 该条跳过并计入失败明细 | 转换为受支持格式后重跑该条 |
| 权限不足 | 写入失败 | 更换输出目录或提升目录写权限 |
| 单条数据异常 | 跳过该条，继续处理其余 | 处理结束后查看失败明细定向重跑 |

失败处理原则：**单条失败不中断整批**，全部异常汇总到失败明细，支持只重跑失败项。

## 稳定性保障

- **超时控制**：单条处理设置上限，超时自动跳过并记入失败明细，避免整批卡死。
- **重试策略**：可恢复类错误（临时占用、瞬时 IO 失败）自动重试 3 次，间隔递增。
- **降级方案**：高级解析失败时自动回退到基础解析模式，保证有可用输出而非直接报错。
- **幂等性**：重复执行同一批输入结果一致，不会产生重复追加。
