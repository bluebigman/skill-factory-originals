## 三、标准操作流程

### 3.1 前置条件

- 输入内容为文本格式的测试配置（`.autotest` 格式或类似键值对结构）
- 配置内容不包含敏感信息（如密码、密钥等），如有请提前脱敏
- 单次输入配置大小建议不超过 50KB

### 3.2 执行步骤

**第一步：接收输入**

用户粘贴配置内容或指定配置来源。若输入为空，提示"未检测到配置内容，请粘贴 .autotest 文件内容"。

**第二步：解析配置项**

将输入内容拆解为独立的配置项，识别字段名与字段值。解析规则如下：

| 解析规则 | 说明 |
|----------|------|
| 字段分隔 | 以换行符或分号分隔不同配置项 |
| 键值对识别 | 以 `=`、`:` 或空格分隔键与值 |
| 注释忽略 | `#` 或 `//` 开头的行为注释，不参与校验 |
| 嵌套结构 | 支持 `[section]` 或缩进表示的分组结构 |

**第三步：完整性校验**

对每个识别到的配置项执行以下三类检查：

- **必填项检查**：核心配置项（如 `test_env`、`test_cases`、`report_format`）是否存在
- **格式检查**：字段值是否符合预期格式（如 URL 格式、枚举值范围、数字范围）
- **逻辑检查**：字段间是否存在逻辑冲突（如报告格式指定为 JSON 但输出路径为 `.html`）

**第四步：生成报告**

输出结构化摘要报告，包含：

1. **配置项摘要表**：所有识别到的配置项及状态
2. **缺失/存疑项清单**：逐条列出问题项，附补全建议
3. **待确认清单**：需要用户进一步确认的信息

### 3.3 输出规范

报告格式遵循以下模板：

```markdown
## 配置摘要报告

### 配置项摘要表
| 配置项 | 状态 | 说明 |
|--------|------|------|
| test_env | ✅ 正常 | 值为 staging |
| ... | ... | ... |

### 缺失/存疑项清单
1. **test_cases**（❌ 缺失）：未指定测试用例路径。建议补全为 `test_cases = ./cases/` 或指定具体文件。

### 待确认清单
- [ ] 请确认 `timeout` 字段的单位是秒还是毫秒
```
