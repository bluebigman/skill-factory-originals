## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 | 缺失时的处理 |
|------|------|--------------|
| 原文文本 | 必填，纯文本格式 | 提示用户提供，否则无法执行 |
| 重复率数据 | 选填，如"知网30%" | 默认按 0.5 强度执行 |
| 目标重复率 | 选填 | 用于计算迭代轮次和强度增量 |
| 保留术语 | 选填，逗号分隔 | 无则全部内容均可调整 |
| 改写强度 | 选填，0.1~1.0 | 默认 0.5 |

### 3.2 执行步骤

**第 1 步：信息收集**

确认以下信息，缺失项用 `[需核实:字段名]` 标注：

```
原文：必填
重复率：选填（如"知网30%"）
目标重复率：选填（如"15%以下"）
保留术语：选填（如"深度学习、Transformer"）
改写强度：选填（0.1~1.0，默认0.5）
```

**第 2 步：首轮改写**

- 按指定强度执行改写
- 保留术语锁定，不做任何变动
- 输出改写结果 + 本轮强度值 + 建议验证方式

**第 3 步：用户验证**

- 用户将改写结果提交查重系统
- 返回新的重复率数据

**第 4 步：迭代判断**

| 条件 | 动作 |
|------|------|
| 重复率达标 | 流程结束，输出最终版本 |
| 重复率未达标且轮次 < 5 | 强度 +0.1~0.2，对上一轮改写结果再次改写 |
| 重复率未达标且轮次 ≥ 5 | 停止迭代，建议人工深度改写或调整引用策略 |

**第 5 步：输出规范**

每次输出包含：

```
【改写结果】
（改写后的完整文本）

【本轮参数】
强度：0.5
轮次：1/5
保留术语：深度学习、Transformer

【下一步建议】
提交查重验证，若重复率仍高于目标，回复"继续"进行下一轮迭代。
```

### 3.3 强度参数参考表

| 强度值 | 改写力度 | 适用场景 | 风险提示 |
|--------|----------|----------|----------|
| 0.1~0.3 | 轻度：同义词替换为主 | 重复率略高（20%左右） | 降重幅度有限 |
| 0.4~0.6 | 中度：句式重组+同义替换 | 常规降重（30%左右） | 需检查语义连贯性 |
| 0.7~0.9 | 重度：结构调整+大幅改写 | 重复率较高（40%+） | 可能偏离原意，需人工复核 |
| 1.0 | 极限：近乎重写 | 极端情况 | 不建议单独使用，需结合上下文 |

## 六、FAQ 反模式

### 6.1 常见坑

| 坑位 | 错误做法 | 正确姿势 |
|------|----------|----------|
| 过度改写 | 强度拉到 1.0，结果语义完全偏离 | 从 0.5 起步，按需递增，每轮验证 |
| 忽略术语 | 专业术语被替换，导致学术不准确 | 提前声明保留术语，锁定关键概念 |
| 一轮定胜负 | 只改一轮就提交，重复率仍高 | 利用迭代机制，最多 5 轮渐进降重 |
| 不验证结果 | 改完直接提交，不做人工复核 | 逐句检查语义、逻辑、数据准确性 |
| 忽略平台差异 | 用知网策略处理 Turnitin 报告 | 根据查重平台调整改写重点 |

### 6.2 反模式对照表

| 反模式 | 表现 | 替代方案 |
|--------|------|----------|
| 无脑同义词替换 | "深度学习"→"深度进修" | 保留术语，改为句式重组 |
| 机械语序颠倒 | 所有句子都改成倒装 | 混合使用多种改写策略 |
| 忽略上下文 | 单句改写，段落逻辑断裂 | 以段落为单位整体处理 |
| 过度承诺 | "保证降到10%以下" | 说明验证义务在用户，提供迭代机制 |
