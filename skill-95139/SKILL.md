# 网页采集与结构化整理工具（Skill 文档）

## 一、能力边界速查卡

本工具专注于将网页中的非结构化内容转换为结构化数据文件（JSON / CSV）。以下是明确的能力范围与限制说明。

### 1.1 能做什么

| 能力项 | 说明 | 示例 |
|--------|------|------|
| 正文提取 | 自动识别并抽取网页主内容区域，去除导航、广告、页脚等干扰元素 | 新闻文章、产品介绍、博客正文 |
| 结构化输出 | 将提取结果按预设字段映射为 JSON 对象，并同步生成 CSV 表格 | `{title, content, author, publish_date}` |
| 批量处理 | 支持输入多个 URL 或一个包含 URL 列表的 CSV 文件，逐页处理 | 100 个产品页批量抓取 |
| 字段自定义 | 允许用户指定需要提取的字段及对应的 CSS 选择器或属性映射 | 提取 `price` 字段时指定 `[data-price]` 选择器 |
| 链接过滤 | 可配置链接抓取规则，排除广告链接、跟踪参数、站外链接等 | 只保留同域名下的文章链接 |

### 1.2 不能做什么

| 限制项 | 说明 |
|--------|------|
| 不执行 JavaScript 渲染 | 仅处理静态 HTML 内容。若目标页面依赖 JS 动态加载数据，提取结果可能为空或部分缺失 |
| 不绕过访问控制 | 不提供登录模拟、验证码识别、IP 代理池等功能。仅抓取公开可访问的页面 |
| 不处理 PDF/图片中的文字 | 仅支持 HTML 页面中的文本内容提取，不支持 OCR 或 PDF 解析 |
| 不保证数据准确性 | 网页结构变化、反爬策略调整等因素可能导致提取结果偏差，需人工复核关键数据 |

### 1.3 适用对象

- 需要快速收集公开网页信息的研究人员
- 需要将网页数据导入内部系统的开发人员
- 需要定期监控竞品公开信息的运营人员

## 三、标准流程

### 3.1 前置条件

- 目标 URL 必须为公开可访问的 HTTP/HTTPS 地址
- 若使用批量模式，CSV 文件需包含 `url` 列（大小写不敏感）
- 本机需具备网络访问能力，且能正常访问目标站点

### 3.2 执行步骤

**步骤 1：初始化请求**

```bash
网页提取 <目标URL> [可选参数]
```

可选参数说明：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--fields` | 字符串 | `title,content` | 需要提取的字段，逗号分隔 |
| `--min-length` | 整数 | `200` | 正文最小字符数，低于此值的块将被丢弃 |
| `--link-filter` | 字符串 | `same-domain` | 链接过滤规则：`all` / `same-domain` / `none` |
| `--output` | 字符串 | `./output` | 输出目录路径 |
| `--format` | 字符串 | `json,csv` | 输出格式，逗号分隔 |

**步骤 2：执行提取**

工具将按以下顺序处理：

1. 发送 HTTP GET 请求，获取页面 HTML
2. 解析 HTML 文档树，定位主内容区域
3. 根据 `--fields` 参数提取对应字段内容
4. 对提取结果进行清洗（去除多余空白、HTML 标签等）
5. 按置信度规则校验提取结果（见第四节）

**步骤 3：输出文件**

在输出目录下生成以下文件：

```
output/
├── result_<时间戳>.json      # 结构化数据（JSON 格式）
├── result_<时间戳>.csv       # 表格数据（CSV 格式）
└── warnings_<时间戳>.log     # 警告日志（如有占位符或异常）
```

**JSON 输出示例：**

```json
{
  "url": "https://example.com/article/123",
  "extracted_at": "2026-08-19T10:30:00Z",
  "data": {
    "title": "示例文章标题",
    "content": "正文内容……",
    "author": "张三",
    "publish_date": "2026-08-18"
  },
  "warnings": []
}
```

**CSV 输出示例：**

```csv
url,title,content,author,publish_date
https://example.com/article/123,示例文章标题,正文内容……,张三,2026-08-18
```

### 3.3 批量处理流程

1. 准备 CSV 文件，至少包含 `url` 列
2. 执行命令：`内容采集 urls.csv --fields title,price`
3. 工具逐行读取 URL，对每个 URL 执行单页提取流程
4. 单个页面失败不影响其他页面处理，失败信息记录在 warnings 日志中
5. 全部处理完毕后，合并所有成功结果为单个 JSON/CSV 文件

## 四、置信度门控

### 4.1 占位符机制

当提取结果无法满足置信度要求时，工具**不会**输出猜测数据，而是插入占位符：

| 情况 | 占位符格式 | 示例 |
|------|-----------|------|
| 字段内容为空 | `[需核实:字段名]` | `[需核实:author]` |
| 字段内容疑似不完整 | `[需核实:字段名-可能截断]` | `[需核实:content-可能截断]` |
| 字段类型与预期不符 | `[需核实:字段名-类型异常]` | `[需核实:price-类型异常]` |

### 4.2 置信度判定规则

| 判定条件 | 置信度 | 处理方式 |
|---------|--------|---------|
| 提取内容长度 ≥ 最小长度阈值，且无异常字符 | 高 | 正常输出 |
| 提取内容长度 < 最小长度阈值 | 低 | 插入占位符，记录警告 |
| 提取内容包含大量 HTML 标签残留 | 低 | 清洗后重试，仍失败则插入占位符 |
| 字段类型不匹配（如数字字段提取到文本） | 低 | 插入占位符，记录警告 |

### 4.3 警告日志

所有占位符均在 `warnings` 字段和 `.log` 文件中列出，格式如下：

```
[WARNING] 字段 "author" 提取为空，已插入占位符 [需核实:author]
[WARNING] 字段 "content" 长度 45 小于阈值 200，已插入占位符
```

### 6.1 常见坑与正确做法

| 常见坑（反模式） | 问题说明 | 正确做法 |
|-----------------|---------|---------|
| 直接抓取需要登录的页面 | 工具无法处理会话认证，结果为空或返回登录页内容 | 先确认页面是否公开可访问，或使用已导出的静态 HTML |
| 忽略 robots.txt 限制 | 可能违反目标网站的使用条款，且容易被封 IP | 抓取前检查目标站点的 robots.txt，遵守规则 |
| 对提取结果不做人工复核 | 网页结构变化可能导致字段错位或数据错误 | 对关键数据（价格、日期、数字）进行抽样人工核对 |
| 使用过小的 `--min-length` 值 | 容易将导航栏、版权信息等噪声内容当作正文 | 默认 200 字符，根据页面类型适当调整 |
| 批量处理时未设置请求间隔 | 高频请求可能触发目标站点的反爬机制 | 在批量模式中内置 1-2 秒请求间隔，或使用 `--delay` 参数 |
