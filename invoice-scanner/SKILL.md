# 票据识别与结构化提取 Skill 文档

## 一、能力边界速查卡

本 Skill 面向需要从票据类文件（PDF、图片）中提取关键信息的场景，输出为结构化字段集合。

| 维度 | 说明 |
|------|------|
| 输入类型 | PDF 文件、PNG/JPG 图片、可访问的 URL 链接 |
| 输出类型 | JSON 结构化字段 + 置信度标注 |
| 处理上限 | 单次调用最多 20 个文件；单文件不超过 10 页 |
| 耗时预估 | 单文件约 2-5 秒（视清晰度与页数浮动） |

### 能做（核心能力）

1. 从票据图像或 PDF 中提取文本内容，识别关键业务字段（如发票号码、开票日期、金额、购销方信息）。
2. 将非结构化文本转换为统一的 JSON 字段结构，字段命名遵循 camelCase 规范。
3. 对每个提取字段附加置信度评分（0.00-1.00），低于 0.70 的字段自动标记为 `[需核实:字段名]`。
4. 支持批量处理：同一目录下多个文件可依次执行，输出合并为一个 JSON 数组。
5. 支持自定义字段映射：用户可传入字段别名表，将输出字段名映射为业务系统内的名称。

### 不能做（明确边界）

- 不处理手写体票据（仅限印刷体或电子发票）。
- 不进行票据真伪验证，仅做文本提取与结构整理。
- 不处理加密 PDF 或带访问密码的文件。
- 不识别票据中的二维码/条形码内容（仅提取可见文本）。
- 不提供财务入账建议或合规性判断。

### 适用对象

- 需要将纸质或电子票据数字化的财务人员。
- 需要从票据中批量提取信息用于对账或审计的开发者。
- 需要快速浏览票据关键信息但不想逐张打开文件的业务人员。

## 三、标准处理流程

### 前置条件

1. 待处理文件与 Skill 运行环境处于同一可访问目录。
2. 文件命名建议遵循 `类型_日期_序号` 格式（如 `invoice_20250115_001.pdf`），便于结果回溯。
3. 确认文件非加密、非扫描倾斜超过 15 度（倾斜过大需先人工矫正）。
4. 若输入为 URL，需确认链接可直接访问且无需登录鉴权。

### 执行步骤

**步骤 1：输入准备**

- 将单个文件路径或文件列表传入。
- 若为目录路径，自动筛选扩展名为 `.pdf`、`.png`、`.jpg`、`.jpeg` 的文件。
- 参数表：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `filePath` | string | 是 | 无 | 文件路径或目录路径 |
| `customFields` | object | 否 | 无 | 自定义字段映射，如 `{"invoiceNo": "发票号"}` |
| `outputFormat` | string | 否 | `json` | 可选 `json` 或 `table` |
| `confidenceThreshold` | number | 否 | `0.70` | 低于此值的字段标记为需核实 |

**步骤 2：文本提取**

- 对 PDF 执行逐页文本抽取；对图片执行 OCR 识别（内置引擎，无需额外配置）。
- 若文本层存在（电子发票 PDF），直接读取文本层；若无文本层，启用 OCR 流程。
- OCR 前自动做灰度化、对比度增强、倾斜矫正预处理。

**步骤 3：字段识别与结构化**

- 基于正则表达式 + 关键词定位策略，从文本中定位以下标准字段：

| 字段名 | 类型 | 示例 |
|--------|------|------|
| `invoiceNo` | string | `INV-2025-00123` |
| `invoiceDate` | string (YYYY-MM-DD) | `2025-01-15` |
| `totalAmount` | number | `1234.56` |
| `taxAmount` | number | `142.06` |
| `sellerName` | string | `某某科技有限公司` |
| `buyerName` | string | `某某贸易有限公司` |
| `itemList` | array | `[{"name":"服务费","amount":1092.50}]` |

- 若用户传入 `customFields` 映射，则按映射关系重命名输出字段。

**步骤 4：置信度标注**

- 每个字段附带 `confidence` 子字段，取值 0.00-1.00。
- 置信度计算依据：文本匹配完整度、字段位置规律性、跨页一致性。
- 低于阈值的字段值替换为 `[需核实:字段名]`，同时保留原始提取值于 `rawValue` 字段中。

**步骤 5：输出与自查**

- 按 `outputFormat` 参数输出 JSON 或 Markdown 表格。
- 自查清单：
  - [ ] 所有必填字段是否已覆盖
  - [ ] 日期格式是否为 `YYYY-MM-DD`
  - [ ] 金额字段是否为 number 类型且保留两位小数
  - [ ] 置信度标注是否完整
  - [ ] 是否存在 `[需核实:...]` 占位符需要用户确认

## 四、置信度门控机制

当提取的信息不完整或存在歧义时，遵循以下规则：

1. **不编造原则**：绝不猜测缺失字段的值。若某字段无法从文本中定位，输出 `[需核实:字段名]`。
2. **部分匹配处理**：若提取值格式异常（如日期写成 `2025/1/15`），自动尝试标准化；若标准化失败，保留原始值并降低置信度。
3. **多页冲突**：同一字段在不同页出现不一致的值时，取置信度较高的一页的值，并在输出中附加 `conflictNote` 说明。
4. **人工确认路径**：当超过 3 个字段被标记为 `[需核实:...]` 时，输出结果末尾附提示语："检测到多处信息不确定，建议人工核对原始文件。"
