## 三、标准流程

### 3.1 前置条件

在开始之前，请确认以下信息：

| 前置条件 | 要求 | 验证方式 |
|----------|------|----------|
| Kaneo 实例 | 版本 ≥ 0.9.0 | 在 Kaneo 设置页查看版本号 |
| 团队角色清单 | 明确各成员职责 | 与团队负责人确认角色列表 |
| 项目时间边界 | 明确开始/结束日期或持续运营 | 查看项目立项文档或排期表 |
| 流程偏好 | Scrum / Kanban / 混合 | 与团队确认工作方式 |

### 3.2 执行步骤

**步骤 1：收集输入信息**

向用户确认以下参数：

| 参数 | 类型 | 必填 | 示例值 |
|------|------|------|--------|
| 团队人数 | 整数 | 是 | 8 |
| 项目类型 | 枚举 | 是 | 软件迭代 / 内容生产 / 市场活动 |
| 流程偏好 | 枚举 | 是 | Scrum / Kanban / 混合 |
| 角色清单 | 数组 | 是 | ["产品经理", "开发", "测试", "设计"] |
| 迭代周期 | 整数（天） | 否 | 14 |
| 故事点基准 | 整数 | 否 | 1 点 = 0.5 人天 |

**步骤 2：生成看板结构**

根据输入参数，输出以下内容：

1. **列定义**：每列的名称、目的、入口条件、出口条件
2. **WIP 限制**：每列的并行任务上限
3. **泳道配置**：按项目、优先级、负责人等维度划分

**步骤 3：生成自动化规则**

输出规则清单，每条规则包含：

- 触发条件（事件 + 条件表达式）
- 执行动作（状态变更、字段更新、通知发送）
- 通知对象（角色、个人、群组）

**步骤 4：生成权限矩阵**

输出角色 × 权限的二维表格，权限项包括：

- 看板查看
- 任务创建
- 任务编辑
- 状态变更
- 删除任务
- 管理看板配置

**步骤 5：生成容量规划**

输出：

- 每列 WIP 上限建议值
- 迭代目标点数建议范围
- 团队速度参考值（基于历史数据或行业基准）

**步骤 6：生成实施清单**

输出在 Kaneo 中逐步操作的检查项，每项包含：

- 操作路径（菜单导航）
- 操作内容
- 预期结果

### 3.3 输出规范

输出文档必须包含以下章节：

```
1. 看板结构（含 ASCII 图示）
2. 自动化规则
3. 权限矩阵
4. 容量规划
5. 实施清单
```

## 六、FAQ 反模式对照

### 6.1 常见坑

| 序号 | 常见错误 | 反模式 | 正确做法 |
|------|----------|--------|----------|
| 1 | 列过多 | 创建 15+ 列导致任务分散 | 控制在 5-8 列，聚焦核心流程 |
| 2 | WIP 限制过松 | 不设 WIP 或设得过高 | 根据团队速度设置合理上限 |
| 3 | 权限过于开放 | 所有成员都有管理权限 | 按角色最小化授权 |
| 4 | 自动化规则复杂 | 规则嵌套过多难以维护 | 保持规则简单，单触发单动作 |
| 5 | 忽略容量规划 | 不设迭代目标导致过载 | 根据历史速度设定合理目标 |

### 6.2 反模式对照表

| 反模式 | 症状 | 后果 | 修正方案 |
|--------|------|------|----------|
| 看板即任务列表 | 看板只是待办清单，没有流程概念 | 团队无法识别瓶颈 | 明确每列的入口/出口条件 |
| 泳道滥用 | 每个成员一条泳道 | 无法看到项目整体进度 | 按项目或优先级划分泳道 |
| 自动化过度 | 每个状态变更都触发通知 | 通知轰炸，成员忽略 | 只对关键状态变更发送通知 |
| 权限一刀切 | 所有人权限相同 | 无法控制变更质量 | 按角色差异化授权 |

## 九、自动化规则示例

### 9.1 规则模板

```json
{
  "rule_name": "任务完成通知",
  "trigger": {
    "event": "task.status_changed",
    "condition": {
      "field": "status",
      "operator": "equals",
      "value": "完成"
    }
  },
  "actions": [
    {
      "type": "send_notification",
      "target": "task.creator",
      "message": "你的任务 {{task.title}} 已完成"
    },
    {
      "type": "update_field",
      "field": "completed_at",
      "value": "{{now}}"
    }
  ]
}
```

### 9.2 常用规则场景

| 场景 | 触发条件 | 动作 | 通知对象 |
|------|----------|------|----------|
| 任务延期 | 到期日 < 今天且状态 ≠ 完成 | 标记为延期 + 发送提醒 | 任务负责人 + 项目经理 |
| 高优先级任务创建 | 优先级 = 紧急 | 置顶 + 通知 | 全体成员 |
| 状态阻塞 | 状态 = 阻塞 | 发送告警 | 项目经理 + 任务创建者 |
| 迭代结束 | 迭代结束日期 = 今天 | 生成报告 + 通知 | 全体成员 |

## 十二、实施清单模板

### 12.1 Kaneo 配置步骤

- [ ] **步骤 1：创建项目**
  - 路径：Kaneo 首页 → 新建项目
  - 输入：项目名称、项目描述、时间范围
  - 预期：项目创建成功，进入看板视图

- [ ] **步骤 2：配置列**
  - 路径：项目设置 → 看板配置 → 列管理
  - 输入：按「看板结构」章节添加列
  - 预期：列顺序正确，WIP 限制生效

- [ ] **步骤 3：配置泳道**
  - 路径：项目设置 → 看板配置 → 泳道管理
  - 输入：按「看板结构」章节添加泳道
  - 预期：泳道分组正确，任务可拖拽到对应泳道

- [ ] **步骤 4：设置自动化规则**
  - 路径：项目设置 → 自动化 → 新建规则
  - 输入：按「自动化规则」章节逐条添加
  - 预期：规则生效，触发条件正确执行

- [ ] **步骤 5：配置权限**
  - 路径：项目设置 → 成员管理 → 角色权限
  - 输入：按「权限矩阵」章节分配权限
  - 预期：各角色权限与矩阵一致

- [ ] **步骤 6：验证配置**
  - 路径：看板视图 → 创建测试任务
  - 输入：创建任务并模拟状态流转
  - 预期：所有流程正常，通知正确发送
