### 6.1 常见坑与反模式

| # | 反模式（错误做法） | 正确做法 | 说明 |
|---|---------------------|----------|------|
| 1 | 配置中不写 `test_version`，认为"反正能跑就行" | 始终显式声明版本号 | 版本号用于追踪配置变更历史，缺失时无法判断配置是否过期 |
| 2 | 将 `auth_token` 硬编码在配置中 | 使用环境变量或密钥管理服务引用 | 硬编码 token 存在安全风险，且可能导致配置泄露 |
| 3 | 多个环境共用一份配置，仅修改 `base_url` | 为每个环境维护独立配置 | 不同环境的超时、重试策略可能不同，共用配置容易遗漏差异 |
| 4 | 配置中写注释说明"这个字段暂时不用" | 删除未使用的字段 | 注释中的字段会被解析器忽略，但容易误导后续维护者 |
| 5 | 批量对比时直接粘贴多份配置而不加分隔符 | 使用 `---` 分隔不同配置 | 无分隔符时解析器无法区分配置边界，导致解析失败 |

## 常见问题（FAQ）

**Q: 支持中文文件吗？**
A: 支持，内置 utf-8/gbk/gb18030 多编码容错。

**Q: 运行报错怎么办？**
A: 工具内置异常降级，错误会有明确提示；可先用 --dry-run 预览。

**Q: 如何确认功能正常？**
A: 运行 --selftest，全部通过即核心功能正常。
