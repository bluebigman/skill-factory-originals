# 单文件代码审查 Skill 文档

## 一、能力边界速查卡

本 Skill 用于对**单份代码文件**进行结构化审查。在开始之前，请先明确以下边界，避免预期偏差。

### 1.1 能做与不能做

| 维度 | 能做 | 不能做 |
|------|------|--------|
| 输入规模 | 单文件，建议 ≤ 2000 行 | 多文件项目、跨文件依赖分析 |
| 语言识别 | 常见语言（Python/JS/Java/Go/C++/TS 等） | 冷门语言或混合语言文件 |
| 检查深度 | 语法结构、逻辑缺陷、资源管理、安全风险、可读性 | 运行时行为验证、性能基准测试 |
| 输出形式 | 分级问题清单 + 改进建议 | 自动修复代码、生成补丁 |
| 上下文 | 仅基于文件内可见代码 | 业务背景、历史变更、团队规范 |

### 1.2 适用对象

- 需要快速定位代码隐患的开发者
- 提交 PR 前的自查场景
- 接手他人代码时的初步摸底
- 教学场景中的代码质量讲评

### 1.3 审查维度一览

| 维度 | 检查要点 | 示例 |
|------|----------|------|
| 结构 | 函数长度、嵌套深度、模块划分 | 单个函数超过 80 行 |
| 逻辑 | 分支覆盖、循环边界、异常路径 | 除零未保护、空指针未判 |
| 资源 | 文件句柄、连接池、内存释放 | 打开文件未关闭 |
| 安全 | 注入风险、敏感信息硬编码 | SQL 拼接、密码明文 |
| 可读性 | 命名、注释、魔法数字 | 变量名 `a`、无注释的复杂表达式 |

## 三、标准执行流程

### 3.1 前置条件

在发起审查前，请确认：

- [ ] 代码文件完整，无截断
- [ ] 已明确语言类型（若不确定，可让本 Skill 自动识别）
- [ ] 已指定审查重点（可选，默认全维度）

### 3.2 执行步骤

**步骤 1：解析输入**

- 识别语言类型（通过扩展名、语法特征）
- 统计代码行数（不含空行与注释）
- 提取主要结构（函数、类、模块）

**步骤 2：静态扫描**

按以下顺序逐项检查：

1. **结构健康度**：函数长度（>60 行提示拆分）、嵌套深度（>4 层提示简化）、重复代码块
2. **逻辑正确性**：边界条件、循环终止、异常捕获范围、空值处理
3. **资源管理**：文件/网络/数据库连接是否释放、是否存在资源竞争
4. **安全基线**：注入风险（SQL/命令/路径）、敏感信息（密码/密钥/Token）、危险函数调用
5. **可读性**：命名规范、魔法数字、注释质量、死代码

**步骤 3：问题分级**

| 级别 | 定义 | 处理时限 | 示例 |
|------|------|----------|------|
| 阻断 | 会导致崩溃、数据丢失或安全漏洞 | 立即修复 | 空指针未判、SQL 注入 |
| 严重 | 特定条件下出错或明显性能瓶颈 | 本迭代修复 | 资源未释放、死循环风险 |
| 建议 | 可读性、可维护性改进 | 择机优化 | 魔法数字、命名不规范 |

**步骤 4：生成报告**

按「输出规范」整理结果，确保每条问题包含：位置（行号）、级别、描述、改进建议。

### 3.3 输出规范

```markdown
## 审查报告

**文件**：`<文件名>`
**语言**：<语言类型>
**规模**：<有效行数> 行
**审查重点**：<全维度 / 指定维度>

### 问题清单

#### 阻断级（N 项）

- [ ] **行号 L12**：<问题描述>
  - 改进建议：<具体修改方向>

#### 严重级（N 项）

- [ ] **行号 L45**：<问题描述>
  - 改进建议：<具体修改方向>

#### 建议级（N 项）

- [ ] **行号 L78**：<问题描述>
  - 改进建议：<具体修改方向>

### 总体评价

<2-3 句话概括代码质量状况>
```
