## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 |
|------|------|
| 输入数据 | 文件存在且格式合法（JSON/CSV/YAML/XML） |
| 映射配置 | 至少指定一个字段映射规则（或使用默认映射） |
| 输出目录 | 输出路径可写，批量模式下目录已创建 |
| 运行环境 | Python 3.8+ 或 Node.js 14+（取决于安装方式） |

### 3.2 执行步骤

**步骤 1：准备输入数据**

确保数据文件格式正确。示例（JSON）：

```json
[
  {
    "id": "A001",
    "name": "张三",
    "department": "研发部",
    "email": "zhangsan@example.com"
  },
  {
    "id": "A002",
    "name": "李四",
    "department": "市场部",
    "email": ""
  }
]
```

**步骤 2：配置映射规则（可选）**

创建 `mapping.json` 自定义字段映射：

```json
{
  "title": "用户档案",
  "fields": {
    "id": "编号",
    "name": "姓名",
    "department": "所属部门",
    "email": "电子邮箱"
  },
  "template": "user-profile-template.md"
}
```

**步骤 3：试运行**

```bash
mda --input data.json --output output.md --mapping mapping.json --dry-run
```

试运行输出预览，不写入文件。核对字段映射是否正确。

**步骤 4：正式执行**

```bash
mda --input data.json --output output.md --mapping mapping.json
```

**步骤 5：批量处理（如需）**

```bash
mda --input data.json --batch --output-dir ./generated/ --mapping mapping.json
```

### 3.3 输出规范

| 输出项 | 规范 |
|--------|------|
| 文档标题 | 使用映射配置中的 `title` 字段，默认取数据源文件名 |
| 字段顺序 | 按映射配置中 `fields` 的声明顺序排列 |
| 置信度标注 | 置信度低于阈值的字段输出 `[需核实:字段名]` |
| 元数据头 | 每个文档头部包含生成时间、数据源、版本号 |

示例输出：

```markdown
# 用户档案

> 生成时间：2025-01-15 10:30:00
> 数据源：data.json
> 版本：1.0.0

## 编号
A001

## 姓名
张三

## 所属部门
研发部

## 电子邮箱
[需核实:email]  <!-- 原值为空，置信度低于阈值 -->
```

## 四、置信度门控

### 4.1 置信度计算规则

| 场景 | 置信度 | 输出行为 |
|------|--------|----------|
| 字段存在且格式合法 | 1.0 | 正常输出 |
| 字段存在但格式异常（如邮箱缺少 @） | 0.6 | 输出 `[需核实:字段名]` |
| 字段缺失 | 0.0 | 输出 `[需核实:字段名]` |
| 字段值超出预期长度（如超过 500 字符） | 0.5 | 输出 `[需核实:字段名]` |

### 4.2 阈值配置

默认阈值为 `0.8`。可通过配置文件调整：

```json
{
  "confidence_threshold": 0.9
}
```

### 4.3 不编造原则

当信息不足时，**绝不**推测或填充虚构值。一律输出 `[需核实:字段名]` 占位符，并在文档末尾附注：

```markdown
> 注意：本文档包含 N 个待核实字段，请人工确认后补充。
```

## 六、FAQ 与反模式

### 6.1 常见坑

| 坑 | 反模式 | 正确做法 |
|----|--------|----------|
| 忽略试运行 | 直接执行正式命令，发现映射错误后返工 | 始终先执行 `--dry-run` 预览 |
| 映射字段遗漏 | 只映射了部分字段，其余字段被丢弃 | 检查映射配置是否覆盖所有需要输出的字段 |
| 批量模式无输出目录 | 未创建输出目录，批量任务全部失败 | 先创建输出目录，或使用 `--create-dir` 参数 |
| 置信度阈值设过高 | 阈值设为 1.0，大量字段被标记为需核实 | 根据数据质量合理设置阈值（建议 0.7-0.9） |
| 忽略元数据头 | 输出文档缺少生成时间、数据源信息 | 保留默认元数据头，便于追溯 |

### 6.2 反模式对照

| 反模式 | 问题 | 替代方案 |
|--------|------|----------|
| 在 CI 中直接执行批量处理而不试运行 | 映射错误导致流水线失败 | 在 CI 中先执行 `--dry-run` 并检查输出 |
| 手动修改生成文档后重新生成 | 手动修改被覆盖 | 使用自定义模板或后处理脚本 |
| 将敏感数据直接输出到公开目录 | 数据泄露风险 | 配置输出目录权限，或使用加密输出 |
