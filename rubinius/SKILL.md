## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 | 检查方式 |
|------|------|----------|
| 输入文件 | 文本格式（.csv/.json/.txt/.md） | `file` 命令或扩展名确认 |
| 文件位置 | 与执行目录一致，或提供绝对路径 | `ls -la` 确认存在 |
| 命名规范 | 建议 `*.input.*` 后缀标识原始文件 | 人工确认 |
| 目标 schema | 明确输出字段列表（可默认提供） | 见 3.3 节默认 schema |

### 3.2 执行步骤

1. **确认输入**：列出待处理文件清单，核对文件数量与命名。
2. **单样本试运行**：选取第一个文件，执行解析，检查输出字段是否完整、类型是否正确。
3. **调整映射规则**：若字段名不匹配，修改映射表（见 3.4 节）。
4. **批量执行**：对剩余文件逐一处理，每处理完一个文件输出一行进度日志。
5. **结果校验**：随机抽取 10% 输出条目，与源数据人工比对关键字段。
6. **生成报告**：输出 `summary.json`，包含处理文件数、成功数、失败数、平均置信度。

### 3.3 输出规范

每个输入文件对应一个输出文件，命名规则：`{原文件名}.parsed.json`

输出 JSON 结构：

```json
{
  "source": "原始文件名或URL",
  "parsed_at": "2026-08-19T10:30:00Z",
  "record_count": 123,
  "records": [
    {
      "字段1": "值1",
      "字段2": "值2",
      "_confidence": {
        "字段1": 0.98,
        "字段2": 0.85
      }
    }
  ],
  "warnings": ["字段 '备注' 在 3 条记录中缺失"]
}
```

## 四、置信度门控

### 4.1 置信度评分规则

| 场景 | 置信度 | 说明 |
|------|--------|------|
| 字段值直接匹配且类型正确 | 0.95~1.0 | 完全可信 |
| 字段值经别名映射获得 | 0.85~0.94 | 映射可信，但需注意别名歧义 |
| 字段值经正则提取 | 0.70~0.84 | 依赖正则准确性 |
| 字段值缺失 | 0 | 输出 `[需核实:字段名]` |
| 字段值类型转换（如字符串转数字） | 0.60~0.75 | 转换可能引入误差 |

### 4.2 低置信度处理

- 置信度 < 0.70 的字段，在输出中追加 `"_needs_review": true` 标记。
- 汇总报告中列出所有低置信度字段及原因。
- 绝不使用猜测值填充缺失字段。

## 六、FAQ 反模式

### 6.1 常见坑与反模式对照

| 坑 | 反模式（错误做法） | 正模式（正确做法） |
|----|--------------------|--------------------|
| 字段名大小写不一致 | 直接按大写字段名匹配 | 统一转为小写后再匹配 |
| 日期格式混乱 | 假设所有日期都是 `YYYY-MM-DD` | 使用正则识别多种格式并统一转换 |
| 空值处理 | 用空字符串 `""` 填充缺失字段 | 使用 `[需核实:字段名]` 占位 |
| 批量处理前不试运行 | 直接对全量数据执行 | 先处理单个样本，确认无误后再批量 |
| 忽略原始文件备份 | 直接修改原文件 | 输出到新文件，原文件保持只读 |

### 6.2 反模式示例

**错误做法**：
```python
# 反模式：直接修改原文件，且不检查字段缺失
data = read_csv("input.csv")
data["total"] = data["price"] * data["quantity"]
write_csv("input.csv", data)
```

**正确做法**：
```python
# 正模式：输出到新文件，缺失字段用占位符
data = read_csv("input.csv")
for row in data:
    if "price" not in row or "quantity" not in row:
        row["total"] = "[需核实:total]"
    else:
        row["total"] = row["price"] * row["quantity"]
write_json("input.parsed.json", data)
```
