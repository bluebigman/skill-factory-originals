## 三、标准流程

### 前置条件

| 条件 | 要求 | 检查方式 |
|------|------|----------|
| 文件目录 | 待处理文件已放入同一目录 | `ls` 或资源管理器确认 |
| 命名规范 | 文件名前缀一致（如 `data_001.csv`） | 肉眼检查或 `ls | head` |
| 格式确认 | 明确输入格式与目标格式 | 查看文件头几行 |
| 备份准备 | 原始文件已复制到 `backup/` 子目录 | `cp -r . backup/` |

### 执行步骤

**第 1 步：确认输入规格**

- 列出目录下所有待处理文件：`ls -la`
- 查看每个文件的头 3 行，确认字段分隔符（逗号、制表符、竖线等）
- 记录字段名列表，与目标结构比对

**第 2 步：单样本试运行**

- 选取 1 个最小文件（或文件的前 10 行）执行转换
- 核对输出字段名、字段顺序、数据类型是否符合预期
- 检查特殊字符（引号、换行符、Unicode）是否被正确转义

**第 3 步：批量执行**

- 确认试运行无误后，对目录下全部文件执行转换
- 输出文件命名规则：`原文件名 + _converted + 新扩展名`
- 原始文件保持不动，转换结果写入 `output/` 子目录

**第 4 步：结果校验**

- 随机抽取 5% 的输出条目（至少 3 条）与源数据逐字段比对
- 核对关键字段（ID、时间戳、金额等）是否一致
- 检查是否有 `[需核实:...]` 占位符残留，若有则回溯源文件补全

### 输出规范

| 项目 | 规范 |
|------|------|
| 输出格式 | JSON 数组（默认）或 CSV（指定时） |
| 编码 | UTF-8 无 BOM |
| 换行符 | LF（`\n`），兼容各平台 |
| 字段缺失 | 以 `[需核实:字段名]` 占位，不编造 |
| 空值处理 | 空字符串保留为空字符串，不填充默认值 |
| 文件命名 | `{原文件名}_converted.{ext}` |
| 输出目录 | `output/`（自动创建） |

## 四、置信度门控

当遇到以下情况时，**不得**编造数据，必须输出占位符：

| 场景 | 处理方式 |
|------|----------|
| 源文件某字段为空 | 输出 `[需核实:字段名]` |
| 字段格式不一致（如日期有 `2024-01-01` 和 `2024/1/1`） | 输出 `[需核实:date_format]` |
| 字段含义不明确（如列名 `a`、`b` 无表头说明） | 输出 `[需核实:column_meaning]` |
| 文件编码无法识别 | 输出 `[需核实:file_encoding]` 并跳过该文件 |
| 数据量级异常（如某字段值超出合理范围 100 倍） | 输出 `[需核实:value_range]` |

**原则**：宁可标记待核实，不可猜测填充。所有占位符在最终报告中列出，供人工复核。
