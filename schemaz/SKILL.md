# schemaz — 数据整形与结构转换技能

## 一、能力边界速查卡

### 1.1 工具定位

schemaz 是一个面向开发者和数据处理人员的命令行工具，用于将各种来源的数据（CSV、JSON、日志文件等）按照预定义的规则转换为统一的结构化格式。它解决的是"数据形态不一致"的问题，而非"数据内容正确性"的问题。

### 1.2 能做什么

| 能力项 | 说明 | 示例 |
|--------|------|------|
| 字段映射 | 将源字段名映射为目标字段名 | `user_name` → `username` |
| 类型转换 | 字符串/数字/布尔之间的自动转换 | `"123"` → `123` |
| 日期标准化 | 解析多种日期格式并统一输出 | `2026/08/19` → `2026-08-19` |
| 枚举值校验 | 检查字段值是否在允许范围内 | 状态字段仅允许 `active/inactive/pending` |
| 批量处理 | 多文件独立转换，互不影响 | 一次处理 100 个 CSV 文件 |
| 置信度标注 | 对转换结果的可信程度打分 | 类型转换失败时降置信度 |
| 自定义模板 | 按业务需求定制输出格式 | 输出为特定 API 的 JSON 结构 |

### 1.3 不能做什么

| 限制项 | 说明 |
|--------|------|
| 不编造数据 | 缺失必填字段时输出占位符，绝不猜测 |
| 不保证数据正确性 | 只做格式转换，不验证源数据本身的业务正确性 |
| 不处理非结构化文本 | 无法从自由文本中抽取实体（需配合 NLP 工具） |
| 不执行数据删除 | 不做去重或清洗（可通过后处理钩子实现） |
| 不支持流式处理 | 必须基于文件输入，不支持 stdin 管道 |

### 1.4 适用对象

- 需要定期将多源数据统一格式的数据工程师
- 需要将导出数据转换为特定 API 格式的后端开发者
- 需要批量整理历史数据文件的数据分析师
- 需要将 CSV 数据导入数据库的运维人员

## 三、标准处理流程

### 3.1 前置条件

| 条件 | 要求 | 检查方法 |
|------|------|---------|
| 输入文件 | 位于当前工作目录 | `ls` 确认 |
| 文件命名 | `[前缀]_[日期].[扩展名]` | 如 `user_data_20260819.csv` |
| 批量文件 | 前缀一致 | 如 `order_20260801.csv`、`order_20260802.csv` |
| 输出目录 | 自动创建，无需手动准备 | 默认 `./output/` |

### 3.2 执行步骤

#### 第一步：放置文件

将待处理文件放入当前工作目录，确认命名符合规范：

```
# 正确示例
user_data_20260819.csv
order_20260801.csv
order_20260802.csv

# 错误示例
data.csv          # 缺少日期
user_data.csv     # 缺少日期
20260819_user.csv # 日期位置不对
```

#### 第二步：运行样本测试

先处理单个文件，验证转换规则是否符合预期：

```bash
schemaz --input user_data_20260819.csv --sample
```

样本模式只处理前 10 行数据，输出到 `./output/sample/` 目录。

#### 第三步：检查输出

打开样本输出，核对以下内容：

- [ ] 输出字段是否完整（无缺失列）
- [ ] 字段类型是否正确（字符串/数字/布尔）
- [ ] 置信度标注是否合理（>0.8 为可信）
- [ ] 日期格式是否统一

#### 第四步：批量执行

样本验证通过后，执行完整批量处理：

```bash
schemaz --pattern "user_data_*.csv" --batch
```

批量模式参数说明：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--pattern` | 文件匹配模式 | `*.csv` |
| `--resume` | 跳过已处理的文件 | `false` |
| `--priority` | 处理优先级（按文件名/大小/日期） | `filename` |
| `--output-dir` | 输出目录 | `./output/` |
| `--threads` | 并行线程数 | `4` |

#### 第五步：验证结果

批量处理完成后，执行质量验证：

```bash
schemaz --verify --ratio 0.1
```

验证流程：
1. 随机抽取 10% 的输出文件
2. 比对关键字段（ID、时间戳、状态值）与源数据一致性
3. 检查置信度低于 0.8 的字段，标记需人工修正

### 3.3 输出规范

输出目录结构：

```
output/
├── sample/              # 样本输出
│   └── user_data_20260819.sample.json
```

## 四、置信度门控机制

### 4.1 基本原则

**信息不足时输出占位符，绝不编造数据。** 置信度低于 0.8 的字段必须标注，由人工确认。

### 4.2 置信度评分规则

| 场景 | 置信度 | 说明 |
|------|--------|------|
| 字段值完全匹配预期类型 | 1.0 | 无需人工复核 |
| 类型自动转换成功 | 0.95 | 如字符串 `"123"` → 数字 `123` |
| 日期格式解析成功 | 0.9 | 如 `2026/08/19` → `2026-08-19` |
| 枚举值在允许范围内 | 0.9 | 状态字段值合法 |
| 类型转换失败，保留原字符串 | 0.6 | 需人工确认 |
| 日期解析失败，标记占位 | 0.5 | 需人工修正 |
| 必填字段缺失 | 0.3 | 输出 `[需核实:字段名]` |
| 枚举值超出范围 | 0.4 | 保留原值，标注 `[需核实:枚举值]` |

### 4.3 占位符规范

| 占位符 | 使用场景 | 示例 |
|--------|---------|------|
| `[需核实:字段名]` | 必填字段缺失 | `[需核实:email]` |
| `[需核实:枚举值]` | 枚举值超出范围 | `[需核实:枚举值]` |
| `[需核实:日期]` | 日期格式无法解析 | `[需核实:日期]` |

### 4.4 调整置信度阈值

高级用户可通过配置文件调整置信度规则：

```yaml
# schemaz.config.yaml
confidence:
  threshold: 0.8          # 全局阈值
  type_mismatch: 0.6      # 类型不匹配
  date_parse_fail: 0.5    # 日期解析失败
  missing_required: 0.3   # 缺失必填字段
  enum_out_of_range: 0.4  # 枚举值超范围
```

## 五、错误码体系

### 5.1 错误码速查表

| 错误码 | 含义 | 提示话术 | 修正步骤 |
|--------|------|---------|---------|
| E1001 | 文件不存在 | "找不到文件：{filename}" | 检查文件路径和命名 |
| E1002 | 文件命名不规范 | "文件名缺少日期或前缀" | 重命名为 `[前缀]_[日期].[扩展名]` |
| E1003 | 必填字段缺失 | "字段 {field} 为必填项" | 检查源数据，补充字段或调整映射规则 |
| E1004 | 日期格式无法解析 | "无法解析日期：{value}" | 检查日期格式，或添加自定义日期格式 |
| E1005 | 枚举值超出范围 | "枚举值 {value} 不在允许列表内" | 检查源数据，或扩展枚举列表 |
| E1006 | 类型转换失败 | "无法将 {value} 转换为 {type}" | 检查源数据，或调整类型映射 |
| E1007 | 输出目录写入失败 | "无法写入输出文件：{path}" | 检查目录权限和磁盘空间 |
| E1008 | 配置文件格式错误 | "配置文件解析失败：{detail}" | 检查 YAML/JSON 语法 |
| E1009 | 批量处理中断 | "批量处理在第 {n} 个文件处中断" | 使用 `--resume` 参数继续处理 |
| E1010 | 内存不足 | "内存不足，请减少批量文件数或使用 --threads 1" | 降低并行度或分批处理 |

### 5.2 错误处理策略

- **单文件错误**：不影响其他文件的处理，错误记录在批次报告中
- **致命错误**（如 E1007）：立即终止整个批次
- **可恢复错误**（如 E1004）：标记该文件为失败，继续处理后续文件

## 六、FAQ 反模式对照

### 6.1 常见坑与反模式

| 坑 | 反模式（错误做法） | 正模式（正确做法） |
|----|-------------------|-------------------|
| **跳过样本测试** | 直接批量处理所有文件，结果发现映射规则错误 | 先跑样本，验证规则后再批量执行 |
| **忽略置信度标注** | 批量处理完成后直接使用所有输出，不检查置信度 | 检查置信度 <0.8 的字段，人工确认后再使用 |
| **修改源文件** | 在转换前手动修改源数据文件 | 保留源文件不变，通过映射规则实现转换 |
| **不检查批次报告** | 批量处理后不查看报告，不知道有失败文件 | 每次批量处理后必查 `batch_report_*.json` |
| **使用绝对路径** | 在配置文件中写死绝对路径，换环境就失效 | 使用相对路径或环境变量 |

### 6.2 反模式对照表

| 反模式 | 问题 | 推荐替代 |
|--------|------|---------|
| 手动修改 CSV 再转换 | 无法追溯，易出错 | 用映射规则自动处理 |
| 用 Excel 打开输出文件再另存 | 可能改变编码和格式 | 直接使用 schemaz 输出 |
| 批量处理时不加 `--resume` | 中断后需从头开始 | 加 `--resume` 跳过已完成文件 |
| 忽略日期格式异常 | 下游系统解析失败 | 检查 `[需核实:日期]` 占位符 |

```python
# hooks.py
def post_process(record):
    """后处理钩子：去除字符串首尾空格"""
    for key, value in record.items():
        if isinstance(value, str):
            record[key] = value.strip()
    return record

def deduplicate(records):
    """去重钩子：按 ID 去重"""
    seen = set()
    unique_records = []
    for record in records:
        if record.get("id") not in seen:
            seen.add(record.get("id"))
            unique_records.append(record)
    return unique_records
```
