## 三、标准流程

### 前置条件

| 条件 | 要求 | 检查方式 |
|------|------|----------|
| 运行环境 | Python 3.8+ 或支持 JSON 解析的脚本环境 | 执行 `python --version` |
| 输入目录 | 存放待处理文件，路径无中文和空格 | `ls input_dir` |
| 输出目录 | 存放转换结果，可读写 | `touch output_dir/.write_test` |
| 网络权限 | 抓取 URL 前确认目标网站允许访问 | 查看 robots.txt |
| 环境自检 | 执行 `gstack --check` 确认就绪 | 返回 `OK` 即通过 |

### 执行步骤

**第一步：准备文件**

将所有待处理文件放入同一目录。支持格式：`.csv`、`.json`、`.txt`、`.log`、`.xml`。

```
input/
  ├── data1.csv
  ├── data2.csv
  └── notes.txt
```

**第二步：单文件试运行**

先处理一个文件验证效果，避免批量出错：

```bash
gstack --input input/data1.csv --output output/
```

检查 `output/data1.json` 是否符合预期。

**第三步：批量处理**

单文件无误后，处理全部文件：

```bash
gstack --input input/ --output output/ --batch
```

**第四步：校验输出**

检查输出目录中的每个结果文件：

```bash
gstack --verify output/
```

校验项包括：JSON 语法合法、字段完整、类型正确。

### 输出规范

#### 默认输出结构

```json
{
  "source": "data1.csv",
  "processed_at": "2025-01-15T10:30:00Z",
  "record_count": 42,
  "records": [
    {
      "field1": "value1",
      "field2": 123
    }
  ]
}
```

#### 字段映射规则

| 输入类型 | 输出类型 | 转换规则 |
|----------|----------|----------|
| 字符串数字（"123"） | 数值（123） | 自动识别并转换 |
| 日期字符串（"2024-01-01"） | ISO 8601 | 统一格式 |
| 布尔字符串（"true"/"false"） | 布尔值 | 大小写不敏感 |
| 空字符串 | null | 保留字段但置空 |
| 嵌套 JSON 字符串 | 嵌套对象 | 自动解析 |

#### 自定义格式（template.json）

创建 `template.json` 定义输出字段：

```json
{
  "fields": [
    {"source": "name", "target": "product_name", "type": "string"},
    {"source": "price", "target": "amount", "type": "number"},
    {"source": "in_stock", "target": "available", "type": "boolean"}
  ],
  "sort_by": "amount",
  "sort_order": "desc"
}
```

使用方式：

```bash
gstack --input input/ --output output/ --template template.json
```

## 四、置信度门控

当输入信息不足或字段无法确认时，**不编造数据**，使用占位符标记：

| 场景 | 输出占位符 | 说明 |
|------|-----------|------|
| 字段缺失 | `[需核实:字段名]` | 源数据中不存在该字段 |
| 类型不确定 | `[需核实:类型]` | 无法判断应转为哪种类型 |
| URL 内容为空 | `[需核实:内容]` | 抓取结果无有效内容 |
| 编码无法识别 | `[需核实:编码]` | 文件编码非 UTF-8/GBK 常见格式 |

示例：

```json
{
  "records": [
    {
      "name": "商品A",
      "price": 99.9,
      "stock": "[需核实:stock]"
    }
  ]
}
```

**处理建议**：出现占位符后，检查源文件对应字段，补充数据后重新运行。

## 六、FAQ 反模式

### 反模式 1：直接批量处理

**错误做法**：拿到文件后直接跑 `--batch`，结果 500 个文件全部出错。

**正确做法**：先单文件试运行，确认输出无误后再批量。

### 反模式 2：忽略置信度占位符

**错误做法**：看到 `[需核实:xxx]` 直接删掉，假装数据完整。

**正确做法**：逐项核实占位符对应的源数据，补充后重新处理。

### 反模式 3：模板字段名随意写

**错误做法**：template.json 中 source 字段与源数据实际字段名不一致，导致大量 `E006` 错误。

**正确做法**：先查看源数据字段结构，再编写模板。

### 反模式 4：输出覆盖源文件

**错误做法**：将输出目录设为输入目录，导致源文件被覆盖。

**正确做法**：始终使用独立输出目录，与输入目录分离。

### 反模式 5：忽略环境自检

**错误做法**：跳过 `gstack --check`，运行到一半才发现环境不兼容。

**正确做法**：每次使用前先执行自检，确认环境就绪。
