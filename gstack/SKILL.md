# gstack — 数据整理与结构化转换 Skill 文档

## 一、能力边界（一页纸速查卡）

### 1.1 能做什么

| 能力项 | 说明 | 示例 |
|--------|------|------|
| 文件转结构化 | 将 CSV、JSON、TXT 等文件转换为统一结构化输出 | `input_001.csv` → 标准 JSON 数组 |
| URL 抓取转结构化 | 从指定 URL 提取数据并转换为结构化结果 | 网页表格 → JSON |
| 批量处理 | 对同一目录下多个文件执行相同转换逻辑 | `input_*.csv` 全量转换 |
| 自定义格式 | 通过 `template.json` 定义字段映射和输出结构 | 字段重命名、类型转换、嵌套结构 |
| 数据校验 | 转换过程中自动检查字段完整性和格式合法性 | 缺失字段标记、日期格式校验 |

### 1.2 不能做什么（明确边界）

| 禁止项 | 说明 |
|--------|------|
| 不编造数据 | 源文件某字段缺失时，输出 `[需核实:字段名]` 占位，绝不猜测填充 |
| 不猜测格式 | 无法判断日期格式时，保留原始字符串并标注 `[需核实:日期格式]` |
| 不推断语义 | 文本含义不明时，不进行自动纠错、补全或语义推断 |
| 不处理二进制 | 不支持图片、音视频等非文本二进制文件的转换 |
| 不访问受限资源 | 需要登录认证的 URL 或内网资源不在处理范围内 |

### 1.3 适用对象

- **数据工程师**：需要快速将多格式数据统一为结构化输出
- **业务分析师**：需要将导出数据转换为可分析的格式
- **运营人员**：需要批量处理报表、日志等常规文件
- **开发者**：需要将外部数据源集成到自己的系统中

## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 | 检查方法 |
|------|------|----------|
| 文件目录 | 所有待处理文件放入同一目录 | `ls -la /path/to/files/` |
| 命名规范 | 文件命名遵循一致模式，如 `input_001.csv` | `ls /path/to/files/ | head -20` |
| 模板文件（可选） | 如需自定义输出格式，创建 `template.json` | `cat template.json` |
| 环境依赖 | Python 3.8+，已安装 gstack 包 | `gstack --version` |

### 3.2 执行步骤

#### 步骤 1：环境自检

```bash
gstack --selftest
```

预期输出：
```
[OK] 环境检查通过
[OK] 依赖库完整
[OK] 模板解析正常
```

#### 步骤 2：单文件试运行

选取一个样本文件执行转换：

```bash
gstack convert input_001.csv --output output_001.json
```

检查输出：
- 字段是否完整
- 格式是否正确
- 类型是否符合预期

#### 步骤 3：模板调整（如需）

若字段缺失或顺序错误，修改 `template.json`：

```json
{
  "field_mapping": {
    "原字段名": "新字段名",
    "date_str": "date",
    "amount_str": "amount"
  },
  "type_conversion": {
    "date": "ISO8601",
    "amount": "float"
  },
  "output_structure": "flat"
}
```

#### 步骤 4：全量执行

确认试运行无误后，对全量数据执行：

```bash
gstack convert /path/to/files/input_*.csv --output /path/to/output/ --batch
```

注意事项：
- 使用通配符或目录参数指定全部文件
- 保留原始文件备份
- 输出到独立目录，避免覆盖源文件

#### 步骤 5：结果抽查

抽查输出条目（至少 5 条）：

```bash
gstack verify output_001.json --sample 5
```

核对内容：
- 关键字段与源数据是否一致
- 日期格式是否正确
- 数值精度是否保留

### 3.3 输出规范

| 输出项 | 规范要求 |
|--------|----------|
| 文件命名 | `output_<原文件名>.json` |
| 编码格式 | UTF-8 无 BOM |
| 字段顺序 | 按 template.json 中定义顺序 |
| 空值处理 | 缺失字段输出 `[需核实:字段名]` |
| 日期格式 | 统一为 ISO8601（如无法判断则保留原样并标注） |

## 五、错误码体系

### 5.1 错误码速查表

| 错误码 | 含义 | 提示话术 | 修正步骤 |
|--------|------|----------|----------|
| `E001` | 文件不存在 | `错误: 找不到文件 <path>` | 检查路径是否正确，确认文件已放入指定目录 |
| `E002` | 文件编码不支持 | `错误: 无法识别文件编码` | 将文件转为 UTF-8 编码后重试 |
| `E003` | 分隔符错误 | `错误: 无法解析分隔符` | 检查 CSV 分隔符是否为逗号，或指定 `--delimiter` 参数 |
| `E004` | 模板字段不匹配 | `错误: 模板字段 <field> 在源文件中不存在` | 检查 template.json 字段名与源文件列名是否一致 |
| `E005` | 日期格式无法解析 | `警告: 日期字段 <field> 格式无法识别，已保留原样` | 在 template.json 中指定 `date_format` 参数 |
| `E006` | 批量处理中断 | `错误: 第 <n> 个文件处理失败，已停止` | 检查失败文件的具体错误，修复后使用 `--skip-errors` 跳过 |
| `E007` | 输出目录无权限 | `错误: 无法写入输出目录` | 检查目录权限，或更换输出路径 |
| `E008` | URL 访问失败 | `错误: 无法访问 <url>，状态码 <code>` | 检查网络连接，确认 URL 可公开访问 |

### 5.2 错误处理建议

- **单文件错误**：先修复单个文件问题，再重新执行
- **批量错误**：使用 `--skip-errors` 跳过问题文件，最后统一处理
- **模板错误**：先验证模板与样本文件的匹配性，再全量执行

## 八、自定义格式配置指南

### 8.1 template.json 结构

```json
{
  "version": "1.0",
  "field_mapping": {
    "source_field": "target_field"
  },
  "type_conversion": {
    "target_field": "string|integer|float|boolean|date"
  },
  "date_format": "YYYY-MM-DD",
  "output_structure": "flat|nested",
  "nested_fields": {
    "parent_field": ["child_field_1", "child_field_2"]
  },
  "filter_rules": {
    "exclude_empty": true,
    "exclude_fields": ["internal_id"]
  }
}
```

### 8.2 参数说明

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `version` | string | 是 | 模板版本号 |
| `field_mapping` | object | 是 | 源字段到目标字段的映射 |
| `type_conversion` | object | 否 | 目标字段的类型转换规则 |
| `date_format` | string | 否 | 日期格式，如 `YYYY-MM-DD` |
| `output_structure` | string | 否 | 输出结构，`flat`（扁平）或 `nested`（嵌套） |
| `nested_fields` | object | 否 | 嵌套结构定义 |
| `filter_rules` | object | 否 | 过滤规则 |

### 8.3 示例：扁平结构

```json
{
  "version": "1.0",
  "field_mapping": {
    "name": "full_name",
    "age": "age",
    "email": "email_address"
  },
  "type_conversion": {
    "age": "integer"
  },
  "output_structure": "flat"
}
```

### 8.4 示例：嵌套结构

```json
{
  "version": "1.0",
  "field_mapping": {
    "user_name": "user.name",
    "user_age": "user.age",
    "order_id": "order.id",
    "order_amount": "order.amount"
  },
  "type_conversion": {
    "user.age": "integer",
    "order.amount": "float"
  },
  "output_structure": "nested"
}
```

## 九、批量处理高级技巧

### 9.1 通配符使用

```bash
# 处理所有 CSV 文件
gstack convert /data/input_*.csv --output /data/output/ --batch

# 处理特定日期范围的文件
gstack convert /data/input_2024*.csv --output /data/output/ --batch
```

### 9.2 错误跳过策略

```bash
# 跳过有错误的文件，继续处理后续文件
gstack convert /data/input_*.csv --output /data/output/ --batch --skip-errors

# 记录错误日志
gstack convert /data/input_*.csv --output /data/output/ --batch --error-log errors.txt
```

### 9.3 并发处理

```bash
# 使用 4 个并行进程处理
gstack convert /data/input_*.csv --output /data/output/ --batch --workers 4
```
