## 四、置信度门控

当输入数据不完整或存在歧义时，工具会输出占位符而非编造数据：

| 场景 | 输出占位符 | 说明 |
|------|------------|------|
| 缺少 `id` 字段 | `[需核实:id]` | 无法生成唯一标识 |
| 缺少 `text` 字段 | `[需核实:text]` | 无法确定激励内容 |
| 缺少 `category` 字段 | `[需核实:category]` | 无法确定分类 |
| 时间戳无法解析 | `[需核实:timestamp]` | 无法确定处理时间 |
| 状态异常 | `[需核实:status]` | 无法确定处理结果 |

**处理原则：**

1. 优先保留原始数据，仅在缺失时插入占位符
2. 占位符格式统一为 `[需核实:字段名]`
3. 校验阶段会标记所有含占位符的记录

## 六、FAQ 反模式

### 6.1 常见坑与反模式对照

| 反模式 | 问题描述 | 正确做法 |
|--------|----------|----------|
| 跳过试运行直接批量 | 批量处理时才发现字段错误，浪费资源 | 始终先执行 `--limit 1` 试运行 |
| 忽略备份参数 | 处理失败后原始数据丢失 | 批量处理时始终添加 `--backup` |
| 手动修改输出文件 | 破坏输出格式，导致后续校验失败 | 通过工具重新生成，不手动编辑 |
| 使用非标准时间格式 | 时间戳解析失败，输出占位符 | 统一使用 ISO 8601 格式 |
| 输入文件放在根目录 | 工具无法识别，报 E001 错误 | 始终将输入文件放在 `input/` 目录 |

### 6.2 反模式示例

**错误做法：**

```bash
# 跳过试运行，直接处理整个目录
dev-motivation-cli --input input/ --output output/
```

**正确做法：**

```bash
# 先试运行一条
dev-motivation-cli --input input/motivation_2025-01-15.json --limit 1

# 确认无误后再批量处理
dev-motivation-cli --input input/ --output output/ --backup
```
