## 三、标准执行流程

### 3.1 前置条件

| 条件项 | 要求 | 检查方式 |
|--------|------|----------|
| 输入文本 | 非空，编码为 UTF-8，大小不超过 10MB | 自动检测 |
| 检索模式 | 至少 1 个，最多 50 个，每个长度 1-256 字符 | 自动校验 |
| 输出格式 | 默认为 JSON，可选 Markdown 表格 | 用户指定或默认 |
| 环境依赖 | 无外部依赖，纯本地计算 | 自动确认 |

### 3.2 执行步骤（分步编号）

1. **输入收集与确认**
   - 接收用户提供的文本内容、文件路径或 URL。
   - 若为文件路径，检查文件是否存在且为文本格式（`.txt`, `.md`, `.log`, `.csv`）。
   - 若为 URL，发送 HTTP GET 请求获取内容，超时时间 10 秒。
   - 向用户回显输入摘要（文本长度、来源类型），等待确认或直接进入下一步。

2. **检索模式解析**
   - 将用户提供的检索目标拆分为独立模式串。
   - 去除空模式与重复模式（保留首次出现）。
   - 若模式数量超过 50，截断并提示用户。

3. **BMH 检索执行**
   - 对每个模式构建坏字符跳转表。
   - 在输入文本中执行 Boyer-Moore-Horspool 搜索。
   - 记录每个命中的起始位置（0-based）与匹配长度。

4. **上下文提取与结构化**
   - 对每个命中，提取前后各 50 字符作为上下文（若边界不足则截断）。
   - 计算置信度：若模式长度 ≥ 5 且命中位置唯一，置信度为 `high`；若模式长度 < 5 或命中位置重叠，置信度为 `medium`；若存在部分匹配（如大小写不一致），置信度为 `low`。

5. **结果输出与自查**
   - 按约定格式生成输出（见 3.3）。
   - 自查：字段完整性（`match_id`, `position`, `context`, `confidence` 是否齐全）、格式正确性（JSON 合法性）、置信度标注是否合理。
   - 若发现缺失字段或格式错误，重新生成。

### 3.3 输出规范

#### 默认 JSON 格式

```json
{
  "input_summary": {
    "source_type": "text|file|url",
    "text_length": 12345,
    "pattern_count": 3
  },
  "matches": [
    {
      "match_id": 1,
      "pattern": "ERROR",
      "position": 1024,
      "context": "...previous text... ERROR ...following text...",
      "confidence": "high"
    }
  ],
  "statistics": {
    "total_matches": 5,
    "patterns_with_matches": 2,
    "patterns_without_matches": 1
  }
```

#### Markdown 表格格式（可选）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `match_id` | int | 是 | 全局唯一命中序号，从 1 递增 |
| `pattern` | string | 是 | 命中的检索模式原文 |
| `position` | int | 是 | 命中起始位置（0-based） |
| `context` | string | 是 | 前后各 50 字符的上下文 |
| `confidence` | string | 是 | `high` / `medium` / `low` 三档 |
