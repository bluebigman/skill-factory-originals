# 笔记整理与结构化归档 Skill 文档

## 一、能力边界与适用对象（速查卡）

本 Skill 面向需要将零散、口语化、非结构化的笔记内容转化为可复用、可检索、层级分明的 Markdown 文档的场景。它不改变原始内容的语义，只做形式与结构的规范化处理。

### 1.1 能做与不能做

| 能力维度 | 支持情况 | 具体说明 |
|---------|---------|---------|
| 文本识别 | ✅ 支持 | 识别输入文本中的标题、列表、段落、代码块、引用等基础 Markdown 元素 |
| 结构推断 | ✅ 支持 | 根据内容语义自动划分章节层级，生成目录树 |
| 信息补全 | ⚠️ 有限支持 | 仅对明显缺失的日期、编号、标签等元数据做占位标记，不进行事实性补充 |
| OCR 识别 | ❌ 不支持 | 本 Skill 不处理图片或扫描件，仅处理纯文本输入 |
| 语义改写 | ❌ 不支持 | 不改变原文措辞，不进行摘要或扩写 |
| 跨文档合并 | ❌ 不支持 | 单次仅处理一份笔记文本 |
| 格式转换 | ✅ 支持 | 输出统一为 Markdown 格式，兼容主流笔记软件导入 |

### 1.2 适用对象

- **个人知识管理**：读书笔记、会议记录、灵感碎片、学习日志
- **团队协作场景**：项目复盘、需求讨论记录、周报素材整理
- **内容创作者**：选题库、素材收集、采访速记

### 1.3 不适用对象

- 已高度结构化的 Markdown 文件（无需二次处理）
- 包含大量图片、表格、复杂公式的笔记（本 Skill 仅处理纯文本）
- 需要事实核查或数据验证的内容（本 Skill 只做形式整理）

## 三、标准执行流程

### 3.1 前置条件

- 输入内容必须为纯文本格式（支持 Markdown 语法）
- 单次输入文本长度建议不超过 50,000 字符
- 若输入内容包含敏感信息，请自行脱敏后再提交

### 3.2 执行步骤

**步骤 1：输入接收与预处理**

接收用户输入的原始笔记文本。系统自动执行以下预处理：
- 去除多余空行（连续空行压缩为单空行）
- 统一换行符为 `\n`
- 识别文本中的 Markdown 标记（`#`、`-`、`1.`、`>`、```` ``` ```` 等）

**步骤 2：结构识别与层级划分**

对预处理后的文本进行语义分析，识别以下结构元素：

| 结构元素 | 识别规则 | 示例 |
|---------|---------|------|
| 一级标题 | 文本开头或独立成行的短句（<20字） | "项目启动会" |
| 二级标题 | 以数字、日期、关键词开头的短句 | "2026-08-13 讨论" |
| 列表项 | 以 `-`、`*`、`+` 开头的行 | "- 张三负责前端" |
| 编号项 | 以 `1.`、`2.` 等开头的行 | "1. 确定需求范围" |
| 引用块 | 以 `>` 开头的行 | "> 客户反馈：界面卡顿" |
| 代码块 | 以 ```` ``` ```` 包裹的内容 | 代码片段 |

**步骤 3：结构化重组**

根据识别结果，按以下规则重组内容：

1. 为每个一级标题生成 `##` 层级
2. 为每个二级标题生成 `###` 层级
3. 列表项统一缩进为 2 空格
4. 引用块统一使用 `>` 标记
5. 为缺失标题的段落自动生成 `### 未分类内容` 占位标题
6. 为缺失日期的记录添加 `[需核实:日期]` 占位符

**步骤 4：元数据补全与校验**

- 检查输出文档中是否存在 `[需核实:字段名]` 占位符
- 检查标题层级是否连续（不允许从 `##` 直接跳到 `####`）
- 检查列表缩进是否一致
- 检查代码块是否闭合

**步骤 5：输出文件生成**

生成两个文件：

1. **主文件**：`整理结果_YYYYMMDD_HHMMSS.md`（时间戳取当前系统时间）
2. **校验报告**：`校验报告_YYYYMMDD_HHMMSS.md`

### 3.3 输出规范

主文件结构如下：

```markdown
# 笔记整理结果

> 整理时间：YYYY-MM-DD HH:MM:SS
> 原始内容长度：N 字符
> 整理后内容长度：M 字符

## 目录

- [章节一](#章节一)
- [章节二](#章节二)

## 章节一

### 子章节

正文内容...

## 未分类内容

[需核实:日期] 待补充的碎片信息
```

校验报告结构如下：

```markdown
# 校验报告

- 检查时间：YYYY-MM-DD HH:MM:SS
- 检查项数量：N
- 通过项数量：M
- 警告项数量：K
- 失败项数量：J

## 检查明细

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 标题层级连续性 | ✅ 通过 | - |
| 列表缩进一致性 | ⚠️ 警告 | 第 15 行缩进不一致 |
| 代码块闭合 | ✅ 通过 | - |
| 占位符检查 | ❌ 失败 | 存在 2 处 [需核实] 占位符 |

## 待处理事项

- [ ] 补充 [需核实:日期] 的具体日期
- [ ] 确认 [需核实:人名] 的完整姓名
```

## 四、置信度门控机制

本 Skill 遵循"宁缺毋滥"原则，在信息不足时明确标记，绝不编造内容。

| 占位符格式 | 使用场景 | 示例 |
|-----------|---------|------|
| `[需核实:字段名]` | 信息缺失或模糊时 | `[需核实:日期]`、`[需核实:人名]` |
| `[需核实:数值]` | 数字不确定时 | `[需核实:预算金额]` |

### 4.2 门控触发条件

以下情况必须输出占位符，不得自行推断：

- 原文中出现"大概"、"可能"、"好像"等模糊词汇，且无法从上下文确认
- 日期、人名、数字等关键信息缺失
- 内容存在明显矛盾（如两个段落对同一事件的描述不一致）

### 4.3 门控解除条件

- 用户后续提供补充信息
- 上下文中有明确线索可推断（如"上周三"可结合整理日期推算）

## 六、常见坑位与反模式对照（FAQ）

### 坑位 1：过度整理

**错误做法**：将原文中每个短句都强行提升为标题，导致文档碎片化。

**反模式示例**：
```
## 今天
### 天气
### 不错
### 适合
### 跑步
```

**正确做法**：保留原文的自然段落结构，仅对语义完整的内容块进行层级划分。

### 坑位 2：信息丢失

**错误做法**：整理过程中删除了看似"不重要"的碎片信息。

**反模式示例**：原文中"顺便记一下：下周三是老王生日"被删除。

**正确做法**：所有信息保留，无法归类的放入"未分类内容"章节。

### 坑位 3：编造信息

**错误做法**：原文未提及日期，整理时自行补上"2026-08-13"。

**反模式示例**：输出文档中出现原文没有的具体日期。

**正确做法**：使用 `[需核实:日期]` 占位符标记。

### 坑位 4：层级混乱

**错误做法**：标题层级跳跃，从 `##` 直接跳到 `####`。

**反模式示例**：
```
## 一级标题
#### 三级标题（跳级）
```

**正确做法**：确保标题层级连续递增或递减。

### 坑位 5：忽略校验报告

**错误做法**：只查看主文件，忽略校验报告中的警告和失败项。

**正确做法**：每次整理后必须查看校验报告，处理所有待核实项。
