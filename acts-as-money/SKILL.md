### 3.2 执行步骤（分阶段）

#### 阶段一：输入预处理
1. 判断输入类型（文本/文件/URL）
2. 若为 URL，发起 HTTP 请求（超时 10 秒，失败重试 2 次，重试间隔指数退避 1s/2s/4s）
3. 若为文件，读取并校验编码（UTF-8/GBK 自动识别，若识别失败则尝试 UTF-8 并报告警告）
4. 将输入统一转为纯文本字符串
5. 若输入为空或仅含空白字符 → 返回错误码 `E1001`

#### 阶段二：金额解析
1. 使用正则表达式匹配金额模式（支持千分位、小数点、正负号、括号负数）
2. 识别货币符号（$、€、¥、£、₩、₹ 等）和 ISO 代码（USD、EUR、CNY 等）
3. 若启用 `unit_convert`，识别中文单位（万、亿）并转换为数值
4. 若启用 `chinese_upper`，识别中文大写金额（壹、贰、叁…）并转换为数值
5. 提取日期字段（支持 YYYY-MM-DD、MM/DD/YYYY、DD/MM/YYYY 等格式）
6. 若启用 `range` 参数，识别范围模式（如 "100-200 USD"）
7. 若启用 `currency_map`，应用自定义货币符号映射

#### 阶段三：置信度评估
1. 高置信度（≥0.9）：金额格式标准、币种明确、无歧义
2. 中置信度（0.7-0.9）：金额格式标准但币种缺失，或币种明确但格式非标准
3. 低置信度（<0.7）：金额格式异常、币种缺失且格式非标准，或存在多种解析可能
4. 置信度评分细则：
   - 基础分 0.5：成功匹配金额模式
   - +0.2：币种明确（符号或 ISO 代码）
   - +0.15：格式完全标准（千分位、两位小数）
   - +0.15：无歧义（仅一种解析可能）
   - 扣分项：币种缺失 -0.2，格式异常 -0.15，多义 -0.15

#### 阶段四：智能洞察（Smart Insights）
> 本阶段自动执行，无需用户额外操作。

1. **模式识别**：自动统计金额分布（如 80% 为 USD，20% 为 EUR），输出 `currency_distribution`
2. **质量评分**：对输入文本整体打分（0-100），基于解析成功率、置信度均值、格式规范性
3. **异常检测**：若启用 `anomaly_check`，标记可能的异常值（如金额为 0、负数值、超出合理范围的值）
4. **趋势提示**：若检测到日期字段，按时间排序输出金额趋势（如"近 3 个月金额呈上升趋势"）
5. **建议输出**：根据解析结果给出后续建议（如"检测到 3 条低置信度记录，建议人工复核"）

#### 阶段五：结果输出
1. 按 `fields` 参数过滤输出字段
2. 应用 `alias` 参数重命名字段
3. 若启用 `dedupe`，去除重复金额记录
4. 若设置 `min_confidence`，过滤低于阈值的记录
5. 按 `output_format` 参数输出（JSON/CSV/表格）
6. 输出 JSON 数组，包含 `amount`、`currency`、`date`、`confidence` 及洞察信息

## 七、失败处理（Error Handling）

### 7.1 异常分类与处理策略

| 异常类型 | 捕获方式 | 处理策略 | 用户提示 |
|----------|----------|----------|----------|
| 输入为空 | 前置校验 | 直接返回错误码 `E1001` | 请提供包含金额的文本 |
| URL 超时 | `requests.Timeout` | 重试 2 次（指数退避 1s/2s/4s），仍失败则返回 `E1003` | 请检查网络或稍后重试 |
| URL 404 | `requests.HTTPError` | 直接返回 `E1003` | 请确认 URL 可公开访问 |
| 文件不存在 | `FileNotFoundError` | 直接返回 `E1004` | 请检查文件路径 |
| 编码错误 | `UnicodeDecodeError` | 尝试 GBK 解码，仍失败则返回 `E1004` | 请确认文件编码为 UTF-8/GBK |
| 单条解析失败 | 正则不匹配 | 跳过该条，记录错误，继续处理 | 在结果中标记 `parse_error: true` |
| 参数非法 | 类型检查 | 返回 `E1006` 并列出合法参数 | 请参考参数表 |
| 内存不足 | `MemoryError` | 建议使用流式处理 | 请使用流式处理或拆分文件 |
| 未知异常 | `Exception` | 记录日志，返回通用错误 | 请重试或联系支持 |

### 7.2 优雅降级流程

1. **部分失败**：单条记录解析失败不影响整体，跳过并标记
2. **URL 不可用**：若 URL 请求失败，尝试从缓存读取（若之前解析过）
3. **文件损坏**：若文件读取失败，尝试读取文件的前 1MB 作为样本
4. **依赖缺失**：若缺少依赖库，给出安装命令并重试一次

### 7.3 重试机制

- URL 请求：最多重试 2 次，指数退避（1s → 2s → 4s）
- 文件读取：最多重试 1 次，间隔 1 秒
- 解析超时：单条记录超时 5 秒则跳过，不重试

## 十、常见坑（Common Pitfalls）

### 坑 1：千分位与小数点的混淆

**问题**：`1.234` 在英文语境是 1.234，在德文语境是 1234
**解决**：默认按英文格式解析（`.` 为小数点），若需德文格式请使用 `locale` 参数

### 坑 2：括号负数的处理

**问题**：`(100)` 可能表示负数 -100，也可能表示括号注释
**解决**：默认将括号内的纯数字金额视为负数，若需改变请设置 `parentheses_negative: false`

### 坑 3：日期格式的歧义

**问题**：`01/02/2024` 可能是 1 月 2 日或 2 月 1 日
**解决**：默认按 MM/DD/YYYY 解析，可通过 `date_format` 参数指定

### 坑 4：货币符号的多义性

**问题**：`$` 可能是 USD、CAD、AUD 等
**解决**：默认将 `$` 视为 USD，可通过 `currency_map` 参数自定义

### 坑 5：中文金额单位的边界

**问题**：`1万5` 可能表示 15000 或 1.5 万
**解决**：默认将 `1万5` 解析为 15000，若需更精确请使用 `1.5万` 格式

## 异常处理

| 异常情况 | 表现 | 处理方式 |
|---|---|---|
| 输入文件不存在 | 提示路径错误并退出 | 核对路径，使用绝对路径重试 |
| 文件格式不符 | 该条跳过并计入失败明细 | 转换为受支持格式后重跑该条 |
| 权限不足 | 写入失败 | 更换输出目录或提升目录写权限 |
| 单条数据异常 | 跳过该条，继续处理其余 | 处理结束后查看失败明细定向重跑 |

失败处理原则：**单条失败不中断整批**，全部异常汇总到失败明细，支持只重跑失败项。

## 稳定性保障

- **超时控制**：单条处理设置上限，超时自动跳过并记入失败明细，避免整批卡死。
- **重试策略**：可恢复类错误（临时占用、瞬时 IO 失败）自动重试 3 次，间隔递增。
- **降级方案**：高级解析失败时自动回退到基础解析模式，保证有可用输出而非直接报错。
- **幂等性**：重复执行同一批输入结果一致，不会产生重复追加。
