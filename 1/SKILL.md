## 三、标准执行流程

### 步骤 0：输入确认与参数初始化

在开始处理前，先确认以下信息：

| 参数名 | 默认值 | 说明 | 示例 |
|--------|--------|------|------|
| `input_type` | auto | 输入类型：text / file / url / auto | `text` |
| `output_format` | json | 输出格式：json / csv / yaml / table | `json` |
| `fields` | 自动检测 | 需要提取的字段列表（逗号分隔） | `name, amount, date` |
| `delimiter` | 自动检测 | 输入分隔符（用于 CSV/日志） | `,` 或 `\|` |
| `encoding` | utf-8 | 输入文件编码 | `utf-8` / `gbk` |
| `deduplicate` | false | 是否去重 | `true` |
| `confidence_threshold` | 0.6 | 置信度门控阈值（低于此值需人工复核） | `0.8` |
| `max_input_size` | 10000 | 最大输入长度（字或行数） | `5000` |
| `timeout_seconds` | 30 | URL 抓取超时时间（秒） | `15` |
| `retry_count` | 2 | 失败重试次数 | `3` |
| `date_format` | iso8601 | 日期统一格式 | `yyyy-mm-dd` |
| `mask_sensitive` | false | 是否脱敏敏感信息 | `true` |
| `regex_pattern` | 无 | 自定义正则表达式 | `INV-\d{3}` |

### 步骤 1：收集用户输入并确认格式

1. 接收用户输入（文本、文件路径、URL）
2. 根据 `input_type` 判断输入类型（若为 auto 则自动检测）
3. 确认输出格式和字段需求
4. 若输入超过 `max_input_size`，提示用户分段处理
5. 若输入包含敏感信息且 `mask_sensitive` 为 true，先执行脱敏

### 步骤 2：按功能逻辑处理输入内容

根据用户需求选择对应处理模块：

- **原始数据解析**：识别文本中的关键字段（如合同条款中的甲方、乙方、金额）
- **文件内容识别**：读取文件内容，按格式解析（CSV/JSON/XML/YAML）
- **URL 内容抓取**：访问 URL，提取正文关键信息
- **结构化输出生成**：按用户指定的字段结构重组数据
- **批量处理与格式自定义**：处理多条记录，支持自定义分隔符和字段映射
- **数据清洗与标准化**：去重、统一日期格式、修正编码
- **字段映射与重命名**：将源字段名映射为目标字段名
- **智能洞察与质量评分**：识别数据模式、异常值，给出质量评分
- **正则表达式提取**：按用户提供的正则模式提取匹配内容
- **数据脱敏处理**：识别并替换敏感信息（手机号、身份证、邮箱等）
- **时间序列标准化**：将多种时间格式统一为指定时区与格式

### 步骤 3：生成结果并校验完整性

1. 生成结构化结果
2. 校验结果完整性（字段是否齐全、格式是否正确）
3. 计算置信度（基于数据完整度、格式规范度、来源可靠性）
4. 若置信度低于 `confidence_threshold`，标注"需人工复核"
5. 若启用 `quality_score`，输出质量评分与改进建议

### 步骤 4：输出结果

输出结构化文本结果，附处理说明和置信度标注。

## 四、高级用法

### 4.1 多级嵌套结构转换

**场景**：将扁平结构转为嵌套结构（或反向展开）。

**示例**：
- 输入：扁平 JSON 数组 `[{"id": 1, "parent_id": null, "name": "A"}, {"id": 2, "parent_id": 1, "name": "B"}]`
- 输出：树形结构 `{"id": 1, "name": "A", "children": [{"id": 2, "name": "B"}]}`

**参数**：
- `nest_by`：指定父子关系字段（如 `parent_id`）
- `nest_key`：指定子节点字段名（默认 `children`）

### 4.2 编码与乱码修复

**场景**：用户打开 CSV 文件发现中文乱码。

**处理流程**：
1. 检测文件编码（UTF-8 / GBK / ISO-8859-1）
2. 尝试自动转换编码
3. 若转换失败，提示用户指定编码格式

**示例**：
- 输入：GBK 编码的 CSV 文件
- 输出：UTF-8 编码的 CSV 文件（内容正常显示）

### 4.3 自定义字段映射规则

**场景**：用户需要将多个源字段合并为一个目标字段，或进行条件映射。

**示例**：
- 输入：`{"first_name": "张", "last_name": "三"}`
- 映射规则：`full_name = first_name + last_name`
- 输出：`{"full_name": "张三"}`

**参数**：
- `mapping_rules`：JSON 格式的映射规则，支持 `+` 拼接、条件判断

### 4.4 批量处理与模板复用

**场景**：用户需要定期处理相同格式的数据。

**处理流程**：
1. 保存处理模板（字段映射、清洗规则、输出格式）
2. 下次处理时直接调用模板
3. 支持模板参数化（如日期范围、文件路径）

**示例**：
- 模板名称：`daily_log_cleanup`
- 模板内容：`{"input_type": "file", "output_format": "json", "deduplicate": true, "fields": ["timestamp", "level", "message"]}`

### 4.5 正则表达式提取

**场景**：用户需要提取特定模式的数据（如发票编号、IP 地址、邮箱）。

**示例**：
- 输入：`"订单号 INV-2024-001 和 INV-2024-002 已发货"`
- 正则：`INV-\d{3}-\d{3}`
- 输出：`["INV-2024-001", "INV-2024-002"]`

**参数**：
- `regex_pattern`：用户提供的正则表达式
- `regex_flags`：正则标志（如 `i` 忽略大小写）

### 4.6 数据脱敏处理

**场景**：用户需要处理包含敏感信息的数据（如手机号、身份证号）。

**示例**：
- 输入：`{"name": "张三", "phone": "13812345678", "email": "zhangsan@example.com"}`
- 输出：`{"name": "张三", "phone": "138****5678", "email": "z***@example.com"}`

**参数**：
- `mask_fields`：需要脱敏的字段列表
- `mask_style`：脱敏样式（`partial` 部分隐藏 / `full` 完全隐藏）

### 4.7 时间序列标准化

**场景**：用户提供不同时区、不同格式的时间戳，需要统一。

**示例**：
- 输入：`["2024-01-15 10:30:00 UTC", "2024/01/15 18:30:00 +08:00", "Jan 15, 2024 18:30:00 CST"]`
- 输出：`["2024-01-15 18:30:00+08:00", "2024-01-15 18:30:00+08:00", "2024-01-15 18:30:00+08:00"]`

**参数**：
- `target_timezone`：目标时区（默认 `UTC+8`）
- `target_format`：目标格式（默认 `iso8601`）

### 4.8 多格式混合输入解析

**场景**：用户输入中包含多种格式（如文本+JSON 片段+表格）。

**处理流程**：
1. 自动识别输入中的格式边界
2. 分别解析各格式片段
3. 合并为统一结构化输出

**示例**：
- 输入：`"以下是订单信息：{"order_id": "A001", "amount": 100}，请处理"`
- 输出：`{"order_id": "A001", "amount": 100, "source": "mixed_input"}`
