# 合同条款审查 Skill 文档

## 一、能力边界速查卡

本 Skill 用于辅助合同文本的结构化审查，帮助使用者快速定位条款中的义务、风险与合规要点。以下内容为能力边界的一页纸速查，请在使用前阅读。

### 能做什么

| 能力项 | 说明 | 示例 |
|--------|------|------|
| 条款解析 | 将合同文本拆分为独立条款，统计条款总数并编号 | 输入一份 20 条的采购合同，输出 1-20 条逐条解析 |
| 合规审查 | 对照常见法律法规（如《民法典》《劳动法》等）识别条款合规性 | 识别出违约金比例可能超出法定上限的条款 |
| 风险标注 | 对高风险条款进行标记，并说明风险原因 | 标注"无限责任条款"为高风险，说明其可能导致的责任外溢 |
| 合同审查 | 输出结构化审查报告，包含条款清单、风险清单、建议清单 | 生成一份包含 3 个部分的 Markdown 报告 |
| 条款比对 | 对同一合同的不同版本进行条款级差异比对 | 对比 V1 与 V2 版本，列出新增、删除、修改的条款 |

### 不能做什么

| 限制项 | 说明 |
|--------|------|
| 不支持纯英文文本 | 仅支持中文（含中英混合），纯英文输入将返回错误码 E1001 |
| 不支持超长文本 | 单次输入上限 30,000 字，超出需分段处理，否则返回错误码 E1002 |
| 不提供法律意见 | 本 Skill 输出为辅助参考，不构成正式法律意见，重大决策请咨询执业律师 |
| 不保证条款完整性 | 合同文本中若存在缺失页码、乱码、表格转换错误，可能影响解析准确性 |
| 不执行自动签署 | 本 Skill 仅做文本分析与报告输出，不涉及任何电子签署或合同生效操作 |

### 适用对象

- 企业法务人员：快速初审合同，定位重点审查区域
- 合同管理员：批量处理标准合同，识别版本差异
- 业务负责人：理解合同中的义务与风险，辅助商务谈判
- 法律学习者：通过条款解析学习合同结构与常见风险点

## 三、标准执行流程

### 前置条件

在执行审查前，请确认以下条件已满足：

| 条件 | 要求 | 检查方法 |
|------|------|----------|
| 文本语言 | 中文或中英混合 | 目测文本中中文字符占比 > 70% |
| 文本长度 | ≤ 30,000 字 | 使用字数统计工具确认 |
| 文本格式 | 纯文本或可转换的文本格式 | PDF/图片需先转换为文本 |
| 文本完整性 | 无缺页、无乱码 | 快速浏览首尾段落确认 |

若条件不满足，请先处理文本（如分段、转换格式），再执行审查。

### 执行步骤

**步骤 1：接收合同文本**

接收用户提供的合同文本。文本可通过以下方式提供：
- 直接粘贴到对话中
- 上传文本文件内容（需为纯文本格式）

**步骤 2：文本预处理**

对接收的文本进行预处理：
1. 去除多余空行、空格、页眉页脚
2. 识别合同标题与正文分界
3. 按条款编号（如"第一条""1.1""第 1 条"等）进行条款切分
4. 统计条款总数

**步骤 3：逐条解析与类型标注**

对每个条款进行解析，标注以下信息：

| 标注字段 | 说明 | 示例 |
|----------|------|------|
| 条款编号 | 原始文本中的条款编号 | 第 5 条 |
| 条款主题 | 概括条款核心内容 | 违约责任 |
| 条款类型 | 义务型 / 权利型 / 程序型 / 定义型 | 义务型 |
| 义务主体 | 承担义务的一方（如甲方/乙方） | 乙方 |
| 义务内容摘要 | 简述义务或权利的具体内容 | 乙方需在 30 日内交付货物 |
| 风险等级 | 高 / 中 / 低 / 无 | 中 |

**步骤 4：风险识别与标注**

基于以下风险信号词表，对条款进行风险扫描：

| 风险信号词 | 潜在风险 | 建议关注点 |
|-----------|----------|-----------|
| 无限责任 / 连带责任 | 责任范围过大 | 是否有限额约定？ |
| 最终解释权 | 解释权归属不明确 | 是否违反公平原则？ |
| 不可抗力 | 免责范围模糊 | 是否列举具体情形？ |
| 违约金 | 金额是否合理 | 是否超过法定上限（如 30%）？ |
| 单方变更 | 合同稳定性差 | 是否有对等权利？ |
| 保密义务 | 保密范围与期限 | 是否有例外情形？ |
| 自动续约 | 合同期限不明确 | 是否有退出机制？ |
| 管辖法院 | 争议解决地点 | 是否对己方不利？ |

**步骤 5：合规建议生成**

针对识别出的风险，生成合规建议。建议需包含以下要素：

| 建议要素 | 说明 | 示例 |
|----------|------|------|
| 风险描述 | 简述风险内容 | 违约金比例可能过高 |
| 法规依据 | 参考的法律法规条文 | 《民法典》第 585 条 |
| 修改建议 | 具体的修改方向 | 建议将违约金比例调整为不超过合同总额的 30% |
| 优先级 | 高 / 中 / 低 | 高 |

### 输出规范

审查报告输出为 Markdown 格式，包含以下三个部分：

**第一部分：条款总览**
- 条款总数
- 条款类型分布统计
- 义务主体分布统计

**第二部分：风险清单**
- 按风险等级排序（高 → 中 → 低）
- 每条风险包含：条款编号、风险描述、风险等级、建议关注点

**第三部分：合规建议**
- 按优先级排序（高 → 中 → 低）
- 每条建议包含：风险描述、法规依据、修改建议、优先级

## 四、置信度门控

在信息不足或不确定的情况下，本 Skill 将使用占位符机制，不进行任何编造或猜测。

### 占位符规则

| 场景 | 占位符格式 | 示例 |
|------|-----------|------|
| 条款内容不完整 | `[需核实:条款内容]` | 第 3 条内容缺失，输出 `[需核实:条款内容]` |
| 义务主体不明确 | `[需核实:义务主体]` | 条款未明确谁承担义务，输出 `[需核实:义务主体]` |
| 法规依据不确定 | `[需核实:法规依据]` | 无法确认具体法规条文，输出 `[需核实:法规依据]` |
| 风险等级不确定 | `[需核实:风险等级]` | 风险程度难以判断，输出 `[需核实:风险等级]` |

### 门控触发条件

以下情况将触发置信度门控：

1. 条款文本存在明显缺失（如"第 X 条"后无内容）
2. 条款表述模糊，无法确定义务主体或义务内容
3. 涉及特定行业法规，但文本未提供足够上下文
4. 条款比对时，版本差异描述不完整

### 门控处理流程

1. 识别信息不足的位置
2. 在输出中插入 `[需核实:字段]` 占位符
3. 在报告末尾添加"待核实事项清单"，列出所有占位符位置及原因
4. 提示用户补充相关信息后可重新生成报告

## 六、FAQ 与反模式

### 常见坑位

**坑位 1：忽略置信度门控**

- **错误做法**：在信息不足时，直接猜测条款内容或风险等级
- **正确做法**：使用 `[需核实:字段]` 占位符，并在报告末尾列出待核实事项
- **反模式示例**：条款内容缺失时，编造"乙方需在 15 日内付款"→ 应输出 `[需核实:条款内容]`

**坑位 2：过度依赖信号词**

- **错误做法**：仅凭信号词（如"违约金"）就判定为高风险，不分析具体语境
- **正确做法**：结合条款上下文、金额比例、双方权利义务平衡度综合判断
- **反模式示例**：看到"违约金"就标高风险 → 应分析违约金比例是否合理

**坑位 3：忽略义务主体识别**

- **错误做法**：只关注风险内容，不明确义务由谁承担
- **正确做法**：每条义务型条款必须标注义务主体（甲方/乙方/第三方）
- **反模式示例**：输出"需在 30 日内交付"→ 应输出"乙方需在 30 日内交付"

**坑位 4：合规建议无依据**

- **错误做法**：给出修改建议但不说明法规依据
- **正确做法**：每条建议必须附带具体的法规条文（如《民法典》第 X 条）
- **反模式示例**："建议降低违约金"→ 应补充"依据《民法典》第 585 条，违约金过高可请求适当减少"

**坑位 5：条款比对时混淆版本**

- **错误做法**：比对时未明确标注哪个是 V1、哪个是 V2
- **正确做法**：在输出中明确标注"V1 版本"与"V2 版本"，差异描述以 V2 为基准
- **反模式示例**："第 3 条被修改了"→ 应明确"V2 版本第 3 条相比 V1 版本，违约金比例从 20% 调整为 30%"

### 反模式对照表

| 反模式 | 问题 | 正确替代 |
|--------|------|----------|
| 猜测条款内容 | 信息不足时编造 | 使用 `[需核实:字段]` 占位符 |
| 一刀切风险判断 | 不分析语境 | 结合上下文综合评估 |
| 忽略义务主体 | 责任归属不清 | 明确标注义务主体 |
| 建议无法规依据 | 缺乏说服力 | 附带具体法规条文 |
| 版本混淆 | 比对结果不可用 | 明确标注版本号 |

条款解析：本合同由甲乙双方于 2024 年 1 月 1 日签订。第一条：甲方应向乙方支付货款 10 万元。第二条：乙方应在收到货款后 15 日内交付货物。
