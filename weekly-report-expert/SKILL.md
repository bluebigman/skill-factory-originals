### 执行步骤（分步编号）

#### 步骤 1：准备输入

1. 将待处理的日志文件放入当前工作目录。
2. 确认文件命名规范一致（建议格式：`{仓库名}_{周标识}.log`）。
3. 若为直接粘贴文本，请确保包含完整的提交记录块。

#### 步骤 2：试运行（单样本验证）

1. 取第一条提交记录作为样本。
2. 执行解析，核对输出字段是否完整（哈希、作者、日期、消息）。
3. 检查日期格式是否统一（建议 ISO 8601：`YYYY-MM-DD`）。
4. 若样本解析失败，检查输入格式是否符合 `git log` 标准输出。

#### 步骤 3：批量执行

1. 对全部输入数据执行解析。
2. 按周（周一至周日）对提交记录分组。
3. 按作者二次分组（可选，根据用户需求）。
4. 对每条提交消息进行类型标注（见下表）。

**提交类型标注规则：**

| 类型 | 关键词匹配（英文） | 关键词匹配（中文） | 优先级 |
|------|-------------------|-------------------|--------|
| 功能新增 | feat, feature, add | 新增, 添加, 实现 | 1 |
| 缺陷修复 | fix, bugfix, patch | 修复, 解决, 修补 | 2 |
| 重构优化 | refactor, optimize | 重构, 优化, 改进 | 3 |
| 文档更新 | docs, doc | 文档, 注释, README | 4 |
| 测试相关 | test, spec | 测试, 用例 | 5 |
| 构建发布 | build, release, ci | 构建, 发布, 部署 | 6 |
| 其他 | 未匹配以上类型 | 未匹配以上类型 | 7 |

#### 步骤 4：生成结果

1. 将分组后的数据整理为周报格式（见输出规范）。
2. 对缺失字段或无法归类的条目标注 `[需核实:字段名]`。
3. 输出周报文本。

#### 步骤 5：自查与确认

1. 检查字段完整性：哈希、作者、日期、消息是否全部包含。
2. 检查格式正确性：日期格式、类型标注是否符合规范。
3. 检查置信度标注：所有不确定项是否已标注。
4. 如有疑问，向用户二次确认后再输出最终版本。
