## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 | 检查方法 |
|------|------|----------|
| 输入格式 | 纯文本或 Markdown | 确认无二进制内容 |
| 编码 | UTF-8 | 检查文件头无 BOM |
| 长度 | ≤ 5000 字 | 用 `wc -c` 或编辑器统计 |
| 命名 | 输入文件命名含日期或项目名 | 如 `2024-01-15_项目A_任务.md` |

### 3.2 执行步骤

1. **接收输入**：获取用户提供的文本内容或文件路径。
2. **预处理**：去除空行、统一换行符（`\n`），识别列表项（`-`、`*`、`1.` 等）。
3. **状态识别**：按以下规则分类：
   - 含 `[x]`、`已完成`、`done` → 已完成列
   - 含 `进行中`、`in progress`、`doing` → 进行中列
   - 含 `!`、`紧急`、`urgent` → 待办列并加 `!` 标记
   - 其余 → 待办列
4. **生成看板**：按以下模板输出：

```markdown
## 看板：{项目名或日期}

### 📋 待办
- [ ] 任务1
- [ ] 任务2（! 紧急）

### 🔄 进行中
- [ ] 任务3

### ✅ 已完成
- [x] 任务4
```

5. **输出规范**：
   - 列顺序固定为：待办 → 进行中 → 已完成
   - 每列前加 emoji 标识（📋/🔄/✅）
   - 任务项保留原始描述，仅添加状态标记
   - 输出末尾附注：`转换完成，共 N 项任务`

### 3.3 输出示例

**输入：**
```
- 写周报
- 进行中：开发登录页
- [x] 修复导航栏bug
- 紧急！处理服务器告警
```

**输出：**
```markdown
## 看板：未命名项目

### 📋 待办
- [ ] 写周报
- [ ] 处理服务器告警（! 紧急）

### 🔄 进行中
- [ ] 开发登录页

### ✅ 已完成
- [x] 修复导航栏bug

---
转换完成，共 4 项任务
```

## 四、置信度门控

当输入信息不足以确定任务状态或分类时，使用以下占位符，不进行猜测：

| 场景 | 占位符 | 示例 |
|------|--------|------|
| 状态不明确 | `[需核实:状态]` | `- [ ] 跟进客户（[需核实:状态]）` |
| 优先级不明确 | `[需核实:优先级]` | `- [ ] 准备演示（[需核实:优先级]）` |
| 归属列不明确 | `[需核实:分类]` | `- [ ] 整理资料（[需核实:分类]）` |

**规则**：
- 占位符必须保留在输出中，不得删除或替换
- 输出末尾追加提示：`注意：N 项任务状态待核实，请人工确认`
- 若超过 30% 的任务需核实，建议用户先手动标注状态再转换
