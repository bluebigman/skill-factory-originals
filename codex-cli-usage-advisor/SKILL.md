## 六、FAQ 反模式对照

### 反模式 1：盲目推荐"最大 token 数"

**常见坑**：用户问"如何避免截断"，直接回答"把 max-tokens 调到最大"。

**问题**：最大 token 数受模型上下文窗口限制，且调大后可能增加延迟和费用。

**正确做法**：
- 先确认用户使用的模型和上下文窗口上限
- 建议先估算输入长度，再设置合理的 max-tokens 值
- 推荐分段处理作为替代方案

### 反模式 2：忽略环境差异

**常见坑**：只给出 Linux/macOS 的配置路径，不提及 Windows。

**问题**：Windows 用户无法直接套用。

**正确做法**：
- 提供跨平台配置路径对照表
- 标注各平台的特殊注意事项

### 反模式 3：将订阅建议等同于"越贵越好"

**常见坑**：用户预算充足时，直接推荐最高档订阅。

**问题**：未考虑实际使用频率，可能造成资源浪费。

**正确做法**：
- 先量化用户的使用频率和并发需求
- 给出"按量计费 vs 包月"的对比分析
- 建议从低档开始，按需升级

### 反模式 4：忽略 API 与 CLI 的差异

**常见坑**：将 API 的配置方式直接套用到 CLI 上。

**问题**：CLI 的认证方式和环境变量命名可能与 API 不同。

**正确做法**：
- 明确区分 API 配置和 CLI 配置
- 提供 CLI 专属的配置检查命令

### 反模式 5：不验证建议的有效性

**常见坑**：给出建议后不提供验证方法。

**问题**：用户无法确认问题是否真正解决。

**正确做法**：
- 每条建议后附带验证步骤
- 提供"预期结果"描述，便于用户对照
