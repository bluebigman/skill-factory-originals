本 Skill 聚焦于中文互联网内容场景下的标题党识别与处理。它不是一个通用文本分析器，也不是法律合规软件。

### 1.1 能做什么

| 能力项 | 说明 | 输出形式 |
|--------|------|----------|
| 标题党识别评分 | 基于预设规则与模型，对标题进行 0-100 分评分，分数越高代表标题党倾向越明显 | JSON 字段 `score` |
| 分类标注 | 将标题归入「夸张夸大」「悬念诱导」「绝对化用语」「恐吓胁迫」「利益承诺」「正常标题」等类别 | JSON 字段 `category` |
| 批量整理 | 支持一次处理多个标题，输入为 JSON 数组或纯文本列表 | 输出 JSON 数组 |
| 改写生成 | 针对被判定为标题党的标题，生成 3-5 个合规、保留吸引力的替代版本 | JSON 字段 `rewrites` |
| 合规校验 | 检查标题是否违反《广告法》禁用词清单（如"最""第一""国家级"等） | JSON 字段 `compliance` |
| 效果预估 | 基于历史数据模型，预估标题的点击率区间（低/中/高） | JSON 字段 `ctr_estimate` |
| 去重合并 | 对批量输入的标题进行相似度去重，合并重复项 | 输出去重后的 JSON 数组 |

## 三、标准处理流程

### 3.1 前置条件

- 输入格式：单个标题为字符串，批量标题为 JSON 数组或换行分隔的纯文本。
- 编码要求：UTF-8 编码。
- 最大输入：单次处理不超过 10,000 条标题。超过时自动启用流式分块处理，每块 1,000 条，内存占用稳定在 200MB 以内。

### 3.2 执行步骤

**步骤 1：输入解析**

- 检测输入格式（JSON / 纯文本 / 混合）。
- 若格式无法解析，返回错误码 `E1001`。

**步骤 2：dry-run 预览（推荐）**

- 使用 `--dry-run` 参数时，仅输出将写入文件的预览内容，不实际写入。
- 预览内容包括：处理条数、每条标题的评分与分类、将被改写或删除的条目列表。

**步骤 3：核心处理**

- 对每条标题执行以下子步骤：
  1. 文本清洗（去除首尾空格、全角半角统一）。
  2. 标题党评分（基于规则引擎，规则库包含 120+ 条模式）。
  3. 分类标注（基于评分结果与关键词匹配）。
  4. 合规校验（对照禁用词库，词库版本号随输出返回）。
  5. 若评分 > 70 分，触发改写生成。
  6. 若启用去重，进行相似度计算（SimHash + 编辑距离）。

**步骤 4：输出生成**

- 默认输出 JSON 格式。
- 使用 `--markdown` 参数时，额外生成 Markdown 格式报告。
- 使用 `--verbose` 参数时，每条标题附带评分依据（命中的规则编号与说明）。

**步骤 5：写入文件（可选）**

- 使用 `--output` 参数指定输出文件路径。
- 正式写入前，若未使用 `--dry-run`，系统会二次确认。

## 六、FAQ 与反模式对照

### 6.1 常见坑

**坑 1：把合规校验当法律意见**

- 反模式：用户问"这个标题合法吗？"，直接回答"合法"。
- 正确做法：输出"未检测到明显违规词，但最终合法性需由专业法律人士确认"。

**坑 2：忽略人工复核**

- 反模式：直接采用 AI 生成的改写标题，不做任何修改。
- 正确做法：将改写结果作为候选，人工选择并微调，确保符合品牌调性。

**坑 3：处理超大批量时内存溢出**

- 反模式：一次性加载 50,000 条标题到内存。
- 正确做法：使用流式分块处理，每块 1,000 条。

**坑 4：对"高级标题党"误判**

- 反模式：认为评分低于 30 分就一定是正常标题。
- 正确做法：结合 `category` 字段与人工判断，反讽、双关类标题需人工识别。

**坑 5：忽略 `--dry-run` 直接写入**

- 反模式：直接执行写入操作，导致覆盖原有文件。
- 正确做法：先执行 `--dry-run` 预览，确认无误后再正式写入。
