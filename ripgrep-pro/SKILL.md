# ripgrep 技能手册

## 一、能力边界（一页纸速查卡）

### 1.1 工具定位

ripgrep（命令名 `rg`）是一款面向开发者的命令行文本搜索工具，专为在大型代码库中快速定位正则模式而设计。它内置了 `.gitignore` 规则识别能力，默认跳过被版本控制忽略的文件，从而显著减少无效扫描。

### 1.2 能做与不能做

| 维度 | 能做 ✅ | 不能做 ❌ |
|------|---------|-----------|
| 搜索范围 | 递归扫描指定目录树 | 无法搜索未挂载的远程文件系统 |
| 模式匹配 | 支持完整正则语法（PCRE2 需 `-P` 参数） | 不支持模糊匹配或自然语言查询 |
| 文件过滤 | 按扩展名、通配符、文件类型过滤 | 无法按文件内容编码自动识别（需手动指定） |
| 输出控制 | 支持 JSON、XML、自定义格式输出 | 不支持直接生成报告文件（需重定向） |
| 性能优化 | 自动并行处理多目录、跳过二进制文件 | 无法在搜索过程中动态调整线程数 |
| 上下文显示 | 支持前后行上下文（`-A`/`-B`/`-C`） | 不支持跨文件上下文关联 |

### 1.3 适用对象

- **日常使用者**：需要快速定位代码中的特定模式、TODO 标记、函数定义
- **代码审查者**：需要跨文件追踪变量引用、API 调用点
- **运维排查者**：需要在日志目录中检索错误模式
- **CI/CD 流水线**：需要将搜索集成到自动化脚本中

## 三、标准流程

### 3.1 前置条件

1. 确认 ripgrep 已安装：终端执行 `rg --version`，若未安装请先安装
2. 确认搜索目标目录存在且可读
3. 明确搜索模式（正则表达式）和过滤条件

### 3.2 执行步骤

**第一步：确定搜索范围**

```bash
# 搜索当前目录（推荐）
rg "pattern" .

# 搜索指定目录
rg "pattern" /path/to/dir

# 搜索多个目录（自动并行）
rg "pattern" dir1 dir2
```

**第二步：应用过滤条件**

```bash
# 按文件类型过滤（最快）
rg -t py "pattern" .

# 按扩展名过滤
rg "pattern" . -g '*.js'

# 排除目录
rg "pattern" . -g '!node_modules' -g '!vendor'

# 限制文件大小
rg "pattern" . --max-filesize 10M
```

**第三步：调整输出格式**

```bash
# 仅列出文件名（不显示匹配行）
rg -l "pattern" .

# 显示匹配计数
rg -c "pattern" .

# 显示上下文（前后各2行）
rg -C 2 "pattern" .

# JSON 输出（适合脚本处理）
rg --json "pattern" .
```

**第四步：验证结果**

```bash
# 检查退出码（0=有匹配，1=无匹配，2=错误）
echo $?
```

### 3.3 输出规范

- 默认输出格式：`文件名:行号:匹配内容`
- 使用 `-l` 时仅输出文件名列表
- 使用 `-c` 时输出 `文件名:匹配次数`
- 使用 `--json` 时输出结构化 JSON 流

## 六、进阶用法

### 6.1 参数化模板

**模板一：代码审计搜索**

```bash
rg -t py -C 3 "def (get|set|post|put|delete)_" . -g '!test*' -g '!migrations'
```

**模板二：安全敏感信息扫描**

```bash
rg -i "(api[_-]?key|secret|password|token)" . -g '!*.lock' -g '!package-lock.json' --max-filesize 5M
```

**模板三：日志错误模式提取**

```bash
rg -n "ERROR|FATAL|Exception" /var/log/app/ -t log -C 1 --sort path
```

### 6.2 高级正则技巧

| 技巧 | 示例 | 说明 |
|------|------|------|
| 非贪婪匹配 | `rg "<[^>]+>" file.html` | 匹配最短的 HTML 标签 |
| 前瞻断言 | `rg -P "foo(?=bar)" file.txt` | 匹配后面跟着 bar 的 foo |
| 后顾断言 | `rg -P "(?<=foo)bar" file.txt` | 匹配前面是 foo 的 bar |
| 反向引用 | `rg -P "(\w+)\s+\1" file.txt` | 匹配重复单词 |
| 多行模式 | `rg -U "start.*?end" file.txt` | 跨行匹配（需 `-U` 参数） |

### 6.3 性能优化指南

| 优化策略 | 预期效果 | 实施方法 |
|----------|----------|----------|
| 缩小目录范围 | 减少扫描文件数 | 指定具体子目录而非根目录 |
| 使用文件类型过滤 | 跳过无关文件 | `-t py` 比 `-g '*.py'` 更快 |
| 排除大型目录 | 避免无谓扫描 | `-g '!node_modules' -g '!vendor'` |
| 限制文件大小 | 跳过超大文件 | `--max-filesize 10M` |
| 并行多目录 | 利用多核 CPU | `rg pattern dir1 dir2` 自动并行 |
| 使用简单正则 | 减少回溯计算 | 避免嵌套量词和复杂分组 |

### 6.4 智能洞察

**场景一：追踪 API 变更影响**

```bash
rg -l "old_api_function" . -t js | xargs -I {} sed -i 's/old_api_function/new_api_function/g' {}
```

**场景二：统计技术债务**

```bash
rg -c "TODO|FIXME|HACK" . -t py -g '!test*' | awk -F: '{sum += $2} END {print "Total tech debt markers:", sum}'
```

**场景三：查找未使用的导入**

```bash
rg -l "^import " . -t py | while read f; do
  imports=$(rg "^import " "$f" | sed 's/import //' | cut -d' ' -f1)
  for imp in $imports; do
    count=$(rg -c "\b$imp\b" "$f")
    if [ "$count" -eq 1 ]; then
      echo "Unused import: $imp in $f"
    fi
  done
done
```
