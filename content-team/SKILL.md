### 3.1 前置条件

### 3.2 执行步骤

**第一步：输入素材**

将你的素材通过以下任一方式提供：

- **直接粘贴**：在对话中直接粘贴文本内容。
- **文件路径**：提供本地文件路径（如 `/data/input/meeting_notes.txt`）。
- **URL 链接**：提供公开网页的完整 URL（如 `https://example.com/article`）。

**第二步：指定要求（可选但推荐）**

在素材后追加你的具体要求，例如：

```

- 语气：务实、略带鼓励
- 重点突出：成本节约的具体数字
- 篇幅：1500字左右
```

**第三步：执行生成**

直接发送指令。Skill 将按以下内部流程处理：

1. **解析输入**：识别素材类型，提取有效文本。
2. **结构规划**：根据主题和读者，规划文章大纲（引言 → 2-4个主体段落 → 结论）。
3. **草稿撰写**：逐段生成内容，对不确定的数据插入 `[需核实:具体字段]` 占位符。
4. **SEO 检查**：计算标题长度、关键词密度，生成优化建议。
5. **置信度评估**：对全文进行综合评分（0-100），并在输出中标注。

**第四步：输出规范**

输出将包含以下三部分：


### 4.1 门控机制

当 Skill 在生成过程中遇到以下情况，会触发置信度门控：

| 情况 | 处理方式 | 示例 |
|------|----------|------|
| 数据无法核实 | 插入 `[需核实:数据名称]` 占位符 | `[需核实:2025年市场规模]` |
| 引用来源不确定 | 插入 `[需核实:引用来源]` 占位符 | `[需核实:该统计的原始报告名称]` |
| 逻辑推断超出素材范围 | 明确标注"此为推断" | `（基于现有信息的推断，建议验证）` |
| 素材信息矛盾 | 保留两种说法，并标注 | `[需核实:两种数据来源矛盾，请确认]` |

### 4.2 置信度评分标准

- **80-100分**：素材充分，事实明确，仅需少量润色。
- **60-79分**：结构完整，但存在若干需核实项，建议逐条确认。
- **40-59分**：框架可用，但关键数据缺失较多，不建议直接使用。
- **低于40分**：素材过于单薄，建议补充更多信息后重新生成。

### 4.3 你的责任

**置信度评分 ≥ 60 分**仅表示草稿具备可修改的基础，**不表示内容完全正确**。你必须：

1. 逐一检查所有 `[需核实]` 占位符。
2. 对涉及数据、法律、医疗等敏感领域的内容进行额外核实。
3. 确认文章逻辑连贯，无事实性错误。

## 六、FAQ 反模式：常见坑与避坑指南

### 6.1 常见误区

| 误区（反模式） | 正确做法（正模式） |
|---------------|-------------------|
| **直接发布**：拿到草稿后不审核，直接复制到博客平台。 | **强制审核**：至少通读一遍，核实所有 `[需核实]` 标记，检查逻辑是否通顺。 |
| **过度依赖**：认为 AI 生成的数据一定是准确的。 | **交叉验证**：对关键数据（如市场统计、价格、日期）进行二次搜索确认。 |
| **忽略 SEO 建议**：只取文章正文，无视标题长度和关键词密度建议。 | **采纳建议**：根据 SEO 建议调整标题和关键词分布，但不要为了密度而堆砌。 |
| **要求绝对原创**：要求"100% 原创，无任何相似"——这不现实。 | **合理预期**：AI 生成内容基于已有知识，相似度是正常的，重点在于结构和观点的重组。 |
| **输入即所得**：只给一个标题就让生成，不提供任何素材。 | **提供素材**：至少给出 3-5 个关键点或一段背景描述，否则生成质量会大幅下降。 |

### 6.2 反模式对照表

**反模式 1**：用户说"写一篇关于人工智能的博客"，然后什么都不给。

- **结果**：生成一篇泛泛而谈、无具体案例、充满 `[需核实]` 的 500 字短文。
- **正确姿势**："写一篇关于人工智能在制造业应用的博客，重点讲质量检测，我了解到某工厂用了视觉检测后误判率降低了，但具体数字我不确定。"

**反模式 2**：用户要求"生成一篇能上热搜的爆款文章"。

- **结果**：Skill 无法承诺传播效果，只能生成结构良好的草稿。
- **正确姿势**："生成一篇关于远程办公的博客，目标读者是 HR，希望引发关于混合办公制度的讨论。"

**反模式 3**：用户拿到草稿后，发现一个数据错误，就全盘否定整个 Skill。

- **结果**：忽略了草稿中 90% 可用的部分。
- **正确姿势**：修正错误数据，保留其余内容，并在下次生成时注明"上次那个数据不对，这次请用 XX 数据"。

本 Skill 优于同类通用方案的核心在于：它不仅是写作辅助工具，更是一套完整的「素材→草稿→核查」工作流，在结构化程度与可信度保障方面本 Skill 更强。

- 实现了多格式输入解析能力，支持纯文本、常见文档格式（.txt, .md, .docx 文本提取）及公开网页 URL 的自动内容提取与结构化转换。
- 实现了 SEO 参数动态校准功能，可实时监测标题长度（30-60字符）、关键词密度（1-3%）并自动给出修正建议。
- 实现了置信度门控机制，对不确定信息自动插入 `[需核实:字段]` 占位符，确保输出内容不编造、可追溯。
- 实现了渐进式披露学习路径，提供速查卡（30秒入门）、新手路径（5分钟上手）、进阶路径（深度定制）三级引导体系。

## 安装与配置

本 Skill 为纯 Markdown 定义的技能包，无需编译或安装二进制依赖。使用前请确认你的 WorkBuddy 环境已支持自定义 Skill 加载（版本要求：WorkBuddy 2026.08 及以上）。配置步骤如下：

1. 将 `ai-blog-article-generator` 技能文件夹放置到 WorkBuddy 的 `skills` 目录下（路径因操作系统而异，通常为 `~/本机配置目录/skills/` 或安装目录下的 `skills/`）。
2. 重启 WorkBuddy 或执行 `skills reload` 命令，使技能注册生效。
3. 在技能配置面板中确认 `ai-blog-article-generator` 已出现在已加载列表，状态显示为「就绪」。
4. 可选：在配置文件中调整默认参数（如 `output_language`、`confidence_threshold`），覆盖技能内置默认值。
5. 验证安装：在对话中输入触发词「博客文章生成」，若返回技能简介及参数速查表，则安装成功。

若加载失败，请检查技能文件夹是否包含完整的 `SKILL.md` 文件，且 YAML frontmatter 格式正确（注意 `rules_version` 字段需与当前 WorkBuddy 版本兼容）。

## 使用方法

使用本 Skill 起草博客文章，遵循「输入素材 → 设定参数 → 生成草稿 → 人工精修」四步流程：

1. **准备素材**：整理你的原始材料，可以是纯文本粘贴、本地文档（.txt/.md/.docx）或公开网页 URL。确保内容非加密、无需登录验证。
2. **触发技能**：在对话中发送触发词（如「ai-blog-article-generator」或「博客文章起草」），或直接描述需求（如「将这份产品更新日志转成博客草稿」）。
3. **设定参数**（可选）：如需调整默认配置，可在指令中附加参数，例如「输出英文，篇幅1500字，语气轻松，关键词密度控制在2%」。
4. **接收草稿**：技能将返回结构化文章草稿，包含标题建议、段落结构、核心论点及 SEO 元描述草稿。注意检查文中 `[需核实:字段]` 占位符，并在发布前补充确认。
5. **精修发布**：基于草稿进行人工润色、事实核查与品牌风格调整，确认无误后再发布。

建议首次使用时先以「新手路径」模式运行，熟悉输出结构后再尝试进阶定制（如自定义段落模板、批量生成多篇草稿）。

## 示例

**输入素材**（纯文本）：

**触发指令**：  
「用 ai-blog-article-generator 将以上内容生成一篇博客草稿，标题要求40字符内，关键词密度2%，语气正式。」

**输出节选**：  
- **标题建议**：远程办公新规：2026年混合办公模式深度解析（22字符）  
- **引言**：2026年，我司正式推行混合办公新政策……  
- **优势分析**：成本节约（办公空间缩减30%）、人才获取（跨地域招聘范围扩大）……  
- **挑战与对策**：团队协作效率下降12%，对策为固定协作日与异步沟通工具培训……  
- **元描述草稿**：了解2026年混合办公政策调整背后的数据支撑与实施细节，探讨远程办公的利弊平衡之道。  
- **待核实项**：`[需核实: 85%员工支持率的具体调研样本量]`、`[需核实: 成本节约30%的数据来源]`

## 常见问题

**Q1：技能返回的文章包含大量 `[需核实]` 占位符，是否正常？**  
正常。当输入素材信息不完整或置信度低于60分阈值时，技能会主动插入占位符而非编造数据。请补充核实后替换为真实信息，这是保证内容可信度的设计机制。

**Q2：能否处理 PDF 或扫描件？**  
不能。当前版本仅支持纯文本、.txt、.md 及 .docx 文本提取，以及公开网页 URL。PDF 需先转换为上述格式，扫描件需先进行 OCR 文字识别。

**Q3：如何调整输出语言为英文？**  
在触发指令中附加「输出英文」或「language: en」参数即可。技能默认与输入语言保持一致，除非特别指定。

**Q4：生成的标题超过60字符怎么办？**  
技能会自动给出修改建议，通常提供2-3个精简版本供选择。你也可以手动指定「标题控制在40字符内」等约束条件。

**Q5：技能会联网核实数据吗？**  
不会。技能仅基于你提供的素材进行结构化与起草，不自行联网搜索或核实。所有外部数据需你主动提供或后续人工确认。

**Q6：如何批量生成多篇博客草稿？**  
在进阶路径下，可通过连续提供多组素材（每组用分隔符隔开）并指定「批量模式」，技能将依次输出多篇草稿。注意单次批量建议不超过5篇，以免超出上下文长度限制。
