# cmdbox — 命令别名收纳与变量替换执行工具

## 一、能力边界（一页纸速查卡）

### 1.1 能做什么

| 能力项 | 说明 | 示例 |
|--------|------|------|
| 命令存储 | 将长命令以别名形式保存，支持分类标签 | `cb add deploy --cmd "rsync -avz ./dist/ user@host:/var/www/" --tag 部署` |
| 变量替换 | 命令中预留 `{var}` 占位符，执行时动态传入 | `cb run deploy --set env=prod` |
| 命令组合 | 将多个已存命令按顺序串联执行 | `cb combo build+deploy` |
| 快速检索 | 按名称、标签、描述模糊搜索已存命令 | `cb list --tag 部署` |
| 批量执行 | 对一组文件或参数循环执行同一命令 | `cb batch run resize --input ./images/*.jpg` |
| 导出/导入 | 将命令库导出为 JSON 或从 JSON 恢复 | `cb export > backup.json` |

### 1.2 不能做什么（明确边界）

| 限制项 | 说明 |
|--------|------|
| 不执行交互式命令 | 需要 TTY 交互（如 `vim`、`ssh` 登录会话）的命令无法通过 cmdbox 直接运行 |
| 不做权限提升 | 不会自动注入 `sudo`，需要权限请自行在命令中写明 |
| 不解析 shell 高级语法 | 管道 `\|`、重定向 `>`、逻辑运算符 `&&` 等请用引号包裹整体命令 |

| 不存储敏感信息 | 明文密码、密钥等不建议写入命令库，可用 `{secret:xxx}` 占位并在运行时手动输入 |

## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 |
|------|------|
| 环境 | 已安装 cmdbox（版本 ≥ 1.0.0），可通过 `cb --version` 确认 |
| Shell | 默认使用当前用户的默认 shell（bash/zsh/sh） |
| 权限 | 命令执行所需权限由用户自行保证，cmdbox 不额外提权 |
| 命名规范 | 建议别名使用 `小写字母+连字符`（如 `deploy-prod`），避免空格与特殊字符 |

### 3.2 执行步骤

#### 步骤 1：添加命令

```bash
cb add <别名> --cmd "<完整命令>" [--tag <标签>] [--desc "<描述>"]
```

参数说明：

| 参数 | 必填 | 说明 |
|------|------|------|
| `<别名>` | 是 | 唯一标识，不可重复 |
| `--cmd` | 是 | 要存储的命令全文，含 `{变量}` 占位符 |
| `--tag` | 否 | 分类标签，可多个（逗号分隔） |
| `--desc` | 否 | 命令用途描述，便于检索 |

示例：

```bash
cb add backup-db --cmd "pg_dump -U {user} -h {host} {dbname} > {backup_file}" --tag 数据库,备份 --desc "备份 PostgreSQL 数据库"
```

#### 步骤 2：查看已存命令

```bash
cb list [--tag <标签>] [--search <关键词>]
```

示例：

```bash
cb list --tag 数据库
cb list --search backup
```

#### 步骤 3：执行命令（带变量替换）

```bash
cb run <别名> [--set key=value ...] [--env 环境名]
```

变量替换规则：

| 写法 | 含义 |
|------|------|
| `{var}` | 必填变量，执行时必须通过 `--set var=值` 提供 |
| `{var:默认值}` | 可选变量，未提供时使用默认值 |
| `{secret:var}` | 敏感变量，执行时提示手动输入，不回显 |

示例：

```bash
cb run backup-db --set user=admin --set host=localhost --set dbname=mydb --set backup_file=/tmp/mydb.sql
```

#### 步骤 4：组合执行

```bash
cb combo <别名1>+<别名2>+<别名3> [--set key=value ...]
```

规则：

- 按 `+` 分隔的顺序依次执行
- 任一命令失败（退出码非 0），后续命令不再执行
- `--set` 参数对组合内所有命令生效（同名变量共享）

#### 步骤 5：批量执行

```bash
cb batch run <别名> --input <文件通配符> [--output <输出目录>] [--set key=value ...]
```

规则：

- `--input` 支持通配符（如 `./images/*.jpg`）
- 每个文件路径自动注入 `{input}` 变量
- 若命令中包含 `{output}`，需配合 `--output` 指定输出目录，文件名自动保留原名

#### 步骤 6：导出/导入

```bash
cb export > cmdbox_backup.json
cb import < cmdbox_backup.json
```

### 3.3 输出规范

| 操作 | 成功输出 | 失败输出 |
|------|----------|----------|
| `add` | `✔ 已添加命令: <别名>` | `✘ 添加失败: <原因>` |
| `list` | 表格形式列出（别名、标签、描述、命令预览） | `✘ 无匹配命令` |

## 六、FAQ 反模式

### 6.1 常见坑与正确做法

| 坑（反模式） | 问题 | 正确做法 |
|--------------|------|----------|
| 命令中直接写死密码 | 密码明文存储在命令库，有泄露风险 | 使用 `{secret:password}` 占位，运行时手动输入 |
| 变量名与 shell 环境变量混淆 | 误以为 `$HOME` 会被自动替换 | cmdbox 只识别 `{花括号}` 语法，`$` 开头的请自行在命令中处理 |
| 组合命令中某个命令失败但继续执行 | 后续命令基于错误状态继续，产生连锁问题 | 默认行为即失败即停，如需忽略错误可在命令末尾加 `; true` |
| 批量执行时输出文件覆盖原文件 | 原文件被覆盖且无法恢复 | 始终指定 `--output` 到独立目录，或命令中使用 `{output}` 变量 |
| 添加命令时未加引号 | 含空格或特殊字符的命令被拆解 | 始终用双引号包裹 `--cmd` 参数 |

### 6.2 反模式对照表

| 反模式 | 反例 | 正例 |
|--------|------|------|
| 不设默认值 | `cb add ping --cmd "ping {host}"` | `cb add ping --cmd "ping {host:localhost}"` |
| 不使用标签 | 命令多了之后检索困难 | 添加时用 `--tag` 分类，如 `--tag 网络,诊断` |
| 忽略退出码 | 组合命令中不检查中间结果 | 依赖默认失败即停机制，或显式处理错误码 |
| 批量输入不验证 | 直接对全量数据执行 | 先用单个样本试运行，确认输出格式后再批量 |
