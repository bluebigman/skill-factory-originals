# agent-resources 技能文档

## 一、能力边界速查卡

本技能面向需要将外部数据（网页、文件、纯文本）转换为结构化结果的开发者与自动化流程设计者。使用前请先确认以下边界，避免期望错位。

### 1.1 能做什么

| 能力项 | 说明 | 典型场景 |
|--------|------|----------|
| URL 抓取 | 发起 HTTP GET 请求，提取 HTML 正文并拆分段落 | 抓取新闻页面、博客文章、产品说明页 |
| 文件读取 | 读取本地文件（默认 UTF-8 编码），按行拆分 | 解析 CSV、日志文件、配置文件 |
| 文本处理 | 接收纯文本，按行拆分并清洗空白字符 | 处理用户输入、批量文本清洗 |
| 批量操作 | 支持多资源同时处理，返回合并结果 | 一次抓取多个 URL 或读取多个文件 |
| 自定义格式 | 输出 JSON / CSV / 纯文本三种序列化格式 | 对接不同下游系统 |

### 1.2 不能做什么

| 限制项 | 说明 |
|--------|------|
| 不执行 JavaScript | 仅抓取静态 HTML，动态渲染页面无法获取完整内容 |
| 不处理二进制文件 | 仅支持文本类文件（.txt、.csv、.log、.md 等） |
| 不进行语义分析 | 仅做结构拆分，不判断内容含义、情感或主题 |
| 不绕过访问控制 | 需要登录或权限验证的资源无法访问 |
| 不处理超大文件 | 单文件建议不超过 10MB，超出可能超时或内存溢出 |

### 1.3 适用对象

- 需要定期采集网页数据的运维或数据工程师
- 需要批量解析本地文本文件的分析人员
- 需要将非结构化文本转为结构化记录的业务系统开发者

## 三、标准操作流程

### 3.1 前置条件

- 确认输入类型：URL（以 `http://` 或 `https://` 开头）、文件路径（本地绝对或相对路径）、纯文本（多行字符串）
- 确认输出格式：`json`（默认）、`csv`、`text`
- 确认批量参数：`batch_size`（单次处理数量，默认 10，最大 50）

### 3.2 执行步骤

#### 步骤 1：输入识别与分类

检查输入参数，判断属于以下哪一类：

| 输入特征 | 类型判定 |
|----------|----------|
| 以 `http://` 或 `https://` 开头 | URL 类型 |
| 路径存在且为文件（`os.path.isfile` 为真） | 文件类型 |
| 以上均不满足 | 文本类型 |

#### 步骤 2：按类型执行处理

**URL 类型处理流程：**

1. 发起 HTTP GET 请求，设置超时时间为 10 秒
2. 检查响应状态码：`200` 为成功，其他状态码转错误码表处理
3. 提取 HTML 中 `<body>` 标签内部内容
4. 移除 `<script>` 和 `<style>` 标签及其内部所有内容
5. 按段落标签（`<p>`、`<div>`、`<h1>`-`<h6>`）拆分文本，每个标签内容作为一条记录

**文件类型处理流程：**

1. 验证文件存在且可读（使用 `os.path.exists` 和 `os.access`）
2. 按指定编码（默认 UTF-8）读取文件内容
3. 按换行符（`\n`）拆分为行数组

**文本类型处理流程：**

1. 直接接收文本内容
2. 按换行符拆分为多条记录
3. 去除每行首尾空白字符

#### 步骤 3：数据清洗

对所有类型的处理结果执行统一清洗：

1. 去除空行和纯空白行
2. 去除每行首尾的空白字符
3. 根据输出格式要求进行序列化

#### 步骤 4：序列化输出

| 输出格式 | 序列化规则 |
|----------|------------|
| `json` | 输出 `{"records": [...], "count": n, "skipped": [...]}` 结构 |
| `csv` | 每条记录为一行，逗号分隔，首行为表头 `index,content` |
| `text` | 每条记录为一行，直接输出纯文本 |

#### 步骤 5：返回结果

返回包含以下字段的结构化结果：

```json
{
  "status": "success",
  "records": ["记录1", "记录2"],
  "count": 2,
  "skipped": [],
  "format": "json"
}
```

### 3.3 输出规范

- `status`：固定为 `success`（处理完成）或 `partial`（部分成功）
- `records`：处理成功的记录数组
- `count`：记录总数（数值类型）
- `skipped`：处理失败的资源标识数组（如 URL 或文件路径）
- `format`：实际使用的输出格式

## 四、置信度门控机制

当处理过程中出现以下情况时，本技能不会编造数据，而是输出占位符标记：

| 场景 | 处理方式 | 输出示例 |
|------|----------|----------|
| 网页内容为空（`<body>` 内无文本） | 输出 `[需核实:内容为空]` | `{"records": ["[需核实:内容为空]"]}` |
| 文件读取成功但内容为空 | 输出 `[需核实:文件为空]` | `{"records": ["[需核实:文件为空]"]}` |
| 响应状态码非 200 且无法重试 | 输出 `[需核实:HTTP状态码{code}]` | `{"records": ["[需核实:HTTP状态码404]"]}` |
| 文件编码无法识别 | 输出 `[需核实:编码不支持]` | `{"records": ["[需核实:编码不支持]"]}` |

**使用原则：**

- 占位符仅用于标记信息缺失，不代表处理失败
- 下游系统收到占位符时应触发人工复核或重新采集
- 批量处理中，单个资源失败不影响其他资源的正常输出

## 五、错误码体系

| 错误码 | 含义 | 提示话术 | 修正步骤 |
|--------|------|----------|----------|
| `E001` | URL 格式无效 | "提供的 URL 格式不正确，请检查是否包含协议头" | 确认 URL 以 `http://` 或 `https://` 开头 |
| `E002` | 网络请求超时 | "请求超时（10秒），请检查网络或稍后重试" | 等待 2-3 秒后重试，或检查目标站点可用性 |

| `E008` | 输入为空 | "未检测到有效输入，请提供 URL、文件路径或文本内容" | 检查输入参数是否为空或全为空白字符 |

## 六、FAQ 与反模式对照

### 常见坑 1：动态网页抓取不全

**错误做法：** 直接抓取需要 JavaScript 渲染的页面，期望获得完整内容。

**反模式示例：**
```
输入：https://example.com/spa-page
期望：完整渲染后的正文
实际：仅获得 HTML 骨架，内容为空
```

**正确做法：** 确认目标页面是否为静态 HTML。若是 SPA（单页应用），需配合无头浏览器工具先行渲染，再传入本技能处理。

---

### 常见坑 2：文件编码混用

**错误做法：** 假设所有文件都是 UTF-8 编码，直接读取。

**反模式示例：**
```
输入：file_path: "./data.csv", encoding: 未指定
期望：正常读取内容
实际：乱码或 E006 错误
```

**正确做法：** 明确指定文件编码。不确定时，先使用 `file` 命令检测编码，再传入对应参数。

---

### 常见坑 3：忽略 `skipped` 数组

**错误做法：** 只关注 `records` 字段，忽略 `skipped` 中的失败项。

**反模式示例：**
```
批量处理 20 个 URL，其中 3 个失败
只处理了 17 条记录，未察觉数据缺失
```

**正确做法：** 每次处理完成后检查 `skipped` 数组，对失败项进行重试或记录日志，确保数据完整性。

---

### 常见坑 4：超大文件导致内存溢出

**错误做法：** 直接读取 100MB 以上的日志文件。

**反模式示例：**
```
输入：file_path: "./huge.log"
期望：一次处理完成
实际：进程崩溃或长时间无响应
```

**正确做法：** 对超大文件进行分片处理，或先使用 `head`/`tail` 截取部分内容验证处理逻辑。

---

### 常见坑 5：混淆输入类型

**错误做法：** 将纯文本内容误判为文件路径。

**反模式示例：**
```
输入："C:\Users\test\data.txt 这是一段文本"
期望：按文本处理
实际：尝试读取不存在的路径，返回 E004
```

**正确做法：** 确保输入参数类型明确。若同时包含路径和文本，分开传入或使用结构化参数。

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `url` | string | 条件必填 | 无 | 目标网页地址，以 `http://` 或 `https://` 开头 |

**注意：** `url`、`file_path`、`text` 三者至少提供一个，多个同时提供时按优先级 `url` > `file_path` > `text` 处理。

## 九、示例

### 示例 1：抓取单个网页

{
  "url": "https://example.com/article",
  "format": "json"
}
