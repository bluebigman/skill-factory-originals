# evidence — 数据核验与证据链构建工具

## 一、能力边界（一页纸速查卡）

### 1.1 能做什么

| 能力项 | 说明 | 输出物 |
|--------|------|--------|
| 数据核验 | 对原始数据（CSV/JSON/Excel）进行字段级校验，识别缺失、越界、格式异常 | 核验报告（含问题清单） |
| 证据链构建 | 将核验通过的记录按时间/业务维度串联，形成可追溯的证据链 | 证据链图谱（JSON/GraphML） |
| 审计追踪 | 记录每一步操作（谁、何时、改了什么、为什么），生成不可篡改的审计日志 | 审计日志（JSONL） |
| 结构化报表 | 将核验结果与证据链汇总为标准化报表，支持导出 PDF/CSV | 报表文件 |

### 1.2 不能做什么

- 不执行数据清洗或修复——只标记问题，不修改原始数据。
- 不验证业务逻辑的正确性——只核验数据格式与完整性。
- 不提供法律效力的公证——仅生成技术性证据链，法律效力需用户自行确认。
- 不处理非结构化数据（如自由文本、图片内容）——仅支持表格化数据。

### 1.3 适用对象

- 数据分析师：需要为报表提供可追溯的数据来源。
- 审计人员：需要构建数据变更的完整轨迹。
- 合规专员：需要验证数据是否符合内部规范。
- 开发人员：需要为 API 或数据库操作生成审计日志。

## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 | 缺失时处理 |
|------|------|------------|
| 输入数据格式 | CSV / JSON / Excel（.xlsx） | 提示“无法识别格式”，建议转换后重试 |
| 数据规模 | 单文件 ≤ 100MB，记录数 ≤ 50 万行 | 超出时提示分批处理 |
| 字段定义 | 需提供字段名列表或样例文件 | 自动推断字段名，但标注“推断字段” |
| 时间戳 | 至少一个时间字段（用于证据链排序） | 无时间字段时，仅生成核验报告，不构建证据链 |

### 3.2 执行步骤

**步骤 1：数据接入与解析**

- 读取输入文件，识别格式与编码（UTF-8/GBK）。
- 生成数据概要：总行数、字段数、字段类型推断。
- 输出：`data_profile.json`

**步骤 2：字段级核验**

对每个字段执行以下检查：

| 检查项 | 规则 | 示例 |
|--------|------|------|
| 非空检查 | 必填字段不允许为空 | 字段 `order_id` 为空 → 标记 `[需核实:order_id]` |
| 类型检查 | 数值字段必须为数字 | 字段 `amount` 为 `"abc"` → 标记类型错误 |
| 范围检查 | 数值需在合理区间内 | 字段 `age` 为 `-5` → 标记越界 |
| 格式检查 | 日期/邮箱/电话等需匹配正则 | 字段 `email` 为 `"abc"` → 标记格式错误 |
| 唯一性检查 | 主键字段不允许重复 | 字段 `id` 出现两次 → 标记重复 |

输出：`validation_report.json`（含问题清单，每条问题含行号、字段名、错误类型、原始值）

**步骤 3：证据链构建**

- 按时间字段升序排列记录。
- 为每条记录生成唯一哈希（SHA-256），作为证据节点。
- 相邻记录间生成关联边（基于时间差与业务键）。
- 输出：`evidence_chain.json`（节点列表 + 边列表）

**步骤 4：审计日志生成**

- 记录本次操作的全部动作：文件读取、核验规则、修改建议（不执行修改）。
- 每条日志含：时间戳、操作类型、操作对象、结果摘要。
- 输出：`audit_log.jsonl`

**步骤 5：报表汇总**

- 将核验结果、证据链统计、审计摘要汇总为报表。
- 支持导出格式：CSV（表格）、PDF（图文报告）。
- 输出：`verification_report.csv` / `verification_report.pdf`

### 3.3 输出规范

所有输出文件命名规则：`{输入文件名}_{步骤名}_{时间戳}.{扩展名}`

| 输出物 | 格式 | 内容要求 |
|--------|------|----------|
| 数据概要 | JSON | 行数、字段数、字段类型、缺失率 |
| 核验报告 | JSON | 问题清单（行号、字段、错误类型、原始值） |
| 证据链 | JSON | 节点（哈希、时间、业务键）、边（来源、目标、关系） |
| 审计日志 | JSONL | 每行一条日志，含时间戳、操作、对象、结果 |
| 汇总报表 | CSV/PDF | 核验统计、证据链拓扑摘要、审计摘要 |

## 六、FAQ 反模式

### 6.1 常见坑

| 坑 | 反模式（错误做法） | 正模式（正确做法） |
|----|--------------------|--------------------|
| 数据清洗 | 直接修改原始数据以通过核验 | 仅标记问题，保留原始数据不变 |
| 时间排序 | 按行号排序而非时间排序 | 始终按时间字段升序排列 |
| 缺失处理 | 用默认值填充缺失字段 | 使用 `[需核实:字段名]` 占位，不填充 |
| 哈希冲突 | 忽略哈希冲突可能性 | 检测到冲突时，添加盐值（salt）后重算 |
| 审计遗漏 | 只记录成功操作 | 成功与失败操作均记录，含错误码 |

### 6.2 反模式对照表
