# hallmark — 文本净化与原创性审查 Skill

## 一、能力边界速查卡

本 Skill 用于识别文本中的 AI 生成痕迹，并通过风格净化降低机械感，辅助原创性审查与内容校准。以下表格明确列出**能做**与**不能做**的事项，请在使用前阅读。

| 维度 | 能做（✅） | 不能做（❌） |
|------|-----------|-------------|
| **检测** | 识别高频套路词（如"值得注意的是""综上所述"）、过度工整的排比、异常均匀的段落长度、缺乏个人化表达等 AI 常见痕迹 | 无法 100% 判定某段文本是否由 AI 生成，检测结果仅为概率性提示 |
| **净化** | 对文本进行同义替换、句式重组、段落节奏调整，降低机械感 | 不改变原文核心事实、数据、逻辑关系；不进行事实核查 |
| **审查辅助** | 输出结构化报告，标记可疑段落与修改建议，供人工复核 | 不自动判定抄袭或学术不端，最终判断权在用户 |
| **批量处理** | 支持多文件批量检测与净化，保留原始文件备份 | 不处理加密文件、扫描件、非 UTF-8 编码文件 |

**适用对象**：内容创作者、编辑、运营人员、学术写作者（需遵守所在机构政策）、任何需要对文本进行原创性自查或风格优化的个人与团队。

**不适用对象**：需要法律级鉴定证明的场景、需要绝对确定性结论的场景、自动化发布流水线（未经人工复核）。

## 三、标准执行流程

### 3.1 前置条件

- 待处理文件为纯文本格式（`.txt`、`.md`），编码为 UTF-8。
- 文件命名规范一致，建议格式：`<名称>_<序号>.txt`（如 `article_001.txt`）。
- 确保 `input/` 目录存在，且已放入待处理文件。
- 首次使用建议先运行 `hallmark --selftest` 验证环境正常。

### 3.2 执行步骤（分步编号）

1. **准备输入**：将待处理文件放入 `input/` 目录，确认命名规范一致（如 `article_001.txt`）。
2. **试运行**：先用单个样本执行，核对输出字段与格式是否符合预期。
   ```bash
   hallmark --file input/test.txt --mode detect
   ```
3. **核对输出**：检查检测报告中的字段（见 3.3 输出规范），确认无误。
4. **批量执行**：确认无误后对全量数据执行，并保留原始文件备份。
   ```bash
   hallmark --dir input/ --mode purify --output output/
   ```
5. **校验结果**：抽查输出条目，核对关键字段与源数据一致（如段落数、关键术语是否保留）。

### 3.3 输出规范

**检测模式（detect）** 输出 JSON 报告，字段如下：

| 字段 | 类型 | 说明 |
|------|------|------|
| `file` | string | 源文件名 |
| `ai_score` | float | AI 痕迹概率（0.0 ~ 1.0，越高越可疑） |
| `suspicious_segments` | array | 可疑段落列表，含段落序号与原因 |
| `suggestions` | array | 针对可疑段落的修改建议 |
| `stats` | object | 段落数、平均句长、重复度等统计信息 |

**净化模式（purify）** 输出净化后的文本文件，并在同目录生成 `.report.json` 报告，包含：

- 修改点列表（原句 → 改后句，及修改原因）
- 保留不变的术语/数据清单
- 净化前后 ai_score 对比

**示例（检测报告片段）**：

```json
{
  "file": "article_001.txt",
  "ai_score": 0.82,
  "suspicious_segments": [
    {
      "paragraph": 3,
      "reason": "连续三句使用'值得注意的是'开头，句式高度重复",
      "suggestion": "删除引导词，直接陈述事实；或改为'需要关注的是'等变体"
    }
  ],
  "stats": {
    "paragraph_count": 12,
    "avg_sentence_length": 28.5,
    "repetition_rate": 0.15
  }
}
```
