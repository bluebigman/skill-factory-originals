### 3.2 执行步骤

#### 第一步：试运行（推荐）

```bash
gitsum --dry-run --input ./data/sample.txt
```

此命令预览提取效果，不生成输出文件。检查提取结果是否符合预期。

#### 第二步：正式处理

```bash
gitsum --input ./data/sample.txt --output ./output/result.md --format markdown --threshold 0.6
```

参数说明：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--input` | 必填 | 输入文件路径或 URL，多个用逗号分隔 |
| `--output` | 控制台输出 | 输出文件路径 |
| `--format` | `markdown` | 输出格式：`markdown` / `json` / `csv` |
| `--threshold` | `0.6` | 置信度阈值，低于此值的条目标记 [需核实] |
| `--dry-run` | 关闭 | 试运行模式，不写文件 |
| `--batch-size` | `10` | 批量处理时每批数量 |

#### 第三步：检查输出

输出文件包含三部分：

1. **元信息**：处理时间、输入来源、参数设置
2. **提取结果**：按置信度降序排列的关键信息条目
3. **统计摘要**：总条目数、平均置信度、需核实条目数

## 四、置信度门控

### 4.1 置信度评分规则

| 评分维度 | 权重 | 说明 |
|----------|------|------|
| 信息完整性 | 40% | 是否包含完整的语义单元（主谓宾） |
| 上下文一致性 | 30% | 与原文整体主题是否一致 |
| 可验证性 | 20% | 是否包含可查证的具体数据或引用 |
| 去重度 | 10% | 是否与已有条目重复 |

### 4.2 信息不足处理

当提取的信息存在缺失或模糊时，输出 `[需核实:字段名]` 占位符，**绝不编造**。

常见占位场景：

| 场景 | 占位示例 |
|------|----------|
| 数据无时间范围 | `[需核实:统计周期] 用户增长率为 23%` |
| 引用无出处 | `[需核实:引用来源] 据报告显示...` |
| 人名/机构名不完整 | `[需核实:机构全称] 该部门负责人表示...` |
| 数值单位缺失 | `[需核实:单位] 成本降低 15` |

### 4.3 阈值调整建议

| 使用场景 | 建议阈值 | 说明 |

| 新闻摘要 | 0.6 | 默认值，平衡召回率与准确率 |
| 学术文献 | 0.7 | 需确保关键结论的准确性 |

## 常见问题

**Q1：为什么无法处理 PDF 或 DOCX 文件？** — 本 Skill 仅支持纯文本格式（.txt、.md、.csv、.json、.log），PDF、DOCX、图片等二进制格式需先转换为文本后方可处理。建议使用第三方转换工具完成格式转换后再调用本 Skill。

**Q2：置信度分数偏低或大量出现 [需核实] 标记怎么办？** — 置信度偏低通常说明原文信息不够明确或存在歧义。建议检查原文质量，或适当调低置信度阈值。需注意，调低阈值会增加误报风险，建议结合人工复核使用。

**Q3：URL 内容提取失败是什么原因？** — 可能原因包括：目标页面需要登录或位于付费墙后、网络连接不稳定、页面为动态渲染内容。本 Skill 不处理加密或需授权访问的内容，建议更换可公开访问的 URL 重试。

**Q4：批量处理大量文件时速度较慢，如何优化？** — 建议将同类型文件分组处理，并优先处理文本量较小的文件。同时确保输入文件编码为 UTF-8，避免编码转换带来的额外开销。若处理量极大，可分批执行并合并输出结果。

**Q5：输出结果与预期不符怎么办？** — 建议先使用试运行功能验证小样本效果，确认提取逻辑符合预期后再执行完整任务。同时检查原文是否包含足够的关键信息，信息不足时提取结果会受影响，可适当补充上下文后重试。
