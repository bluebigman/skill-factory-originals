## 四、参数详细说明

### 4.1 必填参数

| 参数名 | 类型 | 合法范围 | 默认值 | 说明 |
|--------|------|----------|--------|------|
| `queue_size` | int | 256 ~ 1048576 | 8192 | 异步队列容量，决定可缓冲的日志条数 |
| `thread_count` | int | 1 ~ 32 | 4 | 消费队列的工作线程数 |
| `log_level` | string | DEBUG/INFO/WARN/ERROR | INFO | 日志级别阈值 |

### 4.2 可选参数

| 参数名 | 类型 | 合法范围 | 默认值 | 说明 |
|--------|------|----------|--------|------|
| `discard_policy` | string | block/discard/oldest | block | 队列满时的处理策略 |
| `flush_interval` | int | 100 ~ 60000 | 1000 | 批量刷盘间隔（毫秒） |
| `max_batch_size` | int | 1 ~ 1000 | 100 | 单次批量写入的最大条数 |

### 4.3 边界值与约束

- `queue_size` 必须 ≥ 256，且建议 ≥ `thread_count` × 1024，否则可能频繁触发丢弃策略。
- `thread_count` 超过 16 时，收益递减且可能引入上下文切换开销，需谨慎评估。
- `discard_policy` 为 `discard` 时，必须同时设置 `flush_interval` ≤ 5000，避免数据丢失窗口过长。
- `log_level` 为 `DEBUG` 时，建议 `queue_size` 至少为默认值的 2 倍。

## 七、FAQ 与反模式对照

### 7.1 常见坑

| 坑位 | 错误做法 | 正确姿势 |
|------|----------|----------|
| 队列设置过大 | `queue_size=1048576` 且 `thread_count=1` | 按业务峰值估算，通常 8192~65536 足够 |
| 丢弃策略滥用 | 一律使用 `discard` 策略 | 核心日志使用 `block`，非核心可 `discard` |
| 忽略 flush 间隔 | 不设置 `flush_interval` | 根据日志重要性与延迟容忍度设置 500~5000ms |
| 线程数拍脑袋 | `thread_count=32` 追求极致 | 按 CPU 核数 2~4 倍设置，不超过 16 |
| 校验后不验证 | 直接复制 config 上线 | 先在 staging 环境压测验证 |

### 7.2 反模式对照表

| 反模式 | 表现 | 后果 | 替代方案 |

本 Skill 为纯 Markdown 定义技能，无需额外安装依赖或配置环境变量。使用前请确保运行环境支持 WorkBuddy Skill 加载机制，并将本 Skill 文件放置于正确的技能目录下。首次使用建议先执行 `--selftest` 自检模式，验证技能运行链路完整性。技能运行不依赖外部服务或第三方库，所有解析与校验逻辑均在本地完成，无需网络连接。若需在 CI/CD 流程中嵌入使用，请确保调用环境具备 JSON 输入文件的读取权限，并按照批量模式规范传入参数。具体目录配置与加载方式请参考 WorkBuddy 平台的标准技能安装指南。

## 使用方法

本 Skill 支持交互模式与批量模式两种调用方式。交互模式下，用户直接输入合法 JSON 格式的异步日志配置字符串，技能将依次执行配置解析、参数校验与方案生成三个核心步骤，最终输出结构化配置方案。批量模式下，用户通过文件路径传入 JSON 配置，技能自动完成解析与校验，适合嵌入自动化脚本或 CI/CD 流水线。调用时需确保必填参数完整，可选参数可按需提供。输出结果包含 `config` 块与 `recommendations` 优化建议两部分，可直接作为配置落地方案参考。若校验失败，技能将返回对应错误码与错误详情，便于快速定位问题。

## 示例

**交互模式示例：** 用户输入 `{"queue_size": 1024, "thread_count": 4, "log_level": "INFO"}`，技能解析该 JSON 配置，对 `queue_size` 校验其类型为整数、范围在 1-10000 之间且为 2 的幂，对 `thread_count` 校验其为正整数且不超过 64，对 `log_level` 校验其属于 DEBUG/INFO/WARN/ERROR 枚举范围。校验通过后，输出包含完整 `config` 块与 `recommendations` 优化建议的配置方案。**批量模式示例：** 用户传入 `config.json` 文件路径，技能读取文件并执行相同流程，适用于多配置文件批量校验场景。若配置中 `queue_size` 设置为 0 或负数，技能将返回类型或范围校验错误码，并给出修正建议。

## 常见问题

**Q1：输入非 JSON 格式怎么办？** 本技能仅接受合法 JSON 输入，YAML/XML 需先转换为 JSON 格式后再传入。**Q2：校验失败后如何定位问题？** 技能会返回标准错误码，对应 `## 六、错误码体系` 章节中的具体错误类型与说明，同时附带错误参数名称与期望约束。**Q3：配置方案是否保证性能提升？** 不承诺。技能只生成基于参数约束的合法配置方案，实际吞吐量受业务场景、硬件环境等多因素影响，需结合具体场景验证。**Q4：是否支持所有日志框架？** 当前仅针对异步日志通用模型，不绑定特定厂商 SDK，通用场景均可适用。**Q5：`--selftest` 模式的作用？** 用于验证技能运行链路完整性，建议在首次使用或环境变更后执行一次。
