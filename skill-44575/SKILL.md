## 三、标准执行流程

### 3.1 前置条件

| 条件 | 要求 | 检查方式 |
|------|------|----------|
| 软件名称 | 必须提供（如 Excel、Photoshop） | 触发词中提取或系统询问 |
| 目标用户 | 可选（新手/进阶/讲师） | 系统询问或默认"新手" |
| 学习目标 | 可选（基础操作/完整项目/高级功能） | 系统询问或默认"基础操作" |
| 素材文件 | 可选（PDF/Excel/网页） | 用户上传或提供链接 |

### 3.2 执行步骤

1. **接收输入**：解析触发词中的软件名称，记录用户补充信息（目标用户、学习目标）。
2. **素材整理**（如有素材）：提取 PDF/Excel/网页中的操作步骤，去重并排序。
3. **方案生成**：调用 `generate_teaching_plan()` 函数，按模板生成教学方案。
4. **完整性校验**：检查必备字段（软件名称、目标用户、学习目标、步骤列表、练习任务）是否齐全。
5. **步骤连续性校验**：检查步骤间是否有逻辑跳跃（如从"打开软件"直接跳到"导出文件"）。
6. **置信度评估**：根据以下公式计算置信度：
   ```
   置信度 = 0.4 × 信息完整度 + 0.3 × 素材充足度 + 0.3 × 校验通过率
   ```
   - 信息完整度：必备字段齐全率（0~1）
   - 素材充足度：素材覆盖步骤的比例（0~1）
   - 校验通过率：通过校验的检查项占比（0~1）
7. **输出结果**：生成 Markdown 文件，附置信度等级与校验报告。

### 3.3 输出规范

输出文件结构如下：

```markdown
# {软件名称} 教学方案

## 目标用户
{新手/进阶/讲师}

## 学习目标
{基础操作/完整项目/高级功能}

## 前置要求
- 已安装 {软件名称}
- 具备基本的计算机操作能力

## 练习任务
1. 基础练习：完成软件的基本操作
2. 进阶练习：完成一个完整项目
3. 挑战练习：尝试高级功能

## 操作步骤
1. {步骤一}
2. {步骤二}
...

## 校验报告
- 完整性校验：{通过/未通过}
- 步骤连续性校验：{通过/未通过}
- 置信度：{高/中/低}（{数值}%）
```
