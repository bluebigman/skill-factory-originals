| 序号 | 能力项 | 说明 | 适用场景示例 |
|------|--------|------|--------------|
| 1 | 数据/文件/URL 解析 | 读取并解析用户提供的原始材料 | 从 CSV 中提取客户名单、从网页中抓取商品信息 |
| 2 | 关键信息识别与保留 | 自动识别输入中的核心字段，保留上下文关联 | 从合同文本中提取甲方乙方、金额、日期 |

## 三、标准流程

### 3.1 前置条件

| 条件项 | 要求 |
|--------|------|
| 输入格式 | 支持纯文本、CSV、JSON、Markdown、HTML、URL |
| 输入大小 | 单文件 ≤ 50MB，单次批量 ≤ 100 个文件/URL |
| 输出格式 | 默认 JSON，可指定为 CSV、Markdown、YAML |
| 字段结构 | 用户需指定至少 1 个目标字段；未指定时使用默认字段集 |

### 3.2 执行步骤

**Step 1：收集输入并确认格式**

- 确认输入来源（文件路径 / URL / 直接粘贴文本）
- 确认目标输出格式（JSON / CSV / Markdown）
- 确认需要提取的字段列表（如未提供，使用默认字段集）

**Step 2：解析输入内容**

- 读取输入数据，识别数据类型（文本/表格/标记语言）
- 去除无关噪声（如 HTML 标签、多余空白、注释行）
- 将内容切分为可处理的语义单元（段落/行/单元格）

**Step 3：提取关键信息**

- 按用户指定的字段列表逐一匹配
- 使用正则表达式、关键词匹配、位置规则等方法定位字段值
- 对每个提取结果记录来源位置（行号/段落索引）

**Step 4：生成结果并标注置信度**

- 置信度评分规则：

| 置信度等级 | 判定标准 | 示例 |
|------------|----------|------|
| 高（0.9-1.0） | 字段值在输入中显式存在，且格式完全匹配 | 日期 `2024-03-15` 直接出现在文本中 |
| 中（0.6-0.8） | 字段值存在但格式有偏差，或需简单转换 | 日期 `2024/3/15` 需格式统一 |
| 低（0.3-0.5） | 字段值需从上下文中推断，或存在多个候选值 | 从"3月中旬"推断日期 |
| 无法确定（0-0.2） | 输入中无相关信息 | 输入中未提及金额 |

**Step 5：输出结果并自查**

- 检查字段完整性：所有目标字段是否都有值或占位符
- 检查格式正确性：输出是否符合用户指定的格式规范
- 检查置信度标注：每个字段是否都有置信度标记
- 如有疑问，向用户二次确认

### 3.3 输出规范

**默认输出格式（JSON）：**

```json
{
  "meta": {
    "input_source": "file:///path/to/input.csv",
    "processed_at": "2026-08-09T10:30:00Z",
    "total_records": 12
  },
  "data": [
    {
      "field1": "value1",
      "field2": "value2",
      "_confidence": {
        "field1": 0.95,
        "field2": 0.80
      }
    }
  ],
  "warnings": [
    "记录 #3 缺少字段 'phone'，已标记为 [需核实:phone]"
  ]
}
```

**自定义格式示例（Markdown 表格）：**

```markdown
| 字段名 | 值 | 置信度 |
|--------|-----|--------|
| name   | 张三 | 高     |
| phone  | [需核实:phone] | 无法确定 |
```

## 四、置信度门控

### 4.1 基本原则

- **不编造**：输入中不存在的信息，一律输出 `[需核实:字段名]` 占位符
- **不猜测**：存在多个候选值时，输出所有候选值并标注各自置信度
- **可追溯**：每个输出值都记录来源位置，便于用户核验

### 4.2 占位符使用规则

| 场景 | 占位符格式 | 示例 |
|------|------------|------|
| 字段完全缺失 | `[需核实:字段名]` | `[需核实:email]` |
| 字段存在但值不确定 | `[需核实:字段名|候选值1,候选值2]` | `[需核实:date|2024-03-15,2024-03-16]` |
| 字段格式需确认 | `[需核实:字段名|当前值]` | `[需核实:amount|1000元]` |

### 4.3 置信度阈值

- 当整体置信度均值 < 0.6 时，输出结果前自动附加提示：
  `"警告：本次提取的整体置信度较低（均值 0.45），建议人工复核关键字段。"`

## 六、FAQ 反模式

### 6.1 常见坑与反模式对照

| 常见坑 | 反模式（错误做法） | 正模式（正确做法） |
|--------|-------------------|-------------------|
| 字段名模糊 | 用户说"提取重要信息"，不指定具体字段 | 用户明确指定"提取合同中的甲方、乙方、签约日期" |
| 输入格式混杂 | 一个输入中混有中英文、多种日期格式 | 先统一格式，再提取；或分多次处理 |
| 忽略置信度 | 直接使用提取结果，不关注置信度标注 | 对低置信度字段进行人工复核 |
| 过度依赖正则 | 仅用正则匹配，忽略上下文语义 | 结合关键词、位置规则、上下文综合判断 |
| 批量处理无检查 | 批量处理后不抽查结果质量 | 随机抽取 10% 结果人工核验 |

### 6.2 反模式示例

**反模式 1：**
- 用户输入："帮我整理一下这个文件"
- 错误响应：直接输出所有内容
- 正确响应："请指定需要提取的字段，例如：姓名、电话、邮箱。或使用默认字段集。"

**反模式 2：**
- 用户输入："提取所有日期"
- 错误响应：只提取 `YYYY-MM-DD` 格式的日期
- 正确响应：提取所有日期格式（`2024-03-15`、`2024/3/15`、`2024年3月15日`），并统一格式输出
