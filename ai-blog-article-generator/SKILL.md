# 博客文章智能起草器（ai-blog-article-generator）

## 一、能力边界速查卡

本 Skill 用于将各类输入源（数据文件、网页链接、纯文本）转化为一篇带完整 frontmatter 元信息的 Markdown 格式博客文章草稿。它解决的是"从素材到初稿"的转换问题，而非"从零到一"的创意写作。

### 1.1 能做什么

| 输入类型 | 支持格式 | 说明 |
|---------|---------|------|
| 数据文件 | CSV、JSON、TXT、MD | 自动解析表格/结构化数据，提取关键字段 |
| 网页链接 | 公开 URL（HTTP/HTTPS） | 抓取正文内容，去除导航/广告噪音 |
| 纯文本 | 直接粘贴的文本块 | 自动分段、识别主题 |

### 1.2 不能做什么

- **不能访问需要登录认证的网页**（如企业内网、付费墙后的内容）
- **不能解密加密文件**（如带密码的 ZIP、加密 PDF）
- **不能保证事实准确性**——AI 生成内容可能包含不准确信息，必须人工核实
- **不能替代人工编辑**——生成的是草稿，不是终稿
- **不能处理二进制文件**（图片、音频、视频等）

### 1.3 适用对象

- 内容运营人员：快速将数据报告转为博客初稿
- 技术写作者：将 API 文档、代码注释整理为教程文章
- 产品经理：将 PRD、会议纪要转化为对外公告草稿
- 个人博主：将零散笔记整理为结构化文章

## 三、标准执行流程

### 3.1 前置条件检查

在执行任何转换前，必须完成以下检查：

| 检查项 | 方法 | 通过标准 |

| API Key 有效性 | `echo $COHERE_API_KEY` | 非空且未过期 |
| 输入文件可读性 | `file <输入路径>` | 文件类型匹配声明格式 |
| 输入文件大小 | `ls -lh <输入路径>` | ≤ 5MB（超过则提示分段处理） |

### 3.2 执行步骤

**步骤 1：输入解析**

- 识别输入类型（文件/URL/文本）
- 根据类型调用对应解析器：
  - CSV：使用 `csv.DictReader` 逐行读取，保留表头
  - JSON：递归遍历，提取所有键值对
  - TXT/MD：按段落分割，保留标题层级
  - URL：使用 `requests.get()` 抓取，`BeautifulSoup` 提取 `<article>` 或 `<main>` 标签内容

**步骤 2：主题识别**

- 从解析结果中提取高频关键词（TF-IDF 算法，Top 5）
- 结合 frontmatter 的 `trigger_words` 确定文章主题
- 若主题不明确，输出 `[需核实:文章主题]` 占位符并暂停

**步骤 3：结构规划**

根据输入类型自动选择文章模板：

| 输入类型 | 推荐模板 | 章节结构 |
|---------|---------|---------|
| CSV/JSON（数据型） | 数据解读型 | 引言 → 数据概览 → 关键发现（3-5条）→ 趋势分析 → 结论 |
| URL（资讯型） | 摘要评论型 | 引言 → 原文要点 → 深度解读 → 延伸思考 → 结语 |
| TXT/MD（文档型） | 教程指南型 | 背景 → 前置条件 → 分步操作 → 常见问题 → 总结 |
| 纯文本（观点型） | 观点论述型 | 引出话题 → 核心论点 → 论据支撑 → 反驳与回应 → 结论 |

**步骤 4：内容生成**

- 按模板逐节生成内容，每节控制在 150-300 字
- 关键数据点必须标注来源（如 `[数据来源:CSV第3行第2列]`）
- 生成过程中遇到信息缺口，使用 `[需核实:具体缺口描述]` 占位

**步骤 5：SEO 优化**

- 生成 frontmatter 中的 `title`（建议 30-60 字符）
- 提取 5-8 个关键词填入 `keywords` 字段
- 生成 150-160 字符的 `description` 摘要
- 检查标题长度：超过 60 字符则截断并添加省略号

**步骤 6：输出规范**

输出文件必须包含：

```markdown
---
title: <文章标题>
date: <生成日期 YYYY-MM-DD>
author: <默认"内容工坊"或用户指定>
tags: [<关键词1>, <关键词2>, ...]
description: <150-160字符摘要>
keywords: [<关键词1>, <关键词2>, ...]
---

# <文章标题>

<正文内容>
```

## 六、FAQ 与反模式对照

### 6.1 常见坑位

**坑位 1：直接发布 AI 生成内容**

- **反模式**：生成文章后不做任何修改直接发布
- **正确做法**：至少完成以下 5 项人工审核：
  1. 补充事实数据与引用来源——AI 生成内容可能包含不准确信息
  2. 调整语气以匹配品牌风格——默认语气为专业中性
  3. 检查 SEO 标题长度——建议 30-60 字符
  4. 验证关键词密度——建议 1-3%
  5. 人工审核全文——确保逻辑连贯、无事实错误

**坑位 2：输入数据质量差**

- **反模式**：使用含大量缺失值、格式混乱的数据文件
- **正确做法**：预处理数据，确保字段完整、格式统一，必要时先清洗数据

**坑位 3：忽略置信度评分**

- **反模式**：无视置信度评分，直接使用低置信度输出
- **正确做法**：评分低于 60 时，重新提供输入或手动补充信息

**坑位 4：依赖 AI 生成事实**

- **反模式**：将 AI 生成的数据、日期、引用当作真实信息使用
- **正确做法**：所有事实性内容必须人工核实，使用 `[需核实]` 标记追踪

**坑位 5：忽略 SEO 优化建议**

- **反模式**：跳过 SEO 检查步骤，直接使用默认标题和描述
- **正确做法**：按建议调整标题长度、关键词密度，提升搜索可见性

### 6.2 反模式对照表

| 反模式 | 问题 | 替代方案 |
