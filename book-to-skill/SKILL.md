# book-to-skill 技能文档

## 一、能力边界：一页纸速查卡

本技能的核心使命：把一本技术书籍的 PDF 文件，转化为一个结构化的、可被 Claude Code 直接调用的技能包。转化后的技能包包含知识摘要、操作流程、代码示例和自查清单，让你在编码、调试、架构设计时随时查阅，不必再翻原书。

| 序号 | 能力项 | 说明 | 输入示例 | 输出示例 |
|------|--------|------|----------|----------|
| 1 | 书籍内容解析 | 从PDF中提取目录、章节标题、核心概念、代码块 | `~/books/clean-architecture.pdf` | 章节树 + 概念清单 |
| 2 | 知识结构化 | 将散乱内容重组为「概念-原理-操作-示例」四层结构 | 第3章 依赖倒置 | 结构化知识卡片 |
| 3 | 技能包生成 | 生成符合 Claude Code 规范的 SKILL.md 文件 | 解析结果 | 完整 SKILL.md |
| 4 | 代码示例提取 | 从书中提取可运行的代码片段并标注适用版本 | 书中代码块 | 可执行代码 + 环境说明 |
| 5 | 自查与校验 | 检查生成的技能包是否完整、可读、无歧义 | 生成的 SKILL.md | 校验报告 + 修正建议 |


## 六、FAQ 反模式：常见坑与避坑指南

### 坑1：试图一次转换整本大书

**反模式**：把一本600页的书一次性全部转换，导致生成的技能包臃肿难用。

**正确做法**：先指定重点章节（如 `focus_chapters: [2, 5, 8]`），生成精简版技能包，后续按需补充。

### 坑2：忽略代码环境标注

**反模式**：提取代码时不标注依赖环境，导致使用时频繁报错。

**正确做法**：每个代码示例必须标注：语言版本、依赖库、运行环境、验证方式。

### 坑3：直接复制书中原文

**反模式**：将书中大段文字直接复制到技能包中，违反版权且不利于理解。

**正确做法**：用自己的话重新组织，提炼核心要点，保留必要的术语和定义。

### 坑4：不校验生成的技能包

**反模式**：生成后直接使用，不检查内容完整性和格式正确性。

**正确做法**：运行自查清单，逐项验证：触发词是否生效、流程是否清晰、示例是否可运行。

### 坑5：忽略置信度标注

**反模式**：对不确定的内容直接给出结论，误导使用者。

**正确做法**：严格按照置信度门控规则，对不确定内容使用 `[需核实:字段]` 占位。
