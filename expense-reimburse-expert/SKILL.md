## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 |
|------|------|
| 输入形式 | 图片（JPG/PNG/PDF 扫描件）或纯文本金额清单 |
| 图片质量 | 文字清晰可辨，无严重反光/遮挡；模糊图片将降低置信度 |
| 数量限制 | 单次 ≤ 20 张；超过请分批处理 |
| 文本清单格式 | 每行一条记录，格式为：`日期, 金额, 商品/服务描述, 销售方`（可缺省部分字段） |

### 3.2 执行步骤

**步骤 1：接收输入**

- 用户上传图片或粘贴文本清单。
- Skill 检查输入数量与格式，若超限或格式不符，返回错误码 `E1001` 或 `E1002`。

**步骤 2：逐张提取关键信息**

- 对每张图片执行 OCR 识别，提取以下字段：
  - `invoice_code`（发票代码）
  - `invoice_number`（发票号码）
  - `issue_date`（开票日期）
  - `buyer_name`（购买方名称）
  - `seller_name`（销售方名称）
  - `amount_total`（价税合计）
  - `amount_without_tax`（不含税金额）
  - `tax_amount`（税额）
  - `item_description`（商品/服务名称）
- 对文本清单，按分隔符解析字段。

**步骤 3：归类与真伪初查**

- 根据 `item_description` 关键词映射到费用类型（映射表见附录 A）。
- 对发票代码/号码执行格式校验（规则见附录 B）。
- 校验 `amount_total` 是否等于 `amount_without_tax + tax_amount`（允许 ±0.01 误差）。

**步骤 4：置信度评估**

- 每个字段根据识别清晰度、格式合规性、逻辑一致性获得置信度等级。
- 低置信度字段追加 `[需核实]` 标记。

**步骤 5：生成输出**

- 默认输出 Markdown 表格，包含全部字段与置信度标注。
- 若用户指定 CSV 或 JSON，则按对应格式输出。
- 输出末尾附「汇总统计」：总张数、总金额、分类小计、存疑项列表。

## 四、置信度门控

### 4.1 置信度分级规则

| 等级 | 判定条件 | 输出表现 |
|------|----------|----------|
| 高 | 字段识别清晰 + 格式完全合规 + 逻辑校验通过 | 正常显示 |
| 中 | 字段识别基本清晰，但存在以下任一情况：格式部分合规、逻辑校验有 ±0.01 误差、图片有轻微模糊 | 正常显示，但追加 `[需核实]` 标记 |
| 低 | 字段无法完整识别、格式明显不合规、逻辑校验失败、图片严重模糊 | 以 `[需核实:字段名]` 占位，不猜测填充 |

### 4.2 信息不足时的处理原则

- **绝不编造**：无法识别的字段不猜测，直接输出 `[需核实:字段名]`。
- **部分可用**：若某张票据仅金额可识别，其余字段均无法识别，则输出一行，金额正常显示，其余字段全部为 `[需核实]`。
- **整张不可用**：若一张票据完全无法识别，输出一行，所有字段均为 `[需核实]`，并在汇总中标记为「无法识别」。
