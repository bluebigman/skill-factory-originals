## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 | 检查方式 |
|------|------|----------|
| 工作目录 | 包含待处理资料文件 | `ls` 或 `dir` 命令 |
| 文件格式 | `.md`、`.txt`、`.docx`、`.pdf` | 文件扩展名检查 |
| 文件内容 | 非空，且包含人物相关信息 | 文件大小检查（>500 字节） |
| 输出目录 | 当前目录可写 | 权限检查 |

### 3.2 执行步骤

#### 步骤 1：扫描与清单生成

扫描当前目录，排除以下文件类型：
- 所有 `*.md` 输出文件（`*_profile.md`、`INDEX.md`、`execution_log.md`）
- 日志文件（`*.log`）
- 隐藏文件（以 `.` 开头）

生成文件清单，格式如下：

```
1. /path/to/interview_zhang.md (2,340字)
2. /path/to/investment_notes.md (1,890字)
3. /path/to/meeting_minutes.md (860字)
```

#### 步骤 2：用户确认

等待用户明确回复，接受以下任一形式：
- "确认" / "继续" → 进入步骤 3
- 修改指令（如"排除第 2 个"）→ 调整清单后重新确认
- 其他回复 → 视为未确认，保持等待

#### 步骤 3：试运行

1. 将确认后的清单追加至 `execution_log.md`
2. 选取清单中第一个文件作为样本
3. 执行蒸馏流程（见 3.3 蒸馏算法）
4. 输出完整人物档案草稿
5. 与用户核对以下字段：
   - 人物姓名
   - 核心信念（3-5 条）
   - 关键场景（2-3 个）
   - 决策规则（如有）
6. 根据反馈调整参数，重新生成草稿直至用户确认

#### 步骤 4：批量执行

1. 确认试运行无误后，对剩余文件逐一执行蒸馏
2. 每个文件输出独立档案：`人物名_profile.md`
3. 档案命名规则：从资料中提取人物全名，若无法提取则用文件名前缀
4. 所有文件处理完毕后，生成 `INDEX.md`

#### 步骤 5：质量校验

1. 从输出档案中随机抽取 20%（至少 1 条）
2. 对照源资料，核对以下字段：
   - 信念提取是否准确
   - 场景分类是否合理
   - 决策规则是否有据可依
3. 校验通过后，输出最终交付说明：

```
- 输出档案：3 份（张明_profile.md、李华_profile.md、王芳_profile.md）
- 校验通过：1/1（抽样率 33%）
- 处理耗时：45 秒
- 置信度：高（所有关键字段均有源资料支撑）
```

### 3.3 蒸馏算法

#### 阶段 1：文本预处理

| 操作 | 说明 | 参数 |
|------|------|------|
| 清洗 | 去除无关字符、空白行 | 保留段落结构 |
| 分段 | 按语义切分文本块 | 每段 200-500 字 |
| 标注 | 标记人名、时间、地点 | 使用 NER 工具 |

#### 阶段 2：实体识别

- 识别人物全名、别名、代称
- 提取时间信息（绝对时间与相对时间）
- 识别组织、职位、关系网络

#### 阶段 3：信念抽取

从文本中提取以下类型的信念：

| 信念类型 | 识别特征 | 示例 |
|----------|----------|------|
| 价值取向 | "我认为"、"重要的是"、"关键在于" | "我认为诚信比利润更重要" |
| 决策偏好 | "我倾向于"、"我习惯"、"我通常" | "我倾向于先做市场调研再决策" |
| 风险态度 | "我担心"、"我害怕"、"我确信" | "我担心过度扩张会拖垮团队" |
| 人际原则 | "我对待"、"我要求"、"我尊重" | "我要求团队成员坦诚沟通" |

#### 阶段 4：场景分类

将文本中的事件归类到以下场景：

| 场景类型 | 识别特征 | 示例 |
|----------|----------|------|
| 决策场景 | 面临选择、权衡利弊 | "当时我在两个方案之间犹豫" |
| 冲突场景 | 意见分歧、利益冲突 | "我们团队在预算分配上产生了分歧" |
| 协作场景 | 团队合作、资源协调 | "我们跨部门合作完成了项目" |
| 压力场景 | 时间紧迫、资源不足 | "在截止日期前三天，我们还没完成一半" |
| 成长场景 | 学习反思、认知升级 | "那次失败让我意识到自己的盲区" |

#### 阶段 5：结构化输出

输出格式模板：

```markdown
# [人物全名] 思维档案

## 基本信息
- 姓名：[人物全名]
- 来源文件：[文件名]
- 处理时间：[日期]

## 核心信念
1. 信念1（来源：资料A，时间：2023-05）
2. 信念2（来源：资料B，时间：2024-01）

## 关键场景
- 场景1：决策场景
  - 情境描述：[简述]
  - 决策逻辑：[提取的决策规则]
  - 结果与反思：[如有]
- 场景2：冲突场景
  - 情境描述：[简述]
  - 处理方式：[提取的行为模式]
  - 结果与反思：[如有]

## 决策规则
- 规则1：[条件] → [行动]
- 规则2：[条件] → [行动]

## 置信度说明
- 高置信度字段：[列出字段]
- 需核实字段：[列出字段]
```

## 四、置信度门控

### 4.1 置信度等级

| 等级 | 定义 | 输出方式 |
|------|------|----------|
| 高 | 字段有明确源资料支撑 | 直接输出 |
| 中 | 字段可从上下文推断 | 输出并标注"推断" |
| 低 | 字段信息不足 | 输出 `[需核实:字段]` 占位符 |

### 4.2 占位符使用规则

| 场景 | 占位符格式 | 示例 |
|------|------------|------|
| 人物姓名缺失 | `[需核实:人物姓名]` | 使用文件名前缀替代 |
| 时间信息缺失 | `[需核实:时间]` | 标注"时间未知" |
| 信念来源不明 | `[需核实:信念来源]` | 标注"来源待确认" |
| 场景描述不完整 | `[需核实:场景细节]` | 仅输出可确认部分 |

### 4.3 禁止行为

- 禁止编造人物未表达的观点
- 禁止推测人物未提及的情感状态
- 禁止将不同人物的信息混入同一档案
- 禁止在信息不足时强行输出完整档案

## 五、错误码体系

### 5.1 错误码速查

| 错误码 | 含义 | 用户提示 | 修正步骤 |
|--------|------|----------|----------|
| `E_SCAN_FAIL` | 目录扫描失败 | "无法扫描当前目录，请检查路径" | 确认目录存在且有读权限 |
| `E_READ_FAIL` | 文件读取失败 | "无法读取文件，请检查格式" | 确认文件未损坏且格式受支持 |
| `E_EMPTY_FILE` | 文件内容为空 | "文件内容为空，请更换文件" | 检查文件是否包含有效文本 |
| `E_NO_NAME` | 无法提取人物姓名 | "未识别到人物姓名，使用文件名替代" | 确认文件名有意义或手动指定 |
| `E_LOW_CONF` | 置信度过低 | "信息不足，输出包含占位符" | 补充资料或接受占位符 |
| `E_BATCH_ABORT` | 批量处理中止 | "批量处理中止，请检查错误日志" | 查看 `execution_log.md` 定位问题 |
| `E_OUTPUT_FAIL` | 输出文件写入失败 | "无法写入输出文件" | 确认目录有写权限 |

### 5.2 错误处理流程

```
遇到错误
  ↓
记录错误码与上下文至 execution_log.md
  ↓
向用户展示错误提示
  ↓
根据错误码执行修正步骤
  ↓
修正后重新执行
```

## 六、FAQ 反模式

### 6.1 常见坑与反模式对照

| 坑 | 反模式（错误做法） | 正模式（正确做法） |
|----|-------------------|-------------------|
| 过度解读 | 从一句话推断整个价值观体系 | 仅提取有明确语言标记的信念 |
| 时间混淆 | 将不同时间点的观点混为一谈 | 标注每条信念的时间戳 |
| 人物混淆 | 多人物资料合并处理 | 严格一人一档 |
| 信息编造 | 信息不足时自行补全 | 使用 `[需核实:字段]` 占位 |
| 忽略上下文 | 断章取义提取观点 | 保留场景描述与上下文 |
| 过度结构化 | 强行套用模板导致失真 | 根据资料特点调整输出结构 |

### 6.2 用户常见疑问

**Q1：资料中有多个人物怎么办？**
A：每个文件只提取一个主要人物。若资料包含多个人物，优先提取出现频率最高者，并在档案中标注其他人物为"关联人物"。

**Q2：资料是英文的可以处理吗？**
A：可以。蒸馏算法支持中英文混合文本，但输出档案默认使用中文，除非用户指定使用英文输出。

**Q3：处理后的档案可以二次编辑吗？**
A：可以。输出档案为标准 Markdown 格式，用户可自由编辑、扩展或重新组织内容。

**Q4：批量处理时某个文件失败了怎么办？**
A：失败文件会记录错误码并跳过，不影响其他文件的处理。处理完成后会生成错误报告，用户可针对失败文件单独重试。
