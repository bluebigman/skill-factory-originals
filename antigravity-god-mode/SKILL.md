## 三、标准执行流程

### 前置条件

| 条件项 | 要求 |
|--------|------|
| 输入来源 | 用户提供文本 / 文件路径 / URL |
| 输入格式 | 文本类（.txt/.md/.csv/.json）或可直接粘贴的纯文本 |
| 输出格式要求 | 用户需明确指定（JSON/CSV/Markdown 表格/纯文本列表）或使用默认 JSON |
| 必要参数 | 无强制参数，但建议提供字段映射说明（如"把'日期'列映射为 date 字段"） |

### 执行步骤（分步编号）

1. **收集输入并确认格式**
   - 接收用户提供的文本、文件或 URL
   - 确认输出格式（若未指定，默认输出 JSON）
   - 示例：用户输入一段包含多个日期的会议记录，要求输出为表格

2. **解析输入内容**
   - 识别输入类型（纯文本 / CSV 结构 / JSON 结构 / 网页文本）
   - 提取关键信息：实体、数字、日期、状态词、重复出现的模式
   - 示例：从会议记录中识别出日期（2026-03-15）、参会人（张三/李四）、议题（预算审查）

3. **按规则处理**
   - 规则 A：字段映射——将识别出的信息按用户指定的字段名归类
   - 规则 B：去重合并——相同实体出现多次时合并，保留最新值
   - 规则 C：格式标准化——日期统一为 YYYY-MM-DD，数字去除千分位逗号
   - 示例：将"3月15号"标准化为"2026-03-15"

4. **生成结果并标注置信度**
   - 对每个字段标注置信度：高（明确出现且无歧义）、中（存在但格式不规范）、低（推测得出）
   - 示例：`{"date": "2026-03-15", "confidence": "high"}`

5. **输出与自查**
   - 按约定格式输出完整结果
   - 自查清单：
     - [ ] 所有字段是否完整
     - [ ] 格式是否符合用户要求
     - [ ] 置信度标注是否齐全
     - [ ] 是否有遗漏的关键信息

6. **二次确认（仅在必要时）**
   - 当出现以下情况时向用户确认：
     - 同一字段存在多个可能值且无法判定优先级
     - 输入格式严重不符合预期
     - 用户未指定输出格式

### 输出规范

| 输出格式 | 结构要求 | 示例 |
|----------|----------|------|
| JSON | 数组或对象，每个字段含 value 与 confidence | `[{"name": {"value": "张三", "confidence": "high"}}]` |
| CSV | 首行为表头，每行一条记录 | `name,date,confidence` |
| Markdown 表格 | 表头加分隔行，每行一条记录 | `\| 姓名 \| 日期 \| 置信度 \|` |
| 纯文本列表 | 每行一条记录，字段用 `\|` 分隔 | `张三 \| 2026-03-15 \| 高` |

## 四、置信度门控机制

### 基本原则

- **不编造**：当输入中不存在某字段时，不猜测值，输出 `[需核实:字段名]` 占位
- **明确标注**：每个字段必须附带置信度等级
- **低置信度提示**：当置信度为"低"时，在输出末尾附加说明，解释推测依据

### 置信度等级定义

| 等级 | 判定标准 | 示例 |
|------|----------|------|
| 高 | 字段值在输入中明确出现，无歧义 | 输入"2026年3月15日"，输出 date=2026-03-15 |
| 中 | 字段值存在但格式不规范，需标准化 | 输入"3/15"，输出 date=2026-03-15（年份为推测） |
| 低 | 字段值由上下文推测得出 | 输入"下周一开会"，输出 date=2026-03-16（基于当前日期推测） |

### 占位符使用规则

- 当输入中完全找不到某字段时，使用 `[需核实:字段名]` 占位
- 占位字段的 confidence 固定为 "low"
- 输出末尾追加提示：`注意：以下字段需人工核实：[字段名列表]`

### 用户常见疑问

**Q1：输入内容包含敏感信息，处理后会泄露吗？**
A：本技能在本地处理，不传输数据。但建议敏感信息脱敏后再输入。

**Q2：可以处理 Excel 文件吗？**
A：不支持 .xlsx 格式。请将 Excel 导出为 CSV 后再输入。

**Q3：输出结果可以自定义字段顺序吗？**
A：可以。在输入时说明字段顺序，例如"按日期、姓名、金额的顺序输出"。

**Q4：批量处理有数量限制吗？**
A：单次建议不超过 500 条记录，超过时建议分批处理。
