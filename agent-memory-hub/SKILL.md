## 三、标准流程

### 3.1 前置条件

| 条件编号 | 条件内容 | 缺失时处理 |
|----------|----------|-----------|
| P1 | 明确输入材料类型（对话/文档/代码/混合） | 交互式询问，最多追问 2 次 |
| P2 | 输入材料可读取（非加密、非损坏） | 返回错误码 E-1001 |
| P3 | 明确输出目标（摘要/索引/图谱/归档） | 默认输出全部四类资产 |
| P4 | 明确使用场景（个人/团队） | 团队场景自动附加共享索引生成步骤 |

### 3.2 执行步骤

#### 步骤 1：输入解析（耗时占比 5%）

1. 识别输入材料类型（对话文本、文档文件、代码路径、混合输入）
2. 提取关键元数据：来源、时间、涉及主题、参与者（如适用）
3. 若输入为路径，检查路径可访问性

**参数表：**

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| input_type | string | 否 | auto | auto/dialogue/document/code/mixed |
| output_scope | string | 否 | all | all/facts/process/decisions/experience |
| team_mode | boolean | 否 | false | 是否生成团队共享索引 |
| language | string | 否 | zh | 输出语言 |

#### 步骤 2：内容拆解（耗时占比 25%）

1. 将输入材料按语义边界切分为独立信息单元
2. 每个信息单元标注类型：事实（Fact）、流程（Process）、决策（Decision）、经验（Experience）
3. 对代码类输入，按模块/函数/类进行结构拆解

**四类记忆资产定义：**

| 资产类型 | 定义 | 示例 |
|----------|------|------|
| 事实（Fact） | 客观存在的状态、数据、定义 | "系统当前用户量为 10 万" |
| 流程（Process） | 操作步骤、执行路径、方法 | "部署流程：构建→测试→发布" |
| 决策（Decision） | 已做出的选择及理由 | "选用 PostgreSQL 因事务支持完善" |
| 经验（Experience） | 教训、心得、优化建议 | "高峰期勿做全表扫描，会锁库" |

#### 步骤 3：结构化整理（耗时占比 30%）

1. 对每个信息单元进行清洗：去重、去口语化、补全指代
2. 建立信息单元之间的关联关系（引用、因果、时序）
3. 按四类资产分别生成结构化卡片

**输出卡片模板：**

```markdown
### [资产类型] 卡片标题
- **核心内容**：一句话概括
- **详细描述**：2-5 句展开说明
- **来源**：输入材料中的位置标识
- **关联卡片**：相关卡片 ID 列表
- **置信度**：高/中/低（低置信度时标注 [需核实:字段]）
```

#### 步骤 4：索引生成（耗时占比 20%）

1. 汇总所有卡片，生成分类标签体系
2. 提取检索关键词（每张卡片 3-5 个）
3. 生成团队共享索引文件（Markdown 格式）

**索引文件结构：**

```markdown
# 团队知识索引
> 生成时间：YYYY-MM-DD HH:mm
> 资产总数：N

## 分类导航
- 事实资产（n 条）
- 流程资产（n 条）
- 决策资产（n 条）
- 经验资产（n 条）

## 关键词索引
| 关键词 | 关联卡片 | 资产类型 |
|--------|----------|----------|
| 部署 | CARD-001, CARD-004 | 流程 |

## 卡片列表
（按资产类型分组列出全部卡片）
```

#### 步骤 5：质量校验与输出（耗时占比 20%）

1. 检查所有信息单元是否已归类
2. 检查置信度标注是否完整
3. 检查索引文件链接是否有效
4. 输出最终结果 + 下一步建议

### 3.3 输出规范

## 四、置信度门控

### 4.1 置信度分级

| 级别 | 定义 | 输出标记 |
|------|------|----------|
| 高 | 信息在输入材料中有明确直接表述 | 无特殊标记 |
| 中 | 信息可从输入材料中合理推断 | 无特殊标记，但会在描述中注明推断依据 |
| 低 | 信息缺失、模糊或存在多种解释 | 标注 [需核实:字段名] |

### 4.2 需核实场景示例

| 场景 | 输出示例 |
|------|----------|
| 对话中提及"下周三上线"但未说明具体日期 | "上线时间：[需核实:具体日期]，对话中仅提及'下周三'" |
| 代码中调用外部 API 但无文档说明 | "外部依赖：[需核实:API 用途]，函数 `fetchData()` 调用了未注释的端点" |
| 文档中引用图表但图表未提供 | "数据来源：[需核实:图表编号]，正文引用图 3 但未提供图表内容" |

### 4.3 禁止行为

- 禁止编造缺失信息
- 禁止猜测数字、日期、人名
- 禁止将推断信息标注为事实

### 6.1 常见坑
