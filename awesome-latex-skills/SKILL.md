## 三、标准工作流程

### 前置条件

- 输入文件编码建议为 UTF-8（非 UTF-8 需提前说明）
- 错误诊断时需提供**完整**日志（至少包含前 30 行错误信息）

### 执行步骤（分步编号）

#### 流程 A：编译错误修复

1. **接收输入**：收集错误日志、源文件、编译引擎信息（pdflatex/xelatex/lualatex）
2. **错误分类**：按以下优先级排序——
   - 致命错误（缺少 `\begin{document}`、未定义控制序列）
   - 警告类（Overfull hbox、未定义引用）
   - 环境问题（缺少宏包、版本冲突）
3. **定位根因**：逐条分析错误日志，映射到源文件具体行号
4. **生成修复方案**：
   - 提供最小化修改补丁（diff 格式）
   - 说明修改理由（为什么这样改）
   - 标注风险等级（低/中/高）
5. **输出修复报告**：包含错误统计表、修复前后对比、验证建议

#### 流程 B：论文解析

1. **输入确认**：确认文件格式（PDF/TeX/URL）
2. **结构提取**：识别标题、作者、摘要、章节层级、参考文献
3. **内容分析**：
   - 抽取核心论点（每章 1-2 句概括）
   - 标记关键公式（编号 + 物理含义）
   - 提取图表标题与结论
4. **输出结构化摘要**：Markdown 格式，包含元信息表 + 章节摘要 + 公式索引

#### 流程 C：格式适配

1. **确认目标**：获取期刊/会议官方模板信息（如 IEEEtran、ACM、Elsevier）
2. **差异分析**：对比当前文档类与目标模板的差异点
3. **生成适配方案**：
   - 文档类替换建议（含参数配置）
   - 宏包增删清单
   - 参考文献样式调整（.bst 文件）
4. **输出适配报告**：逐项列出修改点 + 示例代码

## 五、错误码体系

| 错误码 | 含义 | 提示话术 | 修正步骤 |
|--------|------|----------|----------|
| `LERR-001` | 缺少 `\begin{document}` | "文档缺少正文开始标记" | 在 preamble 末尾添加 `\begin{document}` |
| `LERR-002` | 未定义的控制序列 | "第 X 行使用了未定义的命令 `\foo`" | 检查拼写或添加对应宏包 |
| `LERR-003` | 环境不匹配 | "`\begin{itemize}` 缺少对应的 `\end{itemize}`" | 检查环境配对，使用编辑器自动补全 |
| `LERR-004` | 宏包冲突 | "`\usepackage{amsmath}` 与 `\usepackage{mathtools}` 冲突" | 移除其中一个，或调整加载顺序 |
| `LERR-005` | 参考文献格式错误 | "`.bib` 文件第 X 行缺少必填字段" | 补充 `author` 或 `year` 字段 |
| `LERR-006` | 图片文件缺失 | "无法找到 `figure.png`" | 检查文件路径或使用相对路径 |
| `LERR-007` | 编码问题 | "文件包含非 UTF-8 字符" | 使用 `iconv` 转换编码 |
| `LERR-008` | 表格列数不匹配 | "表格第 X 行有 Y 列，但声明只有 Z 列" | 调整 `&` 分隔符数量 |

## 六、常见坑与反模式对照（FAQ）

### 坑 1：盲目添加宏包

**错误做法**：遇到任何错误都尝试 `\usepackage{...}` 解决。

**正确姿势**：先确认错误根因，宏包只是解决方案之一。例如 `Undefined control sequence` 可能是拼写错误而非缺少宏包。

### 坑 2：忽略警告信息

**错误做法**：只关注红色错误，忽略黄色警告。

**正确姿势**：`Overfull \hbox` 警告虽然不影响编译，但可能导致排版溢出。建议处理所有警告后再提交。

### 坑 3：直接复制 StackExchange 代码

**错误做法**：从问答网站复制代码而不理解上下文。

**正确姿势**：检查代码中的宏包依赖、编译引擎要求，并在本地测试后再使用。

### 坑 4：修改 .cls 文件

**错误做法**：直接修改模板类文件来适配格式。

**正确姿势**：优先通过 `\documentclass` 参数或 preamble 中的设置调整，避免修改核心类文件。

### 坑 5：忽略编译引擎差异

**错误做法**：假设所有引擎行为一致。

**正确姿势**：确认目标投稿渠道要求的引擎（多数期刊要求 pdflatex，部分人文类要求 xelatex），并在对应引擎下测试。
