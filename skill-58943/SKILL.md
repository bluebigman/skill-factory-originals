## 三、标准作业流程（SOP）

### 3.1 前置条件

在启动任何流程前，请确认以下条件已满足：

| 条件项 | 要求 | 检查方法 |
|--------|------|----------|
| 数据格式 | 纯文本（.txt）、CSV（.csv）、Excel（.xlsx/.xls） | 查看文件扩展名 |
| 数据内容 | 必须包含可识别的文本信息（非空文件） | 打开文件目视检查 |
| 数据来源 | 用户已合法获取的数据（自行采集或 API 获取） | 确认数据来源合规 |
| 环境要求 | 无特殊环境依赖，纯文本处理 | 无需安装额外软件 |

### 3.2 执行步骤

#### 步骤 1：数据接收与格式识别

1. 接收用户输入的数据（文件路径或直接粘贴文本内容）
2. 识别数据格式：
   - 若为文件，检查扩展名（.txt/.csv/.xlsx/.xls）
   - 若为直接粘贴文本，按纯文本处理
3. 检查数据是否为空或明显损坏

**参数表：**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `data_source` | string | 是 | 文件路径或文本内容 |
| `data_format` | string | 否 | 手动指定格式（txt/csv/excel），默认自动识别 |
| `encoding` | string | 否 | 文件编码（utf-8/gbk），默认 utf-8 |

**示例：**

```
输入：data_source="./data/20260812_舆情原始数据.csv"
识别结果：CSV 格式，编码 utf-8，共 156 行数据（含表头）
```

#### 步骤 2：数据解析与字段映射

1. 根据格式解析数据：
   - TXT：按行分割，每行视为一条舆情记录
   - CSV：按逗号分割，首行为表头
   - Excel：读取第一个工作表，首行为表头
2. 将原始字段映射到标准字段：

| 标准字段 | 类型 | 必填 | 说明 | 示例 |
|----------|------|------|------|------|
| `id` | string | 是 | 唯一标识（自动生成或取原 ID） | "OP-20260812-001" |
| `timestamp` | string | 是 | 发布时间（ISO 8601 格式） | "2026-08-12T14:30:00+08:00" |
| `source` | string | 是 | 发布渠道（枚举值见下表） | "weibo" |
| `author` | string | 否 | 发布者名称 | "用户_abc123" |
| `content` | string | 是 | 舆情文本内容 | "某品牌产品质量出现问题..." |
| `sentiment` | string | 是 | 情绪倾向（枚举值见下表） | "negative" |
| `heat_score` | number | 否 | 热度评分（0-100） | 78.5 |
| `url` | string | 否 | 原始链接 | "https://..." |

**渠道枚举值（source）：**

| 枚举值 | 含义 |
|--------|------|
| `weibo` | 微博 |
| `douyin` | 抖音 |
| `zhihu` | 知乎 |
| `wechat` | 微信公众号 |
| `news` | 新闻网站 |
| `forum` | 论坛 |
| `other` | 其他 |

**情绪枚举值（sentiment）：**

| 枚举值 | 含义 | 判定规则（关键词示例） |
|--------|------|------------------------|
| `positive` | 正面 | 好评、点赞、推荐、满意 |
| `negative` | 负面 | 差评、投诉、曝光、维权 |
| `neutral` | 中性 | 无明确情绪词，或陈述事实 |
| `mixed` | 混合 | 同时包含正负面关键词 |

#### 步骤 3：数据清洗与标准化

1. 时间格式统一：将各种时间格式（如 "2026/08/12"、"8月12日"）转换为 ISO 8601 格式
2. 渠道名称标准化：将 "新浪微博"、"微博" 统一为 `weibo`
3. 文本清理：去除多余空格、HTML 标签、特殊符号
4. 情绪初判：基于关键词规则库进行情绪倾向标注

**情绪判定规则示例（简化版）：**

```
负面关键词：投诉、曝光、维权、差评、质量问题、欺诈、虚假
正面关键词：好评、点赞、推荐、满意、优质、可靠
判定逻辑：
  1. 若同时命中正负面关键词 → mixed
  2. 若仅命中负面关键词 → negative
  3. 若仅命中正面关键词 → positive
  4. 若均未命中 → neutral
```

#### 步骤 4：结构化输出

1. 生成标准化 JSON 数据（每条记录包含 schema 版本号）
2. 输出格式：

```json
{
  "schema_version": "1.0",
  "generated_at": "2026-08-12T15:00:00+08:00",
  "total_records": 156,
  "records": [
    {
      "id": "OP-20260812-001",
      "timestamp": "2026-08-12T14:30:00+08:00",
      "source": "weibo",
      "author": "用户_abc123",
      "content": "某品牌产品质量出现问题，已向消协投诉。",
      "sentiment": "negative",
      "heat_score": 78.5,
      "url": "https://weibo.com/xxx"
    }
  ]
}
```

#### 步骤 5：校验与报告生成

1. 对输出的 JSON 数据进行一致性校验（见第五节错误码体系）
2. 根据用户需求生成最终交付物：
   - 若需台账：生成 Markdown 分类汇总表
   - 若需简报：生成舆情简报草稿
   - 若需对接系统：输出 JSON 文件

### 3.3 输出规范

| 输出类型 | 格式 | 适用场景 |
|----------|------|----------|
| 标准化数据 | JSON 文件 | 系统对接、数据入库 |
| 舆情台账 | Markdown 表格 | 人工查阅、会议汇报 |
| 舆情简报 | Markdown 文档 | 日报/周报、管理层汇报 |

## 四、置信度门控机制

当处理过程中出现信息不足或不确定的情况时，本 Skill 将遵循以下原则：

### 4.1 占位符规则

| 场景 | 占位符 | 示例 |
|------|--------|------|
| 时间信息缺失 | `[需核实:timestamp]` | "发布事件：[需核实:timestamp]" |
| 渠道无法识别 | `[需核实:source]` | "来源渠道：[需核实:source]" |
| 情绪无法判定 | `[需核实:sentiment]` | "情绪倾向：[需核实:sentiment]" |
| 热度数据缺失 | `[需核实:heat_score]` | "热度评分：[需核实:heat_score]" |
| 内容不完整 | `[需核实:content]` | "正文内容：[需核实:content]" |

### 4.2 使用原则

1. **绝不编造**：当字段无法从原始数据中提取时，必须使用占位符，不得自行虚构
2. **明确标注**：所有占位符必须在输出中保持可见，不得静默忽略
3. **汇总提示**：在输出末尾附上"需核实字段清单"，方便用户快速定位

**示例：**

```
需核实字段清单：
1. 记录 OP-20260812-003：timestamp 缺失，原始数据中无时间信息
2. 记录 OP-20260812-007：source 无法识别，原始数据中渠道为"某平台"
3. 记录 OP-20260812-012：sentiment 无法判定，文本过于简短
```

## 五、错误码体系

### 5.1 错误码总表

| 错误码 | 错误类型 | 说明 | 提示话术 | 修正步骤 |
|--------|----------|------|----------|----------|
| E-001 | 文件不存在 | 指定的文件路径无效 | "未找到指定文件，请检查路径是否正确" | 1. 确认文件路径；2. 检查文件名拼写；3. 确认文件是否已移动或删除 |
| E-002 | 格式不支持 | 文件扩展名不在支持范围内 | "暂不支持该文件格式，请使用 TXT/CSV/Excel 格式" | 1. 将文件转换为支持的格式；2. 或直接粘贴文本内容 |
| E-003 | 数据为空 | 文件内容为空或仅有表头 | "数据内容为空，请检查源文件" | 1. 确认源文件是否有数据；2. 检查是否选错工作表 |
| E-004 | 编码错误 | 文件编码无法识别 | "文件编码无法识别，请指定编码格式" | 1. 使用 `encoding` 参数指定编码；2. 尝试将文件另存为 UTF-8 编码 |
| E-005 | 字段缺失 | 必填字段（timestamp/source/content）缺失 | "缺少必填字段：{字段名}" | 1. 检查原始数据表头；2. 补充缺失字段或调整映射关系 |
| E-006 | 时间格式错误 | 时间字段无法解析 | "时间格式无法解析：{原始值}" | 1. 手动指定时间格式；2. 或使用占位符 `[需核实:timestamp]` |
| E-007 | 渠道值非法 | source 字段不在枚举值内 | "渠道值不在支持范围内：{原始值}" | 1. 映射到 `other` 枚举值；2. 或补充枚举值定义 |
| E-008 | 情绪判定失败 | 文本过短或无语义信息 | "情绪无法判定，文本内容过短" | 1. 使用占位符 `[需核实:sentiment]`；2. 或人工补充标注 |
| E-009 | 数据量超限 | 单次处理超过 10000 条记录 | "单次处理上限为 10000 条，当前 {实际数量} 条" | 1. 分批处理；2. 或使用数据筛选功能减少数据量 |
| E-010 | 输出冲突 | 用户同时要求多种不兼容的输出格式 | "输出格式冲突，请选择单一输出类型" | 1. 明确输出优先级；2. 或分多次执行 |

| 编号 | 常见坑位 | 反模式（错误做法） | 正确做法 |
