## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 |
|------|------|
| 输入类型 | 文本内容、文件路径、URL 地址（三者至少其一） |
| 文件编码 | UTF-8（其他编码需先转换） |
| 文件大小 | 单文件 ≤ 100K Token（超出需分块，见「七、高级用法」） |
| 网络 | 处理 URL 时需要可访问外网 |

### 3.2 执行步骤

**Step 1：识别输入类型**

| 输入特征 | 判定类型 |
|----------|----------|
| 以 `http://` 或 `https://` 开头 | URL |
| 以 `.py` `.js` `.ts` `.java` `.go` `.rs` `.c` `.cpp` `.h` 结尾 | 代码文件 |
| 以 `.md` `.txt` `.json` `.yaml` `.yml` `.log` 结尾 | 文本文件 |
| 无扩展名且内容含代码特征（如 `def` `function` `class`） | 代码文本 |
| 无扩展名且内容含对话特征（如 `用户:` `assistant:`） | 对话文本 |
| 无法识别 | **暂停**，向用户确认输入类型 |

**Step 2：读取内容**

- 单文件：直接读取
- 多文件：逐个读取，单个失败不影响其他文件
- URL：发起 HTTP 请求获取内容
- 文本：直接使用传入内容

**Step 3：预处理**

| 操作 | 说明 |
|------|------|
| 去除 BOM 头 | 移除文件开头的 `\ufeff` |
| 统一换行符 | 将 `\r\n` 统一为 `\n` |
| 去除首尾空白 | 移除内容首尾的空行与空格 |
| 识别语言类型 | 根据扩展名或内容特征判断代码语言 |

**Step 4：压缩处理**

按策略执行（详见下表）：

| 策略 | 保留内容 | 移除内容 | 压缩率参考 |
|------|----------|----------|------------|
| 保守（conservative） | 全部代码、全部注释、全部空行 | 无 | 0%（仅格式化） |
| 标准（standard） | 全部代码、关键注释（含 TODO/FIXME）、单空行 | 冗余注释、连续空行、调试日志 | 30%-50% |
| 激进（aggressive） | 函数签名、类定义、核心逻辑、字符串字面量 | 全部注释、全部空行、类型注解、文档字符串 | 60%-80% |

**Step 5：置信度标注**

- 压缩过程中无法明确推断的内容，输出 `[需核实:字段名]` 占位符
- 中低置信度的推断内容，标注推断依据（如 `基于函数名推断`）

**Step 6：输出整理**

按指定格式输出（默认 Markdown）：

| 格式 | 适用场景 |
|------|----------|
| Markdown | 人类阅读、文档记录 |
| JSON | 程序化处理、下游工具对接 |
| 纯文本 | 快速复制、粘贴到其他工具 |

### 3.3 输出规范

**Markdown 输出模板：**

```markdown
# 压缩结果

## 输入信息
- 输入类型：代码文件 / 对话文本 / URL
- 文件数量：N
- 原始大小：X KB / Y Token

## 压缩摘要
- 压缩策略：标准
- 压缩后大小：Z KB / W Token
- 压缩率：P%

## 压缩内容
（此处为压缩后的实际内容）

## 失败清单
（如有失败项，列出文件/URL 及失败原因）

## 置信度说明
- 高置信度内容：直接输出
- 中低置信度内容：已标注推断依据
- 需核实内容：已标注 `[需核实:字段名]`
```

## 五、错误码体系

### 5.1 错误码速查表

| 错误码 | 含义 | 提示话术 | 修正步骤 |
|--------|------|----------|----------|
| E001 | 输入为空 | "未检测到有效输入，请提供文本、文件路径或 URL" | 检查输入内容是否为空 |
| E002 | 文件不存在 | "文件 {path} 不存在，请确认路径是否正确" | 检查路径拼写与文件位置 |
| E003 | 网络错误 | "请求 {url} 失败：{原因}" | 自动重试 3 次，间隔 2 秒；仍失败则列入失败清单 |
| E004 | 文件编码不支持 | "文件 {path} 编码无法识别，请转换为 UTF-8" | 使用 `iconv` 或编辑器转换编码 |
| E005 | 文件过大 | "文件 {path} 超过 100K Token 限制，建议分块处理" | 使用分块压缩（见「七、高级用法」） |
| E006 | 输入类型无法识别 | "无法识别输入类型，请确认是代码、对话还是文档" | 暂停处理，向用户确认 |
| E007 | 压缩策略执行失败 | "策略 {strategy} 执行失败，正在降级" | 自动降级为下一级策略 |

### 5.2 错误处理策略

| 策略 | 适用场景 | 执行方式 |
|------|----------|----------|
| 重试 | 网络类错误（E003） | 自动重试 3 次，间隔 2 秒 |
| 降级 | 压缩策略失败（E007） | 激进 → 标准 → 保守，逐级降级 |
| 跳过 | 批量处理中单个文件失败 | 不中断整体流程，失败项列入失败清单 |

### 5.3 失败透明原则

- 处理失败的文件/URL 必须列入失败清单，不静默跳过
- 失败清单包含：文件/URL 路径、错误码、失败原因、建议操作

## 六、FAQ 反模式

### 6.1 常见坑与反模式对照

| 常见坑 | 反模式（错误做法） | 正模式（正确做法） |
|--------|-------------------|-------------------|
| 压缩后丢失关键信息 | 直接使用激进策略压缩所有内容 | 先评估内容重要性，对关键部分使用 `--keep` 保留 |
| 输入类型判断错误 | 将对话文本当作代码处理 | 先确认输入类型，再选择压缩策略 |
| 忽略失败项 | 批量处理时跳过失败文件不报告 | 将失败项列入失败清单，最后统一处理 |
| 过度依赖压缩结果 | 将压缩结果直接用于代码审查 | 压缩结果仅作参考，审查时需对照原始代码 |
| 不检查置信度标注 | 直接使用带 `[需核实]` 的内容 | 先核实标注内容，再决定是否使用 |

### 6.2 反模式示例

**反模式 1：盲目激进压缩**

```text
用户：把这段代码压缩到极致
错误做法：直接使用激进策略，删除了所有注释和类型注解
结果：代码可读性大幅下降，且丢失了关键的类型信息
正确做法：使用激进策略但通过 --keep 保留类型注解
```

**反模式 2：忽略失败清单**

```text
用户：压缩这 10 个文件
错误做法：3 个文件失败后，直接输出 7 个成功的结果
结果：用户不知道有 3 个文件未处理
正确做法：输出 7 个成功结果 + 3 个失败清单（含原因和建议）
```

## 七、高级用法

### 7.1 参数化配置

| 参数 | 可选值 | 默认值 | 说明 |
|------|--------|--------|------|
| `--strategy` | `conservative` / `standard` / `aggressive` | `standard` | 压缩策略 |
| `--format` | `markdown` / `json` / `text` | `markdown` | 输出格式 |
| `--keep` | 逗号分隔的保留规则列表 | 空 | 自定义保留规则 |
| `--chunk-size` | 数字（Token 数） | 100000 | 分块大小 |
| `--output` | 文件路径 | 空（输出到终端） | 输出文件路径 |

### 7.2 `--keep` 参数用法

| 保留规则 | 说明 | 示例 |
|----------|------|------|
| `comments` | 保留全部注释 | `--keep comments` |
| `docstrings` | 保留文档字符串 | `--keep docstrings` |
| `type_annotations` | 保留类型注解 | `--keep type_annotations` |
| `function_bodies` | 保留全部函数体 | `--keep function_bodies` |
| `debug_logs` | 保留调试日志 | `--keep debug_logs` |
| `all` | 保留全部内容（等效保守策略） | `--keep all` |

### 7.3 分块压缩（超大文件）

当文件超过 100K Token 时，使用分块压缩：

```text
1. 将文件按 --chunk-size 切分为多个块
2. 对每个块独立执行压缩
3. 将各块压缩结果合并输出
4. 在输出中标注分块边界
```

### 7.4 与其他 Skill 串联

| 串联场景 | 操作方式 |
|----------|----------|
| 压缩代码 → 代码审查 | 将压缩结果送入代码审查 Skill，快速定位问题 |
| 压缩对话历史 → 决策记录 | 将要点送入决策记录 Skill，沉淀团队知识 |
| 压缩文档 → 知识库整理 | 将摘要送入知识库整理 Skill，建立索引 |

### 7.5 脚本化批量处理

结合 `--format json` 输出，可编写脚本自动化批量压缩任务：

```bash
# 示例：批量压缩项目中的所有 Python 文件
rtk-token-saver --strategy aggressive --format json --output result.json src/*.py
```
