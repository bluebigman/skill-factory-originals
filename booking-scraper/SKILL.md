## 三、标准处理流程

### 3.1 前置条件

- 输入文本为 UTF-8 编码纯文本
- 每条记录之间用空行或 `---` 分隔
- 单次提交不超过 50 条记录
- 文本内容涉及酒店相关信息（名称、价格、地址、评分等）

### 3.2 执行步骤

**步骤 1：输入预处理**

接收用户文本，检查格式合法性：

```
输入检查清单：
□ 是否为纯文本（非图片/PDF/链接）
□ 是否包含至少 1 条完整记录
□ 记录分隔符是否为空行或 ---
□ 记录条数是否 ≤ 50
```

若格式不合法，返回错误码 `ERR_INPUT_FORMAT`。

**步骤 2：字段识别**

对每条记录执行字段提取。默认提取字段如下：

| 字段名 | 说明 | 示例 |
|--------|------|------|
| `hotel_name` | 酒店名称 | 香格里拉大酒店 |
| `price_per_night` | 每晚价格（数字） | 800 |
| `rating` | 评分（0-10 或 0-5） | 8.5 |
| `address` | 地址 | 上海市静安区南京西路 123 号 |
| `amenities` | 设施（逗号分隔） | 泳池,健身房,免费WiFi |
| `booking_source` | 来源平台 | Booking.com |

**步骤 3：置信度评估**

对每个提取的字段进行置信度判断：

| 原文情况 | 处理方式 |
|----------|----------|
| 明确数值（如"800 元"） | 直接提取为 `800` |
| 模糊数值（如"约 800 元"） | 提取为 `[需核实:price_per_night]` |
| 范围数值（如"800-1000 元"） | 提取为 `[需核实:price_per_night]` |
| 缺失字段 | 标注 `[无法提取:字段名]` |
| 多个候选值 | 标注 `[需核实:字段名]` |

**步骤 4：输出生成**

根据用户指定格式输出：

- **默认**：CSV 格式（UTF-8 编码，逗号分隔）
- **可选**：JSON 数组格式
- **可选**：Markdown 表格格式

**步骤 5：质量检查**

输出前自动检查：

```
□ 所有字段是否来自原文（无编造）
□ 模糊信息是否已标注 [需核实:...]

```
