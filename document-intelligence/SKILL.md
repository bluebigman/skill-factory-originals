本技能面向需要将非结构化或半结构化内容转换为规范结构化数据的场景。以下是能力边界的一页纸说明。

### 1.1 能做什么

| 编号 | 能力项 | 说明 | 适用示例 |
|------|--------|------|----------|
| C1 | 输入解析 | 接受用户提供的文件路径、URL 或直接粘贴的文本数据 | 解析一份 PDF 报告、读取网页内容、处理 CSV 文件 |

| C3 | 结构化输出 | 按约定格式（JSON/表格/自定义模板）生成结果 | 输出为 JSON 数组，每条记录含指定字段 |
| C4 | 置信度标注 | 对每个提取字段给出可信程度标记 | 字段值后附加 `confidence: 0.95` |
| C5 | 批量与自定义 | 支持多文件批量处理，允许用户自定义输出格式 | 一次处理 100 份发票，输出格式按用户模板 |

### 1.2 不能做什么

| 编号 | 限制项 | 说明 |

| L1 | 不执行外部操作 | 不发送网络请求、不调用第三方 API、不修改源文件 |

## 三、标准处理流程

### 3.1 前置条件

| 条件项 | 要求 | 说明 |
|--------|------|------|
| 输入来源 | 文件路径 / URL / 直接文本 | 文件需可访问，URL 需可读取 |
| 文件命名 | 建议统一命名规范 | 如 `input_01.pdf`、`input_02.pdf` |
| 输出格式 | 明确指定或使用默认 JSON | 默认格式见 3.3 节 |
| 字段定义 | 明确需要提取的字段列表 | 未指定时使用通用字段集 |

### 3.2 执行步骤

**步骤 1：准备输入**

将待处理文件放入当前工作目录，确认文件命名规范一致。若输入为 URL，确认链接可访问。若为直接文本，确认内容完整。

**步骤 2：单样本试运行**

先用一个样本文件执行完整流程，核对输出字段与格式是否符合预期。检查项包括：

- 字段名称是否正确
- 字段类型是否符合预期（字符串/数字/日期）
- 置信度标注是否合理
- 输出格式是否为约定的 JSON 或表格

**步骤 3：批量执行**

单样本验证通过后，对全量数据执行处理。处理过程中保留原始文件备份，不修改源文件。

**步骤 4：结果校验**

抽查输出条目，核对关键字段与源数据的一致性。建议抽查比例不低于 10%。若发现系统性偏差，回到步骤 2 调整参数后重新执行。

### 3.3 输出规范

默认输出为 JSON 格式，结构如下：


| processed_at | string | 是 | 处理时间（ISO 8601） |

| fields | object | 是 | 提取的字段集合 |
| value | any | 是 | 字段提取值 |

## 四、置信度门控机制

### 4.1 置信度分级

| 置信度范围 | 等级 | 含义 | 处理建议 |
|-----------|------|------|----------|
| 0.90 ~ 1.00 | 高 | 提取结果可靠 | 可直接使用 |
| 0.70 ~ 0.89 | 中 | 提取结果较可靠 | 建议人工复核 |
| 0.50 ~ 0.69 | 低 | 提取结果存在不确定性 | 必须人工确认 |
| < 0.50 | 极低 | 提取结果不可靠 | 标记为需核实 |

### 4.2 信息不足时的处理

当输入信息不足以确定某个字段值时，**不编造内容**，按以下规则处理：

- 输出占位符 `[需核实:字段名]`
- 置信度设为 `0`
- 在 `note` 字段中说明缺失原因

示例：

```json
{
  "fields": {
    "contract_amount": {
      "value": "[需核实:contract_amount]",
      "confidence": 0,
      "note": "源文件中未找到金额相关信息"
    }
  }
}
```

### 4.3 冲突检测

当同一字段在输入中出现多个不一致的值时：

1. 取置信度最高的值作为输出
2. 在 `note` 中列出所有冲突值
3. 若最高置信度低于 0.70，整体标记为需核实
