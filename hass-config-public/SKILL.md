### 3.2 执行步骤

**Step 1 — 准备输入**

将配置文件保存为 `.yaml` 格式，确保文件头部包含 `views:` 或 `cards:` 顶层键。示例：

```yaml
views:
  - title: 客厅
    cards:
      - type: entities
        entities:
          - entity: light.living_room
          - entity: sensor.temperature
```

**Step 2 — 运行解析命令**

单文件模式：

```bash
python hass_parser.py --input dashboard.yaml --output report.md
```

批量模式：

```bash
python hass_parser.py --input-dir ./configs/ --output ./reports/
```

自检模式：

```bash
python hass_parser.py --selftest
```

版本查询：

```bash
python hass_parser.py --version
```

**Step 3 — 查看输出报告**

报告包含以下章节：

| 章节 | 内容 |
|------|------|
| 概览统计 | 视图数、卡片总数、实体总数、卡片类型分布 |
| 卡片明细 | 每个卡片的类型、位置、包含实体、缺失参数 |
| 可视化建议 | 按优先级排列的优化建议（高/中/低） |
| 错误诊断 | 解析错误码及修正指引 |

**Step 4 — 应用建议**

根据建议列表逐项调整配置。建议格式示例：

```
[建议内容] 为 history-graph 卡片增加 hours_to_show: 24 参数（优先级：中）
[原因] 当前未指定时间范围，默认仅显示最近 1 小时数据，无法满足长期趋势观察需求。
```

### 3.3 输出规范

- 报告文件为 Markdown 格式，UTF-8 编码
- 文件名与输入文件同名（批量模式下自动追加序号）
- 报告头部包含解析时间戳与文件哈希值（用于追溯）

### 常见坑位

```yaml
      - entity: light.1
```

**反模式对照**：统一使用 2 空格缩进，禁止 Tab。


**反模式对照**：使用 `entities`，参考 HA 官方文档卡片类型列表。

---

**坑 3：实体 ID 包含非法字符**

```yaml
# 错误示例
entity: light.living room  # 包含空格
```

**反模式对照**：使用下划线替代空格：`light.living_room`。

---

**坑 4：批量处理时输出文件覆盖**

**反模式对照**：使用 `--output ./reports/` 指定独立目录，避免覆盖源文件。

**坑 5：忽略自定义卡片依赖**

**反模式对照**：报告中会标注 `[需核实:card_type]`，需确认自定义卡片已在前端注册。

## 八、参数参考表

### 命令行参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--input` | 字符串 | 无 | 输入 YAML 文件路径 |

| `--output` | 字符串 | `./output/` | 输出报告路径 |
| `--selftest` | 布尔 | False | 运行自检模式 |
| `--version` | 布尔 | False | 显示版本信息 |
| `--no-limit` | 布尔 | False | 禁用文件大小限制 |
| `--verbose` | 布尔 | False | 输出详细日志 |

### 输出报告字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `parse_timestamp` | 字符串 | 解析时间（ISO 8601） |
| `file_hash` | 字符串 | 输入文件 SHA-256 哈希 |
| `view_count` | 整数 | 视图数量 |
| `card_count` | 整数 | 卡片总数 |
| `entity_count` | 整数 | 实体总数（去重） |
| `card_types` | 数组 | 卡片类型分布列表 |
| `suggestions` | 数组 | 优化建议列表（含优先级） |
