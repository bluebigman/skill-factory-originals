### 3.2 执行步骤

#### 步骤 1：准备输入

1. 将所有待处理文件放入同一目录
2. 确认文件命名规范一致（如日期前缀）
3. 如有 URL 列表，保存为 `urls.txt`（每行一个 URL）

#### 步骤 2：试运行（单样本验证）

```bash
oebfare parse --file sample.md --output sample.json
```

验证输出字段：

```json

  "author": "作者名",
  "date": "2024-01-15",
  "tags": ["示例", "测试"],
  "content": "正文内容...",
  "source": "sample.md",
  "url": ""
```

**核对要点**：
- 标题是否完整提取
- 日期格式是否为 ISO 8601
- 标签是否去重

#### 步骤 3：批量执行


执行前确认：
- 原始文件已备份（建议复制到 `./backup/`）
- 输出目录已创建

#### 步骤 4：校验结果

抽查 3-5 条输出记录，核对：
- 标题与源文件一致
- 日期无偏移
- 正文无截断

## 六、FAQ 反模式

### 常见坑 1：日期格式混乱

**反模式**：直接复制源文件中的日期格式（如 "2024年1月15日"）
**正确做法**：统一转换为 ISO 8601（`2024-01-15`）

### 常见坑 2：标签未去重

**反模式**：保留源文件中的重复标签
**正确做法**：解析后自动去重，保持标签唯一性

### 常见坑 3：忽略编码问题

**反模式**：直接按 UTF-8 读取所有文件
**正确做法**：先检测文件编码（GBK/UTF-8），再按对应编码解析

### 常见坑 4：批量执行前不试运行

**反模式**：直接对全量数据执行，发现格式错误后返工
**正确做法**：先用单个样本验证输出格式，确认无误后再批量执行

### 常见坑 5：覆盖原始文件

**反模式**：将解析结果直接写回源文件
**正确做法**：输出到独立目录，保留原始文件备份
