### 执行步骤（分步编号）

#### Step 1：输入预处理

- 去除时间戳、说话人标记（如"医生："、"患者："）中的冗余信息
- 识别对话轮次，按说话人分组
- 去除重复内容（如患者重复说同一症状）

**示例：**
```
输入： "医生：哪里不舒服？ 患者：我这两天胸口疼，就是这儿，一按就疼。 医生：疼多久了？ 患者：大概三天了吧，昨天开始后背也疼。"
处理后： 
  [医生] 哪里不舒服？
  [患者] 我这两天胸口疼，就是这儿，一按就疼。
  [医生] 疼多久了？
  [患者] 大概三天了吧，昨天开始后背也疼。
```

#### Step 2：信息抽取与分类

按以下字段结构抽取信息：

| 字段名 | 说明 | 必填 |
|--------|------|------|
| `主诉` | 患者最主要的症状/体征+持续时间 | 是 |
| `现病史` | 症状发生、发展、诊疗经过 | 是 |
| `既往史` | 既往疾病、手术、过敏史 | 否 |
| `体格检查` | 生命体征、阳性体征 | 否 |
| `初步印象` | 基于症状的初步判断（仅供医生参考） | 否 |

| 口语表述 | 规范术语 | 备注 |
|---------|---------|------|
| 胸口疼 | 胸痛 | 部位+症状 |
| 拉肚子 | 腹泻 | 症状 |
| 脑袋晕 | 头晕 | 症状 |
| 喘不上气 | 呼吸困难 | 症状 |
| 胃里反酸 | 反酸 | 症状 |
| 身上没劲 | 乏力 | 症状 |
| 睡不着 | 失眠 | 症状 |
| 恶心干呕 | 恶心 | 症状 |

**输出格式：**
```
原始表述：胸口疼 → 规范术语：胸痛
原始表述：拉肚子 → 规范术语：腹泻
```

## 四、置信度门控机制

当输入信息不足以生成完整字段时，**严禁编造**。使用以下占位符标记：

| 占位符 | 含义 | 使用场景 |
|--------|------|---------|
| `[需核实:字段名]` | 信息缺失，需人工补充 | 患者未提及既往史 |
| `[需核实:时间]` | 时间信息不明确 | 患者说"好久了"但无具体时间 |
| `[需核实:部位]` | 症状部位描述模糊 | 患者说"这儿疼"但无法定位 |
| `[需核实:程度]` | 症状严重程度未量化 | 患者说"有点疼"但无评分 |

**规则：**
- 占位符必须保留在输出中，不得删除或替换
- 占位符字段不参与后续统计分析
- 输出末尾附"待核实清单"，汇总所有占位符

### 常见问题 FAQ

**Q1：患者说了很多无关内容（如家常），如何处理？**
A：自动过滤与医疗无关的对话内容，仅保留症状描述、时间信息、诊疗经过等医疗相关部分。

**Q2：如何处理方言或口音导致的识别错误？**
A：技能基于文本处理，不涉及语音识别。若转写文本存在方言词汇，术语映射模块会尝试匹配，未匹配的保留原文并标记 `[需核实:术语]`。

**Q3：能否处理英文问诊对话？**
A：支持中英混排，但术语映射表以中文为主。英文术语将保留原文，不做翻译。

**Q4：输出结果可以直接用于电子病历系统吗？**
A：输出为 Markdown 草稿格式，需人工审核后按目标系统的字段要求进行适配。技能不直接对接任何 EHR 系统。

**Q5：批量处理多份问诊记录时如何区分？**
A：输入时使用 `---` 分隔符分隔不同问诊记录，输出时自动生成独立文件。
