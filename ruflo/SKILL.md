## 三、标准流程

### 3.1 前置条件

| 条件 | 要求 |
|------|------|
| 输入目录 | 所有待处理文件必须放在**同一目录**下 |
| 文件格式 | 支持 .csv / .json / .txt / .log / .tsv，编码建议 UTF-8 |
| 原始备份 | 处理前请自行备份原始文件，Skill 不负责恢复 |
| 环境要求 | Python 3.8+，无需额外依赖（纯标准库实现） |

### 3.2 执行步骤

#### 阶段一：单文件试运行（必做）

```bash
# 先跑一个文件，确认解析效果
python ruflo.py --input ./data/sample.csv --output ./output/sample.json
```

**检查项：**
- [ ] 输出 JSON 结构是否符合预期
- [ ] 是否存在 `[需核实:字段]` 占位符
- [ ] 字段映射是否正确（源字段 → 目标字段）

#### 阶段二：批量处理

```bash
# 确认无误后，批量执行
python ruflo.py --input ./data/ --output ./output/ --batch
```

**批量模式参数：**

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--input` | str | 必填 | 输入目录或文件路径 |
| `--output` | str | 必填 | 输出目录或文件路径 |
| `--batch` | flag | False | 启用批量模式 |
| `--workers` | int | 4 | 多智能体并行数（1-16） |
| `--format` | str | json | 输出格式：json / csv |
| `--selftest` | flag | False | 运行自检 |
| `--version` | flag | False | 显示版本号 |

#### 阶段三：校验与合并

1. 批量解析完成后，检查输出目录下的 `_validation_report.json`
2. 报告中列出所有含占位符的记录 ID 与字段名
3. 用户手动补充确认后，重新执行该条记录的解析：

```bash
python ruflo.py --input ./data/sample.csv --output ./output/sample_fixed.json --record-id REC_0007
```

4. **未确认前，该记录不参与最终合并输出**

### 3.3 输出规范

| 输出项 | 格式 | 说明 |
|--------|------|------|
| 解析结果 | JSON / CSV | 结构化数据，字段名与源数据映射 |
| 校验报告 | `_validation_report.json` | 含占位符的记录 ID 与字段名清单 |
| 合并输出 | `merged.json` | 所有已确认记录合并后的最终结果 |

## 四、置信度门控

### 4.1 占位符机制

当解析器对某个字段的置信度低于阈值（默认 85%）时，**不猜测、不编造**，输出：

```
[需核实:字段名]
```

### 4.2 触发条件

| 场景 | 示例 |
|------|------|
| 字段格式异常 | 日期字段出现 "2024/13/45" |
| 字段值缺失 | 地址字段为空 |
| 字段值冲突 | 同一记录出现两个不同的金额 |
| 无法识别的编码 | 乱码文本 |

### 4.3 处理流程

1. 解析器标记低置信度字段 → 输出 `[需核实:字段名]`
2. 校验报告自动生成，列出记录 ID + 字段名
3. 用户查看原始数据，手动确认正确值
4. 重新执行该条记录解析（指定 `--record-id`）
5. 确认后记录参与最终合并输出

## 六、FAQ 反模式对照

### 反模式 1：跳过试运行直接批量

**错误做法：** 拿到文件直接跑 `--batch`，结果 100 个文件全部解析错误。

**正确做法：** 先跑一个文件，确认输出结构无误后再批量执行。

### 反模式 2：忽略占位符直接合并

**错误做法：** 看到校验报告有占位符，直接手动删除占位符强行合并。

**正确做法：** 逐条确认占位符对应的真实值，重新解析后再合并。

### 反模式 3：修改原始文件

**错误做法：** 解析出错后直接编辑原始 CSV 文件。

**正确做法：** 保留原始文件，通过 `--record-id` 单独重跑出错记录。

### 反模式 4：跨目录散放文件

**错误做法：** 文件分散在多个子目录，期望 Skill 自动递归查找。

**正确做法：** 将所有待处理文件复制到同一目录下。

### 反模式 5：并行数拉满

**错误做法：** `--workers 16` 处理小文件，资源浪费且可能 OOM。

**正确做法：** 根据文件大小和机器配置选择 4-8 个并行数。
