| 维度 | 能做 ✅ | 不能做 ❌ |

| 数据清洗 | 去重、缺失值标记、字段对齐、格式统一 | 自动识别并修正所有脏数据（需人工确认规则） |

| 统计分析 | 描述性统计、频次分布、交叉汇总、相关性初探 | 严格因果推断、A/B 检验显著性计算（需专业统计软件） |
| 竞品对比 | 功能/价格/口碑/市场份额四维矩阵生成、雷达图数据输出 | 自动抓取实时竞品数据（需用户提供或授权数据源） |
| 多源融合 | 合并问卷星导出、访谈记录、用户评论等文本/表格数据 | 自动识别所有来源的隐含字段含义（需字段映射说明） |

**适用对象**：产品经理、市场研究员、用户运营人员、学术研究者（非实验设计类）、创业团队。

## 三、标准处理流程

### 3.1 前置条件

在开始处理前，请确认以下三项输入已就绪：

| 输入项 | 要求 | 示例 |
|--------|------|------|
| 调研数据文件 | CSV / Excel / JSON / 纯文本，编码 UTF-8，大小建议 ≤ 100MB | `survey_2026.csv` |
| 调研主题描述 | 一句话说明调研目的 | "了解用户对会员定价的接受度" |
| 目标用户群体描述 | 说明样本来源与特征 | "18-35岁一线城市互联网产品用户" |

> 若缺少主题或用户群体描述，处理流程仍可启动，但输出报告中的"调研背景"部分将标注 `[需核实:调研主题]` 或 `[需核实:目标用户]`。

### 3.2 执行步骤（分步编号）

#### 步骤 1：数据接入与格式校验

- 读取文件头 5 行，检测列名、数据类型、分隔符。
- 校验编码格式，非 UTF-8 时尝试 `gbk` / `latin-1` 兜底解码。
- 输出：数据概览表（列名、非空计数、数据类型）。

```python
import pandas as pd

def load_data(filepath):
    try:
        df = pd.read_csv(filepath, encoding='utf-8')
    except UnicodeDecodeError:
        df = pd.read_csv(filepath, encoding='gbk')
    print(f"加载成功，共 {df.shape[0]} 行，{df.shape[1]} 列")
    return df
```

#### 步骤 2：数据清洗与标准化

- **去重**：基于主键（如用户 ID、提交时间 + IP）识别完全重复行，保留第一条。
- **缺失值处理**：不自动填充，仅标记。新增列 `_missing_flag`，值为 `1` 表示该行存在缺失。
- **字段对齐**：若多源数据合并，统一列名为小写蛇形（`user_age`、`satisfaction_score`）。
- **格式统一**：日期统一为 `YYYY-MM-DD`，数值去除千分位逗号，文本去除首尾空格。

**清洗规则参数表**：

| 规则 | 参数 | 默认值 | 说明 |
|------|------|--------|------|
| 去重 | `subset` | 全列 | 指定列子集去重 |
| 缺失标记 | `missing_threshold` | 0.3 | 缺失率超 30% 的列单独警告 |
| 文本清洗 | `strip_whitespace` | True | 去除首尾空格 |
| 日期解析 | `date_format` | 自动检测 | 支持 `%Y-%m-%d` / `%Y/%m/%d` |

#### 步骤 3：多源数据融合（如适用）

- 输入多个数据源（问卷导出、访谈记录、评论列表）。
- 自动识别公共字段（如 `user_id`、`timestamp`），进行左连接或全连接。
- 字段冲突时，以用户指定的优先级为准（默认：问卷 > 访谈 > 评论）。
- 输出统一数据集，并生成 `_source` 列标注数据来源。

#### 步骤 4：情感倾向分析（针对开放式文本）

- 使用中文情感词典（内置约 5000 积极词、8000 消极词）进行词匹配。
- 规则引擎：否定词反转（如"不"+"好" → 消极）、程度副词加权（"非常"×1.5、"有点"×0.8）。
- 打分范围：`-1.0`（消极）至 `+1.0`（积极），`0` 为中性。
- 输出：每条文本的情感得分 + 整体情感分布统计（积极占比 / 中性占比 / 消极占比）。

**情感分析示例**：

| 评论文本 | 情感得分 | 判定 |
|----------|----------|------|
| "产品很好用，推荐！" | +0.82 | 积极 |
| "一般般，没什么特别" | +0.05 | 中性 |
| "客服态度差，等了好久" | -0.74 | 消极 |

#### 步骤 5：竞品调研对比矩阵（如适用）

- 输入竞品信息（功能列表、价格、口碑评分、市场份额数据）。
- 自动生成四维对比矩阵，输出为 Markdown 表格 + 雷达图数据（JSON 格式）。

**矩阵结构**：

| 维度 | 权重（默认） | 说明 |
|------|-------------|------|
| 功能完整度 | 0.3 | 功能点覆盖数 / 目标功能总数 |
| 价格竞争力 | 0.2 | 相对价格指数（越低越优） |
| 口碑评分 | 0.3 | 归一化后的用户评分（0-10 分制） |
| 市场份额 | 0.2 | 归一化后的市场占有率 |

#### 步骤 6：描述性统计与交叉分析

- 生成各字段的频次分布、均值、中位数、标准差。
- 交叉分析：如"年龄段 × 满意度"的透视表。
- 相关性初探：对数值型字段计算 Pearson 相关系数，输出热力图数据。

#### 步骤 7：报告生成与输出

- 输出结构化 Markdown 报告，包含以下章节：
  1. 调研背景（含主题与目标用户描述）
  2. 数据概况（样本量、字段数、清洗记录）
  3. 关键发现（Top 5 洞察，每条附数据支撑）
  4. 情感分析结果（如适用）
  5. 竞品对比矩阵（如适用）
  6. 附录（数据字典、清洗日志）

### 3.3 输出规范

- 所有结果文件以 `output/` 目录存放，命名规则：`{原文件名}_processed.{ext}`。
- 报告文件为 `report.md`，数据文件为 `clean_data.csv`，情感分析附加 `sentiment_scores.csv`。
- 所有数值保留两位小数，百分比保留一位小数。

## 六、FAQ 与反模式对照

| 常见坑（反模式） | 问题描述 | 正确做法（模式） |
|------------------|----------|------------------|
| **盲目填充缺失值** | 用均值/中位数填充所有缺失，导致数据失真 | 仅标记缺失，不自动填充；如需填充，须用户确认规则 |
| **忽略数据来源** | 多源合并后不保留来源标记，后续无法追溯 | 始终保留 `_source` 列，记录每行数据出处 |
| **过度解读相关性** | 发现相关系数 0.6 就断言"A 导致 B" | 仅输出"存在正相关"，并提示需实验设计验证因果 |
| **情感分析一刀切** | 将所有中性评论归为"无价值" | 中性评论单独分类，可能包含改进建议 |
| **竞品权重拍脑袋** | 随意设定权重且不告知用户 | 权重默认值公开，允许用户自定义，并在报告中注明 |
| **清洗不留日志** | 清洗后无法追溯删除了哪些行、修改了哪些值 | 每次清洗操作记录日志，输出 `cleaning_log.csv` |
