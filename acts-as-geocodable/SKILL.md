# 地址解析与地理编码技能（Geocodable）

## 一、能力边界（一页纸速查卡）

### 1.1 能做什么

| 能力项 | 说明 | 示例 |
|--------|------|------|
| 地址文本解析 | 将非结构化地址字符串拆解为省/市/区/街道/门牌号等结构化字段 | "北京市朝阳区建国路88号" → `{province:"北京市", city:"北京市", district:"朝阳区", street:"建国路", number:"88号"}` |
| 坐标输出 | 返回 WGS-84 坐标系下的经纬度（经度在前，纬度在后） | `{"lng": 116.458, "lat": 39.915}` |
| 置信度评估 | 对每次解析结果给出 0~1 的置信度分数 | 0.95 表示高置信，0.55 表示需人工复核 |
| 批量处理 | 支持一次调用处理多条地址（上限 100 条/批） | 输入数组，输出数组，顺序一一对应 |

### 1.2 不能做什么

| 限制项 | 说明 |
|--------|------|
| 非字符串输入 | 不接受数字、对象、布尔值等非字符串类型，直接返回错误码 `E1002` |
| 含 HTML/URL 的地址 | 输入中若包含 `<div>`、`http://` 等标签或链接，拒绝解析并返回 `E1003` |
| 离线解析 | 坐标匹配依赖外部地理编码服务，网络不可用时返回 `E2001` |
| 逆地理编码 | 本技能仅支持"地址→坐标"，不支持"坐标→地址" |
| 跨语言解析 | 仅支持中文地址（简体/繁体均可），其他语言返回 `E1004` |

### 1.3 适用对象

- 需要将用户填写的收货地址转为地图坐标的电商/物流系统
- 需要将门店地址批量转为坐标用于可视化展示的数据分析场景
- 需要校验地址真实性的风控系统（通过置信度阈值过滤异常地址）
- 需要标准化地址格式的 CRM 系统

## 三、标准处理流程

### 3.1 前置条件

| 条件 | 要求 | 检查方式 |
|------|------|----------|
| 输入类型 | 字符串（UTF-8 编码） | `typeof input === 'string'` |
| 输入内容 | 不含 HTML 标签、URL | 正则匹配 `/<\/?[a-z][\s\S]*>/i` 和 `/https?:\/\//i` |
| 网络状态 | 可访问外部地理编码服务 | 发送心跳请求，超时 3 秒 |
| 输入长度 | 单条地址不超过 200 字符 | `input.length <= 200` |

### 3.2 执行步骤

**步骤 1：输入校验**

```
输入: "北京市海淀区中关村大街27号"
检查: 类型为字符串 ✓ | 无 HTML/URL ✓ | 长度 18 ≤ 200 ✓
通过 → 进入步骤 2
失败 → 返回对应错误码（见第五节）
```

**步骤 2：地址标准化**

- 去除首尾空白字符
- 全角字符转半角（如 `Ａ` → `A`，`１` → `1`）
- 繁体转简体（如 `臺北市` → `台北市`）
- 统一行政区划名称（如 `内蒙古` → `内蒙古自治区`）

**步骤 3：地址解析与坐标匹配**

```
解析流程:
  3.1 将标准化后的地址按"省/市/区/街道/门牌"层级拆分
  3.2 将拆分后的结构化地址发送至地理编码服务
  3.3 服务返回候选坐标列表（最多 5 个）
  3.4 按匹配度排序，取最高分作为结果
  3.5 计算置信度 = 匹配度 × 地址完整度系数
```

**步骤 4：输出结果**

```json
{
  "status": "success",
  "data": {
    "input": "北京市海淀区中关村大街27号",
    "structured": {
      "province": "北京市",
      "city": "北京市",
      "district": "海淀区",
      "street": "中关村大街",
      "number": "27号"
    },
    "coordinates": {
      "lng": 116.3168,
      "lat": 39.9889
    },
    "confidence": 0.96,
    "matched_level": "street_number"
  }
}
```

### 3.3 输出规范

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `status` | string | 是 | `success` 或 `error` |
| `data.input` | string | 是 | 原始输入地址 |
| `data.structured` | object | 是 | 结构化地址字段 |
| `data.coordinates.lng` | number | 是 | 经度（WGS-84） |
| `data.coordinates.lat` | number | 是 | 纬度（WGS-84） |
| `data.confidence` | number | 是 | 置信度 0~1，保留两位小数 |
| `data.matched_level` | string | 否 | 匹配精度级别：`country`/`province`/`city`/`district`/`street`/`street_number` |

**匹配精度级别说明：**

| 级别 | 含义 | 典型置信度范围 |
|------|------|----------------|
| `country` | 仅匹配到国家 | 0.10 ~ 0.25 |
| `province` | 匹配到省级 | 0.25 ~ 0.40 |
| `city` | 匹配到市级 | 0.40 ~ 0.55 |
| `district` | 匹配到区县级 | 0.55 ~ 0.70 |
| `street` | 匹配到街道级 | 0.70 ~ 0.85 |
| `street_number` | 匹配到门牌号 | 0.85 ~ 1.00 |

## 四、置信度门控

### 4.1 降级策略

当置信度低于阈值时，按以下策略处理：

| 置信度区间 | 处理方式 | 输出附加标记 |
|------------|----------|--------------|
| ≥ 0.85 | 直接使用，无需复核 | 无 |
| 0.60 ~ 0.84 | 可用但建议人工抽查 | `"review": "recommended"` |
| 0.40 ~ 0.59 | 不可直接使用，需人工确认 | `"review": "required"` |
| < 0.40 | 拒绝输出坐标，仅返回结构化地址 | `"coordinates": null` |

### 4.2 信息不足时的占位规则

当输入地址缺少必要字段（如只有"北京市"没有街道门牌），无法完成有效解析时：

- 不编造坐标，输出 `[需核实:缺少街道/门牌信息]` 占位符
- 在 `data.structured` 中保留已解析出的字段，缺失字段置为 `null`
- 返回错误码 `E3001`（信息不完整）

**示例：**

      "province": "北京市",

## 五、错误码体系

| `E1002` | 输入类型非字符串 | "地址必须是文本格式" | 将输入转为字符串类型后再调用 |
| `E1003` | 输入含 HTML 标签或 URL | "地址中不能包含网页链接或HTML代码" | 去除输入中的 `<...>` 标签和 `http(s)://` 链接 |

## 六、FAQ 反模式

### 6.1 常见坑与反模式对照

| 反模式（错误做法） | 问题 | 正确做法 |
|---------------------|------|----------|
| 直接传入用户原始输入，不做任何预处理 | 用户输入常含表情符号、多余标点、换行符，导致解析失败或置信度低 | 先清洗：去除非地址字符、统一全半角、去除空白 |
| 忽略置信度，直接使用坐标 | 低置信度坐标可能偏移数公里，导致配送/定位错误 | 设置置信度阈值（如 0.7），低于阈值走人工复核流程 |
| 将错误码当异常抛出，不做业务处理 | 网络错误（E2001）是临时性的，直接抛异常会导致用户体验差 | 捕获错误码，对可重试错误（E2001/E2002）做指数退避重试 |
| 批量处理时不检查单条结果 | 批量中某条失败会导致整批失败 | 逐条处理，单条失败不影响其他条，返回部分成功结果 |
| 缓存所有解析结果 | 地址数据可能涉及隐私，且地址会变化（如拆迁） | 仅缓存高置信度（≥0.9）结果，设置缓存有效期（如 30 天） |

### 6.2 输入预处理建议

```
推荐预处理流程:
1. 去除所有 HTML 标签:  input.replace(/<[^>]*>/g, '')
2. 去除 URL:            input.replace(/https?:\/\/[^\s]+/g, '')
3. 去除表情符号:        input.replace(/[\u{1F300}-\u{1F9FF}]/gu, '')
4. 全角转半角:          input.replace(/[Ａ-Ｚａ-ｚ０-９]/g, s => String.fromCharCode(s.charCodeAt(0) - 0xFEE0))
5. 压缩连续空白:        input.replace(/\s+/g, ' ').trim()
```
