# cache-fu 技能文档

## 一、能力边界（一页纸速查卡）

### 1.1 能做什么

| 能力项 | 说明 | 约束条件 |
|--------|------|----------|
| 缓存扫描 | 遍历系统常见缓存目录，统计各目录占用空间 | 仅扫描预设目录列表，不递归全盘 |
| 安全清理 | 将待清理文件移动至回收站目录，而非直接删除 | 回收站位于 `~/.cache-fu/trash/` |
| 清理预览 | 生成待清理文件清单，展示预计释放空间 | 预览不执行任何移动操作 |
| 误删恢复 | 从回收站恢复指定文件至原路径 | 仅支持回收站内未过期的备份 |
| 清理日志 | 每次清理操作生成完整日志文件 | 日志保存于 `~/.cache-fu/logs/` |
| 空间对比 | 输出清理前后磁盘空间变化 | 对比数据基于清理日志记录 |
| 白名单保护 | 指定应用缓存目录不参与清理 | 白名单配置存储于 `~/.cache-fu/config.json` |
| 自动清理回收站 | 删除超过 30 天的回收站内容 | 可通过配置调整保留天数 |

### 1.2 不能做什么

- **不能**清理系统关键目录（如 `/System`、`/Windows`、`/etc` 等）
- **不能**清理正在被进程占用的文件
- **不能**跨用户清理其他用户的缓存目录
- **不能**清理未列入预设目录列表的自定义路径（需手动添加）
- **不能**保证清理后应用功能完全不受影响（部分应用可能重新生成缓存）
- **不能**恢复超过保留期限的回收站文件

### 1.3 适用对象

- 个人开发者：需要定期清理开发环境缓存（如 npm、pip、gradle 缓存）
- 系统管理员：管理多台服务器，需要批量清理缓存并生成报告
- 普通用户：磁盘空间不足，希望安全释放空间且可回滚

## 六、FAQ 反模式

### 6.1 常见坑与正确做法

| 常见错误（反模式） | 问题说明 | 正确做法 |
|-------------------|----------|----------|
| 直接删除缓存文件 | 无法恢复误删数据 | 使用 `--clean` 移动至回收站 |
| 清理所有缓存目录 | 可能影响正在运行的应用 | 仅清理超过 100MB 且非活跃的目录 |
| 忽略预览直接清理 | 可能误删重要数据 | 先 `--preview` 确认清单 |
| 清理后不重启应用 | 应用可能因缓存缺失而异常 | 清理后重启相关应用验证功能 |
| 手动修改回收站文件 | 破坏回滚机制 | 通过 `--restore` 恢复文件 |
| 不配置白名单 | 重要应用缓存被清理 | 提前添加白名单保护 |
| 清理后立即删除日志 | 无法审计和回滚 | 保留日志至少 30 天 |

### 6.2 反模式对照表

**反模式 1：盲目清理**

```
❌ 错误：不配置白名单，直接清理

```

**反模式 3：清理后不验证**
```
❌ 错误：清理后直接关机
```

本 Skill 为命令行工具形态，安装前请确认系统满足以下前置条件：操作系统为 Linux/macOS（Windows 可通过 WSL 使用），已安装 Python 3.8 及以上版本，且当前用户对目标缓存目录具有读取权限。安装时，将本 Skill 所在目录添加至系统 PATH 环境变量，或直接调用可执行文件路径。首次使用前，建议执行环境自检命令，确认工具可正常访问预设缓存目录列表。配置文件位于 `~/.cache-fu/config.json`，可在此调整回收站保留天数（默认30天）、白名单目录列表等参数。若需清理自定义路径，请先手动将其添加至配置文件的预设目录列表中，否则工具不会扫描该路径。安装完成后，建议先执行一次扫描预览，确认识别结果符合预期后再进行实际清理操作。

## 使用方法

使用本 Skill 时，遵循「扫描→预览→清理→验证」的标准流程。首先执行环境自检，确认工具运行正常且具备必要的目录访问权限。随后执行缓存扫描，工具将遍历预设缓存目录并统计各目录占用空间，生成分布概览。在清理前务必生成预览清单，核对待清理文件列表与预计释放空间，确认无误后再执行清理操作。清理完成后，查看清理日志与空间对比报告，验证清理效果。若清理后发现误删文件，可通过恢复命令从回收站找回。如需保护特定应用的缓存不被清理，提前在配置文件中添加白名单。建议定期查看清理日志，了解系统缓存增长趋势，并适时调整清理策略与白名单配置。

## 使用示例

以下为典型使用场景的操作示例。场景一：日常清理——用户执行扫描命令查看缓存分布，生成预览清单确认后可释放空间，确认后执行清理，最后查看报告确认释放效果。场景二：误删恢复——用户清理后发现某文件被误删，通过恢复命令指定文件路径，工具从回收站将其还原至原位置。场景三：白名单配置——用户希望保留某开发工具的缓存目录，编辑配置文件添加白名单路径，再次执行扫描验证该目录已不在清理清单中。场景四：批量管理——系统管理员在多台服务器上执行扫描并输出 JSON 格式结果，对接监控平台统一分析，再批量执行清理并收集日志归档。场景五：回收站维护——用户查看回收站内容，确认过期文件后手动触发自动清理，或调整保留天数配置以延长备份保留周期。

## 常见问题

**问题一：扫描结果中未出现预期目录。** 本 Skill 仅扫描预设目录列表，不递归全盘。若需清理自定义路径，请手动将其添加至 `~/.cache-fu/config.json` 的预设目录列表中。**问题二：清理时提示文件被占用。** 本 Skill 不能清理正在被进程占用的文件，请关闭相关应用后重试，或将该路径加入白名单避免后续干扰。**问题三：误删文件后无法恢复。** 仅支持恢复回收站内未过期的备份，超过保留天数（默认30天）的文件会被自动清理且不可恢复。请根据实际需求调整保留天数配置。**问题四：清理后应用功能异常。** 部分应用可能重新生成缓存，本 Skill 不保证清理后应用功能完全不受影响。若遇异常，可尝试从回收站恢复对应缓存文件。**问题五：跨用户清理需求。** 本 Skill 不能跨用户清理其他用户的缓存目录，请切换至对应用户身份执行操作。**问题六：日志文件持续增长。** 每次清理都会生成完整日志，建议定期归档或清理 `~/.cache-fu/logs/` 目录下的历史日志文件。
