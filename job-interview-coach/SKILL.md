## 三、标准工作流程

### 3.1 前置条件

- 客户资料需以「速查卡」格式提供。每行一个字段，格式为 `[字段名: 值]`。
- 必填字段（至少 3 个）：
  - `收件人`：联系人姓名或称呼
  - `公司`：对方公司名称
  - `产品/痛点`：你提供的产品或服务能解决的对方痛点（至少列出 3 个）
- 可选字段（补充越多，邮件越精准）：
  - `行业`、`职位`、`地区`、`过往互动记录`、`推荐人`、`公司规模`、`近期动态`

### 3.2 执行步骤

#### 单封模式

1. 输入触发词（如"开发信"）。
2. 粘贴速查卡格式的客户资料。
3. （可选）指定语气参数：`formal` / `semi` / `casual`，默认 `semi`。
4. （可选）指定篇幅参数：`compact` / `standard` / `detailed`，默认 `standard`。
5. 等待生成，检查输出中的 `[需核实:...]` 占位符。
6. 补充缺失信息后重新生成，或手动替换占位符。
7. 通读全文，确认无误后复制到邮件客户端发送。

#### 批量模式

1. 输入触发词 + "批量"（如"批量开发信"）。
2. 粘贴多条速查卡，每条之间用空行分隔。
3. 系统逐条生成，输出按序号排列的邮件草稿。
4. 逐封检查占位符，统一补充缺失字段后重新生成。

### 3.3 输出规范

- 每封邮件包含：**主题行**（建议 3 个备选）+ **正文**（含称呼、开场、痛点共鸣、价值主张、行动召唤、署名）。
- 信息不足处使用 `[需核实:字段名]` 标注，绝不虚构。
- 邮件末尾附一行提示：`（本邮件由 AI 生成草稿，发送前请人工审阅）`。

## 四、置信度门控机制

### 4.1 信息缺口处理

当速查卡缺少关键信息时，系统不会猜测，而是按以下规则处理：

| 缺失字段 | 处理方式 |
|---------|---------|
| 收件人姓名 | 使用 `[需核实:收件人姓名]` 占位，称呼用"您好" |
| 公司名称 | 拒绝生成，提示补充必填字段 |
| 产品/痛点不足 3 个 | 拒绝生成，提示至少补充 3 个痛点 |
| 推荐人 | 不提及推荐关系，仅用 `[需核实:推荐人]` 标注可选位置 |
| 过往互动记录 | 不编造历史，仅用 `[需核实:过往互动]` 标注 |

### 4.2 置信度分级

- **高置信**：所有必填字段齐全，邮件中无占位符。
- **中置信**：必填字段齐全但可选字段缺失，邮件中有 1-2 个占位符。
- **低置信**：必填字段不完整，系统拒绝生成并返回错误码。
