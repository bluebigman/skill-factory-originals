## 一、能力边界（一页纸速查卡）

### 1.1 能做什么

| 能力项 | 说明 | 示例 |
|--------|------|------|
| 格式转换 | 将 CSV、TSV、JSON Lines 等表格型数据转为统一 JSON 结构 | `users.csv` → `users.json` |
| 字段映射 | 支持自定义映射规则，将源字段名映射为目标字段名 | `姓名` → `name`，`年龄` → `age` |
| 数据清洗 | 自动识别空值、重复值、格式异常并标记 | 空邮箱、重复 ID、非法日期 |
| 类型推断 | 自动推断字段类型（字符串、数字、布尔、日期） | `"2024-01-01"` → `date` 类型 |
| 警告输出 | 对可疑数据生成 `warnings` 数组，提示人工核实 | `[需核实:邮箱格式]` |
| 批量处理 | 支持整个目录的批量转换 | `input/` 下所有 `.csv` 文件 |

### 1.2 不能做什么

| 限制项 | 说明 |
|--------|------|
| 不处理非表格数据 | 图片、音频、PDF 扫描件等非结构化数据无法直接转换 |
| 不自动修正数据 | 对可疑数据仅标记 `[需核实]`，不擅自修改原始值 |
| 不保证数据准确性 | 输出结果的质量取决于输入数据的质量 |
| 不提供数据可视化 | 仅输出结构化 JSON，不生成图表或报告 |
| 不支持实时流式处理 | 仅处理静态文件，不监听实时数据流 |

## 四、置信度门控

### 4.1 基本原则

**不编造、不猜测、不自动修正。** 当遇到无法确定的数据时，输出 `[需核实:字段]` 占位符，并记录到 `warnings` 数组。

### 4.2 需要标记的场景

| 场景 | 标记方式 | 示例 |
|------|---------|------|
| 字段值为空 | `[需核实:空值]` | `"email": "[需核实:空值]"` |
| 格式不符合预期 | `[需核实:格式]` | 邮箱缺少 `@` |
| 类型冲突 | `[需核实:类型]` | 年龄字段出现 `"abc"` |
| 超出合理范围 | `[需核实:范围]` | 年龄为 `-5` 或 `200` |
| 重复值 | `[需核实:重复]` | 同一 ID 出现多次 |

### 4.3 处理流程

1. 转换时自动检测可疑数据
2. 在 `data` 中保留原始值，但追加 `[需核实]` 标记
3. 在 `warnings` 数组中记录详细信息
4. 由使用者人工确认后决定保留、修正或删除

6. 尝试修改源数据中的问题字段，重新转换

### 7.3 进阶路径（深入使用）

1. 创建 `mapping.json` 自定义字段映射：

```json
{
  "姓名": "name",
  "年龄": "age",
  "邮箱": "email",
  "注册日期": "created_at"
}
```

2. 使用批量模式处理整个目录：

```bash
tidescope --input input/ --output output/
```

3. 编写脚本读取输出 JSON 进行后续分析：

```python
import json

with open("output/your_data.json") as f:
    data = json.load(f)

# 分析数据
for row in data["data"]:
    print(row["name"], row["age"])

# 处理警告
for warning in data["warnings"]:
    print(f"警告: {warning['field']} - {warning['reason']}")
```

4. 结合 `warnings` 输出建立数据质量监控流程：

```bash
# 定时检查警告数量
tidescope --input input/ --output output/
jq '.warnings | length' output/*.json
```
