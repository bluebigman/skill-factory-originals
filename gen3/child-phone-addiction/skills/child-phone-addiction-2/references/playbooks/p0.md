# 操作手册（playbooks）

> 本页说明：**拿到输入后具体怎么做**。决策树 + 分步处置 + 故障处理。
> 来源：`config.json` 规则表（逐条展开）。

## 一、总体决策树

```
输入为空？
  ├─ 是 ⇒ 返回 empty，提示补充内容（不要瞎猜）
  └─ 否 ⇒ 归一化（去空白/统一大小写/全半角）
        ├─ 命中规则？（4 条）
        │    ├─ 是 ⇒ 按权重排序，给出前 3 条动作
        │    └─ 否 ⇒ 再试召回词（7 个）
        │          ├─ 命中 ⇒ 给出候选动作
        │          └─ 未命中 ⇒ 返回 unknown，追问补充信息
        └─ 输出：状态 + 条目 + 下一步
```

## 二、逐条操作手册

### PB-01：家长单方面宣布时间

**触发条件**：输入中出现「家长单方面宣布时间」或其近义表达。

**执行步骤**：

1. 确认该情境确实命中（不要凭单字猜）
2. 执行：让孩子参与定：给两个方案让他选，参与感决定执行率
3. 复核：确认动作与用户实际场景一致
4. 记录：把本条命中原因写进输出，便于用户判断

**常见错误**：命中了字面但语义不符 ⇒ 必须说明「按字面命中，请确认」。

### PB-02：约定只说不能用多久

**触发条件**：输入中出现「约定只说不能用多久」或其近义表达。

**执行步骤**：

1. 确认该情境确实命中（不要凭单字猜）
2. 执行：必须同时约定「不用手机的时候做什么」，否则空出来的时间还是想手机
3. 复核：确认动作与用户实际场景一致
4. 记录：把本条命中原因写进输出，便于用户判断

**常见错误**：命中了字面但语义不符 ⇒ 必须说明「按字面命中，请确认」。

### PB-03：违反了没有后果

**触发条件**：输入中出现「违反了没有后果」或其近义表达。

**执行步骤**：

1. 确认该情境确实命中（不要凭单字猜）
2. 执行：约定时就说清违反的后果，且后果要可执行（如次日减少30分钟）
3. 复核：确认动作与用户实际场景一致
4. 记录：把本条命中原因写进输出，便于用户判断

**常见错误**：命中了字面但语义不符 ⇒ 必须说明「按字面命中，请确认」。

### PB-04：一次谈完就指望长期有效

**触发条件**：输入中出现「一次谈完就指望长期有效」或其近义表达。

**执行步骤**：

1. 确认该情境确实命中（不要凭单字猜）
2. 执行：每两周复盘一次，按实际执行调整，不是一劳永逸
3. 复核：确认动作与用户实际场景一致
4. 记录：把本条命中原因写进输出，便于用户判断

**常见错误**：命中了字面但语义不符 ⇒ 必须说明「按字面命中，请确认」。

## 三、故障处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 返回 unknown | 输入与规则/召回词都不匹配 | 请用户补充背景，或明确告知超出范围 |
| 返回 empty | 输入为空 | 提示提供内容 |
| 输出过多 | 多条规则同时命中 | 按权重取前 3，其余折叠 |
| 结果不准 | 命中了字面但语义不符 | 说明命中依据，请用户确认 |
