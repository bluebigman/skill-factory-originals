# 操作手册（playbooks）

> 本页说明：**拿到输入后具体怎么做**。决策树 + 分步处置 + 故障处理。
> 来源：`config.json` 规则表（逐条展开）。

## 一、总体决策树

```
输入为空？
  ├─ 是 ⇒ 返回 empty，提示补充内容（不要瞎猜）
  └─ 否 ⇒ 归一化（去空白/统一大小写/全半角）
        ├─ 命中规则？（3 条）
        │    ├─ 是 ⇒ 按权重排序，给出前 3 条动作
        │    └─ 否 ⇒ 再试召回词（7 个）
        │          ├─ 命中 ⇒ 给出候选动作
        │          └─ 未命中 ⇒ 返回 unknown，追问补充信息
        └─ 输出：状态 + 条目 + 下一步
```

## 二、逐条操作手册

### PB-01：事情过去了就当没发生

**触发条件**：输入中出现「事情过去了就当没发生」或其近义表达。

**执行步骤**：

1. 确认该情境确实命中（不要凭单字猜）
2. 执行：1 小时内复盘：用「下次我们怎么做」让他自己说一个办法
3. 复核：确认动作与用户实际场景一致
4. 记录：把本条命中原因写进输出，便于用户判断

**常见错误**：命中了字面但语义不符 ⇒ 必须说明「按字面命中，请确认」。

### PB-02：复盘变成二次批评

**触发条件**：输入中出现「复盘变成二次批评」或其近义表达。

**执行步骤**：

1. 确认该情境确实命中（不要凭单字猜）
2. 执行：只谈办法不谈对错，说「我们一起想个更好的办法」
3. 复核：确认动作与用户实际场景一致
4. 记录：把本条命中原因写进输出，便于用户判断

**常见错误**：命中了字面但语义不符 ⇒ 必须说明「按字面命中，请确认」。

### PB-03：同样情况反复发生

**触发条件**：输入中出现「同样情况反复发生」或其近义表达。

**执行步骤**：

1. 确认该情境确实命中（不要凭单字猜）
2. 执行：记录触发点（时间/地点/前置事件），一周内做规律排查
3. 复核：确认动作与用户实际场景一致
4. 记录：把本条命中原因写进输出，便于用户判断

**常见错误**：命中了字面但语义不符 ⇒ 必须说明「按字面命中，请确认」。

## 三、故障处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 返回 unknown | 输入与规则/召回词都不匹配 | 请用户补充背景，或明确告知超出范围 |
| 返回 empty | 输入为空 | 提示提供内容 |
| 输出过多 | 多条规则同时命中 | 按权重取前 3，其余折叠 |
| 结果不准 | 命中了字面但语义不符 | 说明命中依据，请用户确认 |
