## 三、标准流程

### 3.1 前置条件

- 输入必须为字符串形式的 shell 命令（如 `rm -rf ./build`）
- 命令长度不超过 1024 字符
- 若输入为空或非命令文本，返回错误码 `E1001`

### 3.2 执行步骤

**步骤 1：接收命令输入**

接收用户提供的命令字符串，去除首尾空白字符。

**步骤 2：命令解析与规范化**

- 将命令拆分为「主命令 + 参数 + 目标路径」
- 规范化路径（如 `~` 展开为 `/home/user`，`./` 保留相对路径）
- 示例：
  - 输入：`rm -rf /var/log/*.log`
  - 解析结果：主命令=`rm`，参数=`-rf`，目标=`/var/log/*.log`

**步骤 3：风险模式匹配**

对照内置模式库进行匹配，模式库包含但不限于：

| 模式 ID | 匹配规则 | 风险权重 |
|---------|----------|----------|
| P001 | 主命令为 `rm` 且包含 `-r` 或 `-f` | 40 |
| P002 | 目标路径包含 `/var`、`/etc`、`/usr` 等系统目录 | 30 |
| P003 | 目标路径包含通配符 `*` 或 `?` | 20 |
| P004 | 主命令为 `git push` 且包含 `--force` 或 `-f` | 35 |
| P005 | 主命令为 `mkfs`、`dd`、`shutdown` 等 | 50 |

**步骤 4：上下文增强评估**

- 检查命令是否在容器/虚拟机内执行（若用户提供环境信息）
- 检查目标路径是否为当前工作目录或上级目录
- 检查是否包含管道符 `|` 或重定向 `>` 等组合操作

**步骤 5：计算综合风险等级**

风险分值 = 各模式权重之和 + 上下文加分项，上限 100 分。

| 分值区间 | 等级 | 建议动作 |
|----------|------|----------|
| 0-30 | 低危 | 可执行，建议确认 |
| 31-60 | 中危 | 建议修改或加保护措施 |
| 61-100 | 高危 | 强烈建议取消或替换 |

**步骤 6：生成风险报告**

报告包含以下字段：

```json
{
  "command": "rm -rf /var/log/*.log",
  "risk_score": 90,
  "risk_level": "高危",
  "matched_patterns": ["P001", "P002", "P003"],
  "suggestions": ["建议先备份 /var/log 目录", "使用 find 命令精确匹配后再删除"]
}
```

**步骤 7：输出规范**

- 输出格式为 Markdown 表格 + 风险报告 JSON
- 若风险等级为「高危」，在报告开头加粗提示：**⚠️ 高危操作，请谨慎执行**
