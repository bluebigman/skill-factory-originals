## 三、标准处理流程

### 3.1 前置条件

| 检查项 | 要求 | 不满足时的处理 |
|--------|------|----------------|
| 输入文本 | 至少 50 字以上 | 提示用户补充内容 |
| 文本语言 | 中英文均可，但需单一语言 | 混合语言时提示分段处理 |
| 格式标记 | 支持 Markdown 基础语法 | 复杂格式（表格、代码块）保留不动 |
| 处理目标 | 用户需明确改写方向 | 默认按"自然化+精简"处理 |

### 3.2 执行步骤

**第一步：文本解析与特征识别**

- 读取输入文本，识别以下特征：
  - 句式重复度（相邻句是否都以"我们""该""此"开头）
  - 连接词密度（"首先""其次""此外""总之"出现频率）
  - 修饰词堆砌（"非常""十分""极其""显著"等程度副词）
  - 结构模板化（是否呈现明显的三段式或总分总结构）

**第二步：分层改写处理**

按以下优先级逐层处理：

| 层级 | 处理内容 | 操作方式 |
|------|----------|----------|
| L1 | 句式变换 | 长短句交替、主动被动互换、疑问句插入 |
| L2 | 连接词替换 | "首先/其次"→"说起来/另外还有"；"总之"→"说到底" |
| L3 | 冗余删除 | 删除"值得注意的是""众所周知""不可否认"等空话 |
| L4 | 语气调整 | 增加第一人称视角、适度口语词、情感表达 |
| L5 | 结构重组 | 调整段落顺序，打破固定模板框架 |

**第三步：关键信息核对**

- 提取原文中的以下信息，改写后逐一比对：
  - 数字与日期（如"2024年""37.5%""第3季度"）
  - 专有名词（人名、地名、机构名、产品名）
  - 核心观点（每段的主旨句是否保留）
  - 逻辑关系（因果、转折、并列是否清晰）

**第四步：输出与标注**

- 输出改写后的完整文本
- 附上"改写说明"：列出主要改动点（3-5条）
- 对不确定的信息使用 `[需核实:字段名]` 占位

### 3.3 输出规范

## 六、常见坑与反模式对照

| 坑（反模式） | 问题说明 | 正确做法 |
|--------------|----------|----------|
| 过度口语化 | 把正式文本改成"贼好""超棒"等网络用语 | 保持适度口语，根据原文基调调整，不强行接地气 |
| 改写后信息丢失 | 为了"自然"删掉了关键数据 | 先提取关键信息清单，改写后逐项核对 |
| 句式单一化 | 所有句子都改成短句，失去节奏感 | 长短句交替，保留原文的论述节奏 |
| 过度使用同义词替换 | "重要"改成"关键""重大""核心"轮换 | 优先调整句式结构，而非机械替换词汇 |
| 忽略原文语气 | 把严肃的讣告改成轻松风格 | 先判断原文情感基调，保持语气一致性 |
| 为了"去AI味"而添加错误口语 | 在学术论文里加"说白了""你懂的" | 口语化要分场景，学术文本保持严谨 |

```bash
python run.py <命令> [参数]    # 执行核心功能
python run.py --selftest      # 运行自检
```

## 示例（Examples）

```bash
# 示例 1: 查看帮助
python run.py --help

# 示例 2: 执行核心功能
python run.py main --selftest file.txt

# 示例 3: 运行自检
python run.py --selftest
```

## 常见问题（FAQ）

**Q: 支持中文文件吗？**
A: 支持，内置 utf-8/gbk/gb18030 多编码容错。

**Q: 运行报错怎么办？**
A: 工具内置异常降级，错误会有明确提示；可先用 --dry-run 预览。

**Q: 如何确认功能正常？**
A: 运行 --selftest，全部通过即核心功能正常。
