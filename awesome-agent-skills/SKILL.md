## 三、标准流程

### 前置条件

| 条件 | 要求 | 检查方式 |
|------|------|----------|
| 技能库已加载 | 当前环境已注册至少 1 个技能 | 执行 `--selftest` 验证 |
| 输入格式正确 | 文本输入，长度 ≤ 200 字符 | 超出则截断处理 |
| 版本兼容 | 调用方支持本 Skill 的 CLI 接口 | 执行 `--version` 确认 |

### 执行步骤

1. **接收输入**：获取用户的检索关键词或任务描述。
   - 若输入为空，直接跳至步骤 4。
   - 若输入为 `--selftest`，执行自检并返回环境状态。
   - 若输入为 `--version`，返回当前版本号。

2. **意图解析**：
   - 若输入为关键词（≤ 4 个词），直接作为匹配项。
   - 若输入为任务描述（> 4 个词），提取核心动词 + 宾语组合，映射到技能类别。

3. **匹配计算**：
   - 将解析结果与技能库中的名称、标签、描述进行文本相似度比对。
   - 相似度得分归一化至 0.00 ~ 1.00 区间。
   - 按得分降序排列，取前 5 条结果。

4. **结果输出**：
   - 输出格式为编号列表，每项包含技能名称和匹配度。
   - 示例：
     ```
     1. [技能名称]（匹配度 0.92）
     2. [技能名称]（匹配度 0.78）
     3. [技能名称]（匹配度 0.65）
     ```
   - 若输入为空，输出完整技能目录树（按类别分组）。

5. **附加提示**：
   - 对匹配度 ≥ 0.7 的结果，额外标注前置条件摘要。
   - 对匹配度 < 0.3 的结果，提示"未找到合适技能，请尝试更换关键词"。

### 输出规范

| 输出类型 | 格式要求 |
|----------|----------|
| 检索结果 | 编号 + 技能名称 + 匹配度，每行一条 |
| 目录树 | 按类别分组，缩进表示层级 |
| 错误信息 | 以 `[错误]` 开头，后接错误码和说明 |

## 六、FAQ 反模式

### 常见坑 1：输入过于宽泛

- **反模式**：输入"处理文件"这种泛化描述。
- **问题**：匹配结果分散，难以定位。
- **正确做法**：输入具体操作，如"批量重命名图片文件"。

### 常见坑 2：忽略匹配度阈值

- **反模式**：直接选用匹配度最低的结果。
- **问题**：技能与需求不匹配，执行效果差。
- **正确做法**：优先选择匹配度 ≥ 0.7 的结果，低于 0.5 的建议更换关键词重试。

### 常见坑 3：跳过前置条件检查

- **反模式**：看到推荐结果直接调用，不检查前置条件。
- **问题**：运行时才发现依赖缺失，浪费资源。
- **正确做法**：调用前先确认前置条件是否满足，不满足则先补齐。

### 常见坑 4：一次只用一个关键词

- **反模式**：只输入一个词，如"图片"。
- **问题**：结果范围过大，难以筛选。
- **正确做法**：组合多个关键词，如"图片 压缩 批量"。

### 常见坑 5：依赖记忆而非检索

- **反模式**：凭印象直接调用技能，不经过检索。
- **问题**：技能库更新后，旧印象可能失效。
- **正确做法**：每次调用前都执行一次检索，确保使用的是当前可用技能。
