## 三、标准流程

### 3.1 前置条件

开始评估前，请确认已具备以下条件：

| 条件 | 要求 | 缺失处理 |
|------|------|----------|
| 评估目标 | 明确要评估的对象（产品/方案/代码/活动等） | 提示用户先明确目标 |
| 信息维度 | 至少提供 3 个维度的信息（如功能、性能、体验等） | 标注 `[需核实:缺失维度]` 后继续 |
| 评估目的 | 明确评估用途（内部改进/对外展示/个人自评） | 默认按内部改进处理 |

### 3.2 执行步骤

**步骤 1：信息收集**

用户提供评估目标及已知信息。系统自动识别信息覆盖的维度。

**步骤 2：信息清单输出**

系统输出已获取的信息清单，并标注缺失项：

```
已获取信息：
- 功能范围：包含用户注册、登录、数据看板
- 技术栈：Vue 3 + Node.js
- 用户规模：日活约 5000

缺失信息：
- [需核实:性能指标]
- [需核实:用户反馈]
```

**步骤 3：五维评分**

对以下五个维度逐一评分（1-10 分）：

| 维度 | 评分标准（1-3 分 / 4-7 分 / 8-10 分） |
|------|----------------------------------------|
| 功能完整性 | 核心功能缺失 / 核心功能可用但细节不足 / 功能完备且体验流畅 |
| 性能效率 | 明显卡顿或响应慢 / 可接受但有优化空间 / 响应迅速且资源占用合理 |
| 用户体验 | 操作路径混乱 / 基本可用但学习成本高 / 直观易用且反馈及时 |
| 可维护性 | 代码耦合严重或文档缺失 / 结构尚可但文档不全 / 模块清晰且文档完善 |
| 创新性 | 无差异化 / 有局部亮点 / 有显著创新突破 |

**步骤 4：总分计算**

默认权重：五个维度各占 20%。总分 = Σ(维度得分 × 权重)。

示例：
```
功能完整性：8 分 × 20% = 1.60
性能效率：  7 分 × 20% = 1.40
用户体验：  6 分 × 20% = 1.20
可维护性：  7 分 × 20% = 1.40
创新性：    5 分 × 20% = 1.00
─────────────────────────
总分：6.60 / 10
```

**步骤 5：改进建议输出**

按优先级输出建议清单：

```
改进建议：
1. [高优先级] 优化用户注册流程，减少必填字段数量
2. [高优先级] 补充性能监控，定位首屏加载瓶颈
3. [中优先级] 完善 API 文档，补充错误码说明
4. [低优先级] 探索数据可视化的差异化展示方案
```
