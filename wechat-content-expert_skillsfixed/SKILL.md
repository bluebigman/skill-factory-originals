## 一、能力边界与适用场景（一页纸速查卡）

### 本 Skill 能做什么

| 能力项 | 说明 |
|--------|------|
| 格式转换 | 将 Markdown 文本转换为带内联样式的 HTML，可直接粘贴至公众号编辑器 |
| 主题定制 | 内置 6 套预设主题，支持通过参数自定义主色、字体、间距等视觉属性 |
| 元素覆盖 | 支持标题（H1-H6）、段落、有序/无序列表、引用、代码块、表格、图片、分割线、加粗/斜体/行内代码 |
| 校验机制 | 自动检测 Markdown 语法错误、链接失效、图片缺失等问题，输出警告报告 |
| 批量处理 | 支持单文件、多文件、目录通配符三种输入模式 |

| 限制项 | 说明 |

| 不处理图片上传 | 图片需自行托管，本 Skill 仅保留原始 URL 与 alt 文本 |
| 不执行排版微调 | 转换后的 HTML 如需细节调整，请在公众号编辑器中手动操作 |
| 不支持复杂交互 | 不生成投票、小程序卡片、视频等公众号专属组件 |

## 三、标准工作流程

### 前置条件

1. 输入文件为 `.md` 格式，编码为 UTF-8
2. 图片 URL 可公开访问（或使用相对路径并在后续手动处理）
3. 本机已安装 Node.js 环境（用于执行 CLI 命令）

### 执行步骤

#### 步骤 1：准备输入内容

支持三种输入方式：

| 输入方式 | 示例 |
|----------|------|
| 文件路径 | `gzh design skill 文章.md` |
| URL | `gzh design skill https://example.com/article.md` |
| 直接粘贴 | 运行命令后粘贴文本，以 `EOF` 结束 |

#### 步骤 2：指定主题（可选）

| 参数 | 说明 | 示例 |
|------|------|------|
| `--theme` | 指定预设主题名 | `--theme tech-blue` |
| `--primary-color` | 自定义主色 | `--primary-color #FF6600` |
| `--font-family` | 自定义字体 | `--font-family "PingFang SC, Microsoft YaHei"` |
| `--font-size` | 正文字号（px） | `--font-size 16` |
| `--line-height` | 行高倍数 | `--line-height 1.8` |
| `--code-theme` | 代码块配色方案 | `--code-theme github-dark` |

#### 步骤 3：执行转换

```bash
gzh design skill 输入文件.md --theme tech-blue
```

#### 步骤 4：获取输出

转换完成后，在源文件同目录生成：

- `.html` 文件（与源文件同名）
- `.report.json` 文件（处理报告）

#### 步骤 5：粘贴至公众号

1. 打开生成的 `.html` 文件
2. 全选复制（Ctrl+A / Cmd+A）
3. 粘贴到公众号编辑器
4. 预览效果，如有需要微调

## 八、FAQ 与反模式对照

### 常见坑 1：样式丢失

**反模式**：直接复制 HTML 源码粘贴到公众号编辑器。

**正确做法**：在浏览器中打开 HTML 文件，全选复制渲染后的内容，再粘贴到编辑器。

### 常见坑 2：图片不显示

**反模式**：使用本地相对路径引用图片。

**正确做法**：确保图片 URL 为公网可访问的绝对地址，或先上传至图床。

### 常见坑 3：表格错位

**反模式**：在表格单元格中使用复杂嵌套结构。

**正确做法**：保持表格结构简单，避免在单元格内嵌套列表或代码块。

### 常见坑 4：主题参数不生效

**反模式**：同时使用 `--theme` 和 `--primary-color`，期望后者覆盖前者。

**正确做法**：`--theme` 指定基础主题，`--primary-color` 等参数仅用于派生主题（不指定 `--theme` 时基于默认主题派生）。

### 常见坑 5：批量处理时部分文件失败

**反模式**：忽略错误报告，直接使用部分成功的输出。

**正确做法**：查看每个文件的报告，单独处理失败文件。

使用本 Skill 时，首先准备 Markdown 格式的输入文件，确保文件内容符合标准 Markdown 语法规范。然后通过触发词（如"公众号排版"、"Markdown转HTML"）唤起 Skill，或直接指定输入文件路径。可选操作是指定主题名称或自定义主题参数，若不指定则使用默认主题。执行转换后，Skill 会生成带内联样式的 HTML 文件及一份处理报告，报告中包含转换结果、警告信息与校验详情。最后，将生成的 HTML 内容复制并粘贴至公众号编辑器中即可完成发布。对于批量场景，可使用目录通配符一次处理多篇文章，Skill 会为每篇生成独立的 HTML 文件。

## 示例

假设有一篇名为 `article.md` 的 Markdown 文章，内容包含标题、段落、列表、代码块与表格。用户输入"公众号排版 article.md"，Skill 将自动执行转换，生成 `article.html` 文件。该 HTML 文件中的每个元素均带有内联样式，粘贴至公众号编辑器后，标题层级、字体大小、颜色、间距等视觉属性均与所选主题一致。若文章中存在图片链接失效或表格语法错误，处理报告中会列出对应警告信息，用户可在粘贴前手动修正。若用户指定自定义主题参数（如主色为 `#ff6600`、正文字号为 `16px`），Skill 会按参数生成对应样式，并将配置保存至 `.gzh-theme.json` 供后续复用。

## 常见问题

**Q1：转换后的 HTML 粘贴到公众号后样式丢失怎么办？**  
请确认使用的是公众号编辑器自带的"粘贴"功能，而非快捷键直接粘贴。若仍丢失样式，请检查是否使用了不支持的浏览器或微信版本，建议使用 Chrome 或 Edge 浏览器的最新版本。

**Q2：图片无法显示是什么原因？**  
本 Skill 不处理图片上传，仅保留原始 URL 与 alt 文本。请确保图片 URL 可公开访问且未失效，同时确认图片链接为直接可访问的图片地址（如 `.jpg`、`.png` 结尾），而非网页链接。

**Q3：表格在公众号中显示错位如何处理？**  
表格错位通常由列宽不一致或单元格内容过长导致。建议在 Markdown 中保持表格列数一致，并适当精简单元格内容。若问题持续，可在公众号编辑器中手动调整表格列宽。

**Q4：自定义主题参数不生效怎么办？**  
请检查 `.gzh-theme.json` 文件是否位于当前工作目录，且 JSON 格式正确、字段名与内置主题参数表完全一致。同时确认在执行转换时指定了该配置文件，或将其命名为默认文件名以便自动加载。

**Q5：批量处理时部分文件转换失败如何处理？**  
请查看处理报告中对应的错误码与警告信息，定位失败原因。常见原因包括：文件编码不支持、Markdown 语法严重错误、文件路径包含特殊字符。修正后重新执行转换即可。
