# codexia — 表格智造 · 数据规整 · 字段映射

## 一、能力边界（一页纸速查卡）

### 1.1 工具定位

codexia 是一个**数据整形器**。它接收任意格式的输入数据（CSV、JSON、纯文本、日志片段等），在用户指定或自动推断的字段结构下，输出**带置信度标注的结构化表格**。适用于数据入库前的预处理、多源异构数据的统一规整、批量信息抽取等场景。

### 1.2 能做 / 不能做

| 维度 | ✅ 能做 | ❌ 不能做 |
|------|---------|-----------|
| 输入格式 | CSV、JSON、纯文本、半结构化日志、键值对列表 | 图像/PDF 中的文字识别（需先经 OCR 转文本） |
| 字段处理 | 字段自动推断、类型转换、字符串清洗、日期格式统一 | 跨表关联查询、数据库写入（需自行对接） |
| 批量能力 | 单批次处理任意数量文件，自动拆分 `needs_review` 记录 | 分布式并行计算（单机内存受限） |
| 置信度 | 字段级置信度标注（high / medium / low），记录级置信度聚合 | 置信度数值的细粒度解释（仅提供三档） |
| 规则扩展 | 通过 `--rules` 加载自定义转换规则（JSON 格式） | 规则热更新（需重启进程） |

## 三、标准流程

### 3.1 前置条件检查

2. **磁盘空间充足**：运行 `df -h .` 确认剩余空间 ≥ 输入文件总大小的 2 倍。

### 3.2 执行步骤

#### Step 1 — 单样本试运行

```bash
codexia 数据解析 --input sample_data.txt --dry-run
```

**输出内容**：
- 前 5 行转换结果预览
- 字段映射表（原始字段 → 目标字段 → 推断类型 → 置信度）
- 建议 schema（JSON 格式）

**示例输出**：

```
=== 转换预览（前 5 行）===
| id | name       | signup_date | tier     |
|----|------------|-------------|----------|
| 1  | 张三       | 2024-03-15  | premium  |
| 2  | 李四       | 2024/3/16   | free     |

=== 字段映射表 ===
原始字段     → 目标字段    → 类型    → 置信度
record_id    → id          → int     → high
full_name    → name        → string  → high
created_at   → signup_date → date    → medium
member_level → tier        → string  → high

=== 建议 Schema ===
{"fields": ["id", "name", "signup_date", "tier"]}
```

#### Step 2 — 核对字段

- 检查字段映射表，确认每个原始字段是否映射到正确目标字段。
- 若映射有误，可手动编辑 schema 文件（JSON 格式），指定字段类型与映射规则。
- 确认置信度标注是否符合预期。

#### Step 3 — 批量执行

```bash

```

**参数说明**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--input` | ✅ | 输入文件路径或目录通配符 |

| `--rules` | ❌ | 自定义转换规则文件（JSON） |
| `--dry-run` | ❌ | 试运行模式，仅输出预览不写文件 |
| `--selftest` | ❌ | 运行自检 |
| `--version` | ❌ | 显示版本号 |

#### Step 4 — 校验报告

批量执行完成后，codexia 生成 `validation_report.json`，包含：

- 总记录数、成功转换数、`needs_review` 数

## 四、置信度门控

### 4.1 置信度等级定义

| 等级 | 含义 | 触发条件 |
|------|------|----------|
| `high` | 字段值可靠，可直接使用 | 字段值格式与推断类型完全匹配，且来源明确 |
| `medium` | 字段值基本可靠，建议抽查 | 存在格式偏差（如日期分隔符不一致）、或值域超出常规范围 |
| `low` | 字段值存疑，需人工确认 | 字段值缺失、格式严重异常、或与 schema 类型冲突 |

### 4.2 记录级置信度聚合规则

1. **上限规则**：若某字段置信度为 `low`，则该条记录整体置信度上限为 `medium`。
2. **阈值规则**：若一条记录中 `low` 置信度字段超过 3 个，整条记录标记为 `needs_review`。
3. **分流规则**：批量处理时，`needs_review` 记录单独输出至 `review_queue.csv`，不混入主结果。

### 4.3 信息不足时的处理

当输入数据缺少某字段所需信息时，codexia **不会编造数据**，而是在对应单元格输出占位符：

```
[需核实:字段名]
```

例如，某条记录缺少 `phone` 字段，则输出 `[需核实:phone]`，并将该字段置信度标记为 `low`。

### 7.3 进阶路径（深度使用）

1. **自定义 Schema**：编写 schema JSON 文件，指定字段类型与映射规则。示例：

```json
{
  "fields": [
    {"name": "id", "type": "int", "source": "record_id"},
    {"name": "signup_date", "type": "date", "format": "%Y-%m-%d"}
  ]
}
```

```json
{
  "rules": [

    {"field": "name", "action": "strip_whitespace"}
  ]
}
```
