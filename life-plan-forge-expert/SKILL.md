## 三、标准流程（前置条件 → 执行步骤 → 输出规范）

### 3.1 前置条件（必须满足至少 2 项）

| 参数 | 是否必填 | 默认值 | 取值范围 |
|------|----------|--------|----------|

| 口味偏好 | 必填 | 无 | 清淡/辣/鲜香/酸甜/无特别要求 |
| 预算（人均日） | 选填 | 60 元 | 30-200 元/人/天 |
| 忌口/过敏 | 选填 | 无 | 如：不吃香菜、海鲜过敏、素食 |
| 热量统计 | 选填 | 否 | 是/否 |

### 3.2 执行步骤（分步编号）

**Step 1：信息收集**
- 若用户未一次性给全参数，按以下顺序追问：
  1. 几个人吃？
  2. 口味偏好？（给出选项：清淡/辣/鲜香/酸甜/不挑）
  3. 预算大概多少？（人均每天）
  4. 有没有忌口或过敏？
- 追问上限 3 轮，超过则使用默认值生成。

**Step 2：生成菜单**
- 根据人数 N 和预算 B（元/人/天），计算每日总预算 T = N × B。
- 按以下配比分配三餐成本：早餐 20%、午餐 40%、晚餐 40%。
- 菜单结构示例（以 2 人、辣味、人均 60 元/天为例）：

```
【第 1 天】
早餐（预算 24 元）：小米粥 + 煎蛋 + 凉拌黄瓜
午餐（预算 48 元）：辣椒炒肉 + 蒜蓉空心菜 + 米饭
晚餐（预算 48 元）：水煮鱼片（草鱼）+ 清炒豆芽 + 杂粮饭
```

**Step 3：生成采购清单**
- 将 7 天菜单中所有食材去重，按品类分组：
  - 蔬菜类（叶菜/根茎/菌菇）
  - 肉禽蛋类
  - 水产类
  - 主食类（米/面/杂粮）
  - 调味料（油盐酱醋等，按整瓶估算）
- 每项标注估算用量（如"土豆 2 斤"），基于人数和餐次推算。

**Step 4：热量统计（可选）**
- 若用户要求，在每餐后标注 `[约 XXX 千卡]`。
- 热量估算基于常见食材每 100g 热量值，取整十数。
- 输出日均总热量范围（如"日均约 1800-2100 千卡"）。

### 3.3 输出规范

- 菜单按天分块，每天包含早/午/晚三餐，每餐 1-2 道菜 + 主食。
- 采购清单按品类用 Markdown 表格输出，含"食材名 / 估算用量 / 备注"三列。
- 热量统计以括号形式附在菜名后，不单独成段。
- 所有输出使用中文，菜名用书名号括起。

## 六、FAQ 反模式（常见坑 + 对照）

### 坑 1：把"采购清单"当"菜谱"用
- **反模式**：用户拿到清单后问"这个土豆怎么炒？"
- **正确做法**：清单只负责"买什么"，菜谱做法需另行请求（如"给我土豆的 3 种做法"）。

### 坑 2：忽略忌口导致食材冲突
- **反模式**：用户说"不吃香菜"，但菜单里出现了凉拌香菜。
- **正确做法**：在 Step 1 信息收集阶段必须确认忌口，生成时全局过滤。

### 坑 3：预算按"每顿"而非"每天"理解
- **反模式**：用户说"预算 60"，实际意思是"每顿 60"，但 Skill 按"每天 60"处理。
- **正确做法**：追问时明确单位——"预算是指每人每天还是每顿？"若用户不明确，默认按"每人每天"。

### 坑 4：热量统计被当作精确营养数据
- **反模式**：用户拿热量数值去计算精确卡路里缺口。
- **正确做法**：输出时附带说明"热量为估算值，实际以食材称重为准"。

### 坑 5：菜单重复率高（连续两天出现同样菜）
- **反模式**：第 1 天和第 3 天都是"辣椒炒肉"。
- **正确做法**：生成时做去重检查，若重复则替换为同口味替代菜（如"青椒肉丝"）。

## 常见问题（FAQ）

**Q: 支持中文文件吗？**
A: 支持，内置 utf-8/gbk/gb18030 多编码容错。

**Q: 运行报错怎么办？**
A: 工具内置异常降级，错误会有明确提示；可先用 命令行参数(详见 --help) 预览。

**Q: 如何确认功能正常？**
A: 运行 --selftest，全部通过即核心功能正常。
