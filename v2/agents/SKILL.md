### 3.2 执行步骤

- 输出：结构化任务定义（JSON格式）

```json

  "task_id": "task_001",
  "objective": "完成竞品分析报告",
  "constraints": ["数据来源限公开渠道", "报告不超过5000字"],
  "output_format": "markdown"
}
```

**步骤2：任务拆解**

- 输入：结构化任务定义
- 操作：按依赖关系拆分为子任务，标注每个子任务的输入/输出
- 输出：任务依赖图（DAG）

```json

    {"id": "s1", "role": "collector", "depends_on": [], "output": "raw_data"},
    {"id": "s2", "role": "cleaner", "depends_on": ["s1"], "output": "clean_data"},
    {"id": "s3", "role": "analyst", "depends_on": ["s2"], "output": "analysis_result"},
    {"id": "s4", "role": "writer", "depends_on": ["s3"], "output": "final_report"}

```

**步骤3：Agent实例化**

- 输入：子任务列表
- 操作：为每个子任务创建Agent实例，配置模型参数与提示词模板
- 输出：Agent实例列表

| 参数 | 默认值 | 说明 |
|------|--------|------|
| model | gpt-4 | 底层模型 |
| temperature | 0.7 | 生成随机性 |
| max_tokens | 2048 | 最大输出长度 |
| system_prompt | 角色定义 | 系统提示词 |

**步骤4：执行调度**

- 输入：Agent实例列表 + 任务依赖图
- 操作：按拓扑序执行，无依赖的子任务并行运行
- 输出：各Agent执行结果

**步骤5：结果整合**

- 输入：各Agent输出
- 操作：按预定义Schema合并，检查完整性
- 输出：最终结构化结果

## 六、FAQ 反模式

### 6.1 常见坑与反模式对照

| 常见坑 | 反模式示例 | 正确做法 |
|--------|-----------|---------|
| 任务拆解过细 | 将"写一句话"拆成3个Agent | 子任务粒度以"可独立验证"为标准 |
| 角色职责重叠 | 两个Agent都负责"数据分析" | 明确每个Agent的输入/输出边界 |
| 忽略依赖关系 | 所有子任务并行执行 | 先画依赖图，再决定并行策略 |
| 输出格式不统一 | 各Agent自由输出 | 提前定义统一Schema并写入提示词 |
| 无错误恢复机制 | 单个Agent失败导致整个任务终止 | 设置重试机制和降级策略 |

### 6.2 反模式对照表

| 反模式 | 问题 | 替代方案 |
|--------|------|---------|
| 把所有逻辑塞进一个Agent | 单点故障，难以调试 | 按职责拆分，每个Agent专注一件事 |
| 不设超时限制 | 任务可能无限挂起 | 为每个Agent设置合理超时时间 |
| 忽略中间结果验证 | 错误被放大传递 | 每个Agent输出后立即校验 |
| 过度依赖Agent自主决策 | 结果不可控 | 在提示词中明确约束条件和输出格式 |
