## 三、标准处理流程

### 3.1 前置条件

- 输入内容需明确包含：**表名/字段名** 或 **数据文件路径** 或 **Schema描述**
- 若提供文件，需确认文件编码为UTF-8，且首行为字段名
- 若提供URL，需确保可公开访问且为结构化文档（如OpenAPI、DBML）

### 3.2 执行步骤

1. **解析输入**：提取表名、字段名、过滤条件、聚合需求等关键要素
2. **需求确认**：若存在歧义（如"最近"指7天还是30天），输出时标注 `[需核实:时间范围]`
3. **SQL构建**：按以下优先级组装语句：
   - 基础骨架：`SELECT ... FROM ... WHERE ...`
   - 聚合逻辑：`GROUP BY` + `HAVING`（如有）
   - 排序分页：`ORDER BY` + `LIMIT/OFFSET`
   - 高级特性：CTE/窗口函数（仅在用户明确要求时使用）
4. **方言适配**：根据用户指定的数据库类型调整语法（如SQLite无`IFNULL`用`COALESCE`）
5. **置信度标注**：对每个生成结果给出0-1的置信度值，低于0.7时附注原因
6. **输出整理**：按约定格式输出，包含SQL代码块、字段映射表、执行注意事项

### 3.3 输出规范

    p.category,
    COUNT(*) AS order_count,

JOIN products p ON o.product_id = p.id
WHERE o.created_at >= '2024-01-01'
GROUP BY p.category
HAVING COUNT(*) > 10
ORDER BY order_count DESC;

### 6.1 常见坑位

| 坑位描述 | 反模式（错误做法） | 正确模式 |
|----------|-------------------|----------|
| 字段名猜测错误 | 直接使用猜测字段名而不标注 | 使用 `[需核实:字段名]` 占位并列出候选 |
| 忽略SQL注入风险 | 将用户输入直接拼接到SQL中 | 生成参数化查询模板，标注 `?` 占位符 |
| 过度使用子查询 | 所有复杂查询都用嵌套子查询 | 优先推荐CTE（WITH语句）提升可读性 |
| 忽略NULL处理 | 直接比较可能为NULL的字段 | 自动添加 `IS NOT NULL` 或 `COALESCE` 处理 |
| 方言混用 | 在MySQL中使用SQL Server专有函数 | 根据目标数据库类型严格适配语法 |

### 6.2 反模式对照示例

**反模式：**
```sql
-- 用户说"查一下所有没付款的订单"
SELECT * FROM orders WHERE payment_status != 'paid';
-- 问题：未处理NULL状态，且未考虑大小写差异
```

**正确模式：**
```sql
SELECT * 
FROM orders 
WHERE COALESCE(LOWER(payment_status), '') NOT IN ('paid', 'completed');
-- 说明：处理NULL值，统一大小写，排除已支付状态
```
