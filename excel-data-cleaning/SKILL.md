## 一、能力边界速查卡

### ✅ 能做什么

| 序号 | 能力项 | 说明 | 关键参数 |
|------|--------|------|----------|
| 1 | **重复行清理** | 按指定列组合判断重复，支持全列比对或子集比对 | `dedup_cols` |
| 2 | **空白字符清理** | 去除字符串列首尾空格、全角空格、制表符 | `strip_cols` |
| 3 | **格式标准化** | 日期统一为 `YYYY-MM-DD`；金额去除千分位与货币符号；文本统一大小写 | `format_rules` |
| 4 | **异常值标记** | 3σ 离群值检测 + 正则校验邮箱/手机号/身份证，异常值前缀 `[异常]` | `anomaly_check` |
| 5 | **清洗报告生成** | 自动产出 HTML 报告：行数列数变化、异常明细、操作日志、数据质量评分 | 自动 |
| 6 | **多表合并** | 同一工作簿多 Sheet 合并；多个文件按行（纵向）或按列（横向）拼接 | `merge_type` |
| 7 | **编码修复** | 自动识别 UTF-8 BOM / GBK / Latin-1 乱码并修复 | 自动检测 |

### ❌ 不能做什么

| 限制项 | 具体边界 |
|--------|----------|
| 文件大小 | 单文件 ≤ 50MB，超过需拆分或开启 `batch_mode=true` |
| 行数上限 | 单表 ≤ 100 万行，超过需拆分或分批处理 |
| 输入格式 | 仅支持 `.xlsx`、`.xls`、`.csv`（CSV 需指定编码，默认 UTF-8） |
| 数据类型 | 不支持图片、嵌入对象、宏（`.xlsm` 仅读取值） |
| 自定义规则 | 不支持用户自定义 Python 表达式，仅支持预设清洗规则 |

## 三、标准执行流程

### 3.1 前置条件

| 项目 | 要求 |
|------|------|
| 输入文件 | 存在且可读，格式为 `.xlsx` / `.xls` / `.csv` |
| 文件编码 | CSV 需明确编码（默认 UTF-8，可指定 GBK） |
| 文件大小 | ≤ 50MB，行数 ≤ 100 万 |
| 列名 | 建议首行为表头；若首行非表头需说明 |

### 3.2 执行步骤

**Step 1 — 输入解析**

- 确认文件路径、格式、编码
- 读取表头与预览前 5 行
- 向用户展示结构摘要，请求确认清洗参数

**Step 2 — 参数确认**

| 参数名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `dedup_cols` | list | `[]` | 去重依据列；空表示不去重 |
| `strip_cols` | list | `[]` | 去空格列；空表示跳过 |
| `format_rules` | dict | `{}` | 格式规则映射，如 `{"日期":"YYYY-MM-DD"}` |
| `anomaly_check` | bool | `false` | 是否启用异常检测 |
| `merge_type` | str | `"none"` | `none` / `concat_rows` / `concat_cols` |
| `batch_mode` | bool | `false` | 超过 50MB 或 100 万行时开启分批 |
| `output_format` | str | `"xlsx"` | 输出格式：`xlsx` / `csv` |

**Step 3 — 执行清洗**

1. 编码检测与修复（自动）
2. 多表合并（如启用）
3. 去空格 → 格式标准化 → 去重 → 异常标记（按此顺序）
4. 每步操作记录日志（影响行数、操作类型）

**Step 4 — 结果校验**

- 检查输出文件行数、列数是否与预期一致
- 抽查 3-5 行数据确认清洗效果
- 生成置信度标注

**Step 5 — 报告生成与输出**

- 输出清洗后的文件（与原文件同目录，文件名后缀 `_cleaned`）
- 生成 HTML 清洗报告
- 返回摘要信息

### 3.3 输出规范

| 输出项 | 格式 | 说明 |
|--------|------|------|
| 清洗后文件 | `.xlsx` / `.csv` | 文件名：`原文件名_cleaned.扩展名` |
| 清洗报告 | `.html` | 文件名：`原文件名_cleaning_report.html` |
| 控制台摘要 | 文本 | 行数变化、异常统计、操作日志摘要 |

## 六、FAQ 反模式对照

### 常见坑与正确做法

| # | 常见错误（反模式） | 正确做法 |
|---|---------------------|----------|
| 1 | **盲目全列去重**：用户要求"全部去重"，结果把本应保留的重复客户记录也删了 | 先预览数据，确认哪些列应参与去重；推荐按业务主键（如订单号）去重 |
| 2 | **忽略列名大小写**：列名为 `CustomerName`，用户写 `customername` 报错 | 输入列名时与表头完全一致；或先请求系统列出所有可用列名 |
| 3 | **日期格式一刀切**：把 `2024/1/5` 和 `2024-01-05` 都统一为 `YYYY-MM-DD`，但部分数据是文本格式导致失败 | 先确认日期列的数据类型；文本型日期需先转换类型再格式化 |
| 4 | **异常标记覆盖原值**：异常值被 `[异常]` 前缀覆盖，后续计算无法使用原始数值 | 异常标记应放在新增列（如 `异常标记`），保留原始列不动 |
| 5 | **合并后不做校验**：多个文件合并后列顺序错乱，未发现 | 合并后自动校验列名一致性，输出列名对比表 |

### 反模式对照表

| 场景 | 反模式（不要这样做） | 正模式（推荐） |
|------|----------------------|----------------|
| 去重 | 全列去重，删除所有完全相同的行 | 按业务主键（订单号/客户ID）去重 |
| 去空格 | 对所有列去空格，包括数值列 | 仅对字符串列去空格，数值列保留原样 |
| 异常检测 | 对所有数值列做 3σ 检测 | 仅对正态分布的数值列做 3σ 检测；偏态数据用 IQR 方法 |
| 编码修复 | 直接按 UTF-8 读取所有文件 | 先检测 BOM / 统计乱码特征，再决定编码 |
| 报告输出 | 仅输出清洗后文件，无报告 | 同时输出 HTML 报告，含操作日志与异常明细 |

1. **概览卡片**：清洗前后行数 / 列数 / 变化率
