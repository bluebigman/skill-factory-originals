| 能力项 | 具体说明 | 输入示例 | 输出示例 |

| 去除重复项 | 按指定列（或全列）识别并移除重复行 | 客户名单（含重复手机号） | 去重后的唯一客户列表 |
| 格式统一 | 统一日期格式（YYYY-MM-DD）、数字格式（保留两位小数）、文本去空格 | 2024/1/5、2024年1月5日、2024-01-05 | 2024-01-05 |
| 空值处理 | 识别空单元格并标记或填充（可指定填充值） | 某列存在空白单元格 | 填充为"N/A"或指定值 |
| 列名规范化 | 将中文列名转为英文小写下划线命名，或统一为指定命名规则 | 客户名称、下单时间 | customer_name、order_time |
| 数据类型校正 | 将文本型数字转为数值型，将文本型日期转为日期型 | "123"（文本） | 123（数值） |
| 异常值标记 | 识别超出合理范围的值（如负数价格、超长文本） | 价格列出现 -5 | 标记为 [需核实:price] |

| 限制项 | 说明 |

| 不做数据可视化 | 不生成图表、仪表盘，仅输出清洗后的表格数据 |
| 不做统计分析 | 不计算均值、方差、回归等统计指标 |
| 不做数据合并 | 不合并多个来源的表格（如需合并，请先自行拼接） |

| 不处理图片/PDF | 仅处理结构化文本表格（CSV、TSV、Excel导出文本） |

**步骤 4：执行清洗**

## 六、FAQ 反模式对照

| 常见坑（反模式） | 问题描述 | 正确做法 |
|------------------|----------|----------|
| 盲目全列去重 | 用户对包含"备注"列的数据全列去重，导致本应保留的重复订单被删除 | 去重前先确认业务逻辑：通常按"订单号"或"用户ID"去重，而非全列 |
| 日期格式一刀切 | 将"2024/1/5"和"2024年1月5日"统一为"2024-01-05"时，未考虑用户可能希望保留原格式 | 先询问用户目标格式，再执行统一 |
| 空值填充过度 | 将数值列的空值填充为"N/A"，导致后续无法进行数值计算 | 数值列空值建议填充为0或保留空白，文本列填充"N/A" |
| 忽略异常值标记 | 清洗后直接使用数据，未处理被标记的 `[需核实:xxx]` 单元格 | 清洗后应人工复核所有标记单元格，确认或修正后再进入分析流程 |
| 列名翻译错误 | 将"客户名称"翻译为"customer_name"时，用户实际希望保留中文列名 | 列名规范化前先询问用户是否需要翻译，或保留原列名 |
