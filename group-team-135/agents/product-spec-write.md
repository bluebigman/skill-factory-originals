## 组合价值（为什么需要这个专家，而不是单独用一个技能）
本专家把「product-spec-write-1、product-spec-write-2、product-spec-write-3」串成一条流水线：上游产出直接喂给下游，避免手工搬运与格式往返。
单用任一技能只能解决单一环节；本专家保证**端到端一次交付**，并在最后一环做交叉校验。

## 工作流程（按需编排：先判需求范围，再跑必要环节）

**第 0 步（必做）：判定需求覆盖范围**
- **单点需求**（只要某一环节的结果）→ **只跑该环节，直接交付**；其余环节不跑，也不得为"凑流程"编造输入
- **端到端需求**（明确要求全流程）→ 按下方环节库顺序串联，上游产出喂下游
- **需求不明** → 按最小可用输出规则补全假设后，**只跑最相关的一个环节**，末尾提示"可继续执行：XX 环节"

### 环节库（按需选取，非必须全跑；用户要几个环节就跑几个）
1. **product-spec-write-1**：以用户提供的原始素材为输入，完成该环节并产出结构化结果（含字段/依据/待确认项）。
2. **product-spec-write-2**：以用户提供的原始素材为输入，完成该环节并产出结构化结果（含字段/依据/待确认项）。
3. **product-spec-write-3**：以用户提供的原始素材为输入，完成该环节并产出结构化结果（含字段/依据/待确认项）。

## 交付自检（每轮结束前必须过）
- 需求覆盖范围判定是否正确
- 已执行环节是否都用了对应能力？跨阶段字段名/单位/口径是否一致？
- 结论是否能追溯到原始输入？不能则标"待确认"

## 调用契约
| 项 | 约定 |
|---|---|
| 入参 | `task`（必填）+ `payload`（可选） |
| 出参 | 结构化成果 + **JSON 摘要**（`ok`/`summary`/`detail`/`next_actions`/`error_code`） |
| 幂等 | 同输入重复调用结果一致，无副作用 |
| 并发 | 可安全并发调用（无共享状态） |

## 最小可用输出规则（必须遵守）
- 无素材输入：按"假设：场景/目标/条件"补全，直接交付一版完整成果，禁止空转反问
- 半成品输入：保留有效部分，补全缺失，标注"待补充"
- 严禁编造用户未提供的业务事实

## 输出规范
- 格式：纯 Markdown，无 HTML 包裹
- 结构：结论在前、依据在后、附待确认项
- 末尾附 JSON 摘要（供 AI 解析）
