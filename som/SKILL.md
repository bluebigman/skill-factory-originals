## 三、标准处理流程

### 前置条件

| 条件项 | 要求 | 检查方式 |
|--------|------|----------|
| 输入文件 | 文件可读、编码为 UTF-8 或 GBK | 读取前先检测编码 |
| 命名规范 | 批量处理时文件名需包含序号或统一前缀 | 列出文件名清单供确认 |
| 处理规则 | 用户需明确输出格式（文件类型 + 字段结构） | 未明确时先询问 |
| 环境要求 | 本地目录有读写权限 | 测试写入一个临时文件 |

### 执行步骤（分步编号）

**步骤 1：输入确认**

- 接收用户提供的数据/文件/URL 列表
- 确认输入来源类型（文本/文件/URL）
- 确认输出格式要求（JSON/CSV/Markdown/自定义）

**步骤 2：单样本试运行**

- 取第一个样本执行完整流程
- 核对输出字段是否完整、格式是否正确
- 将试运行结果展示给用户确认

**步骤 3：批量执行**

- 用户确认试运行结果无误后，对全量数据执行
- 处理过程中保留原始文件备份（备份目录：`./backup/`）
- 每个文件处理完成后记录状态（成功/失败/跳过）

**步骤 4：结果校验**

- 抽查输出条目（建议抽查 10%-20%）
- 核对关键字段与源数据是否一致
- 对不一致项标注 `[需核实:字段名]`

**步骤 5：输出交付**

- 将结果整理为约定格式输出
- 附带处理报告（处理总数、成功数、失败数、需核实项列表）

### 输出规范

| 输出类型 | 字段结构要求 | 示例 |
|----------|--------------|------|
| JSON | 顶层为数组，每个对象包含 `id`、`data`、`confidence` 字段 | `[{"id":1,"data":{...},"confidence":0.95}]` |
| CSV | 首行为表头，字段间用逗号分隔，文本字段用引号包裹 | `id,title,date\n1,"示例",2024-01-01` |
| Markdown | 使用表格语法，表头加粗，对齐方式统一 | `\| id \| title \| date \|` |

## 四、置信度门控机制

### 置信度等级定义

| 等级 | 数值范围 | 含义 | 标注方式 |
|------|----------|------|----------|
| 高 | 0.90-1.00 | 字段值直接从输入中提取，无歧义 | 正常输出 |
| 中 | 0.70-0.89 | 字段值经过推断或转换，存在一定不确定性 | 输出值 + 置信度标注 |
| 低 | 0.50-0.69 | 字段值来自模糊匹配或缺失补全 | 输出值 + `[需核实:字段名]` |
| 无法确定 | <0.50 | 字段值无法从输入中推断 | 仅输出 `[需核实:字段名]` |

### 门控规则

1. **信息不足时**：不编造数据，使用 `[需核实:字段名]` 占位
2. **字段缺失时**：在输出中保留该字段位置，值为 `[需核实:字段名]`
3. **格式冲突时**：优先遵循用户指定格式，冲突处标注 `[需核实:格式]`
4. **批量处理时**：单条数据置信度低于 0.50 时，该条标记为"需人工复核"

### 置信度计算参考

| 场景 | 置信度 | 说明 |
|------|--------|------|
| 字段值直接匹配输入文本 | 0.95 | 无任何转换 |
| 字段值经过格式转换（如日期格式） | 0.85 | 转换规则明确 |
| 字段值来自正则匹配 | 0.75 | 匹配模式可能存在遗漏 |
| 字段值来自上下文推断 | 0.60 | 推断依据不充分 |
| 字段值完全无法确定 | 0.30 | 仅输出占位符 |

## 六、FAQ 反模式对照

### 常见坑 1：输入未清洗

**错误做法**：直接处理含大量无关字符的原始文本，导致输出字段被噪音污染。

**正确做法**：先进行预处理，去除无关字符、统一换行符、规范化空白。

### 常见坑 2：忽略编码问题

**错误做法**：假设所有文件都是 UTF-8 编码，遇到 GBK 文件时出现乱码。

**正确做法**：读取前检测文件编码，必要时进行编码转换。

### 常见坑 3：批量处理前未试运行

**错误做法**：直接对全量数据执行，发现格式错误后需要全部重来。

**正确做法**：先用单个样本试运行，确认输出格式无误后再批量执行。

### 常见坑 4：置信度标注缺失

**错误做法**：对不确定的字段直接输出猜测值，不标注任何提示。

**正确做法**：对置信度低于 0.70 的字段标注 `[需核实:字段名]`，提醒用户复核。

### 常见坑 5：输出格式与用户预期不符

**错误做法**：按自己的习惯输出格式，不确认用户的实际需求。

**正确做法**：执行前明确确认输出格式（文件类型 + 字段结构），必要时提供示例。
