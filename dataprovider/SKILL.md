# dataprovider Skill 文档

## 一、能力边界速查卡

本 Skill 定位于**学习与参考场景**下的数据规范化处理，不涉及任何生产环境的数据管道搭建或商业数据服务。

| 维度 | 说明 |
|------|------|
| **核心用途** | 将用户提供的原始数据（文本/文件/URL）转换为结构化的字段化结果 |
| **输入类型** | 纯文本段落、CSV/JSON 文件、网页 URL 指向的公开内容 |
| **输出形态** | Markdown 表格、JSON 对象、键值对清单（按用户指定格式） |
| **处理上限** | 单次批量不超过 200 条记录；单条记录原始文本不超过 5000 字符 |
| **处理耗时** | 单条平均 1-3 秒，批量 200 条约 5-10 分钟（视内容复杂度浮动） |

### 能做与不能做

**能做：**

1. 从非结构化文本中抽取实体与关键属性（如人名、日期、编号、金额）
2. 将半结构化文件（CSV/JSON）按新字段映射规则重新组织
3. 对网页 URL 指向的静态公开内容做字段化提取
4. 对提取结果逐字段标注置信度（高/中/低）
5. 按用户自定义模板输出结果（字段顺序、命名、格式可调）

**不能做：**

- 不能访问需登录认证的页面或接口
- 不能处理加密文件或二进制格式（图片内文字、PDF 扫描件）
- 不能对数据做语义推断或主观判断（如"这个数据是否合理"）
- 不能保证提取结果 100% 准确——所有输出均带置信度标注
- 不能替代专业数据清洗工具处理脏数据（缺失值、乱码等）

**适用对象：**

- 需要快速将零散资料整理为统一格式的学生、研究者
- 需要将网页内容转为可编辑表格的文案工作者
- 需要批量规范化文件名或字段命名的个人使用者

## 三、标准处理流程

### 前置条件

1. 待处理文件与 Skill 运行目录一致，文件名不含空格和特殊符号
2. 文件编码为 UTF-8（非 UTF-8 需先转换）
3. 批量处理时，所有文件遵循同一命名规范（如 `data_01.csv`、`data_02.csv`）
4. 明确告知输出格式（JSON / Markdown 表格 / 键值对清单）

### 执行步骤

**第一步：输入确认**

用户需提供以下信息（缺一不可）：

| 参数 | 必填 | 说明 | 示例 |
|------|------|------|------|
| `input` | 是 | 原始数据内容、文件路径或 URL | `./data/sample.csv` |
| `output_format` | 是 | 输出格式 | `json` / `md_table` / `kv_list` |
| `fields` | 否 | 自定义字段映射（不填则自动识别） | `{"name":"姓名","date":"日期"}` |
| `batch_mode` | 否 | 是否批量处理 | `true` / `false` |

**第二步：解析与识别**

- 自动检测输入类型（文本/文件/URL）
- 识别关键字段：日期（YYYY-MM-DD 或 YYYY/MM/DD）、金额（数字+货币符号）、编号（字母+数字组合）、人名（中文姓名或英文全名）
- 若用户提供 `fields` 映射，则按映射规则提取；否则自动识别常见字段

**第三步：置信度标注**

每个输出字段附带置信度标记：

| 置信度 | 标记 | 判定标准 |
|--------|------|----------|
| 高 | `[高]` | 字段值在原文中完整出现，无歧义 |
| 中 | `[中]` | 字段值经过格式转换或存在轻微歧义 |
| 低 | `[低]` | 字段值推断得出，原文未直接出现 |

**第四步：输出生成**

按用户指定格式输出结果，并附总览信息（处理条数、耗时、字段完整率）。

**第五步：自查校验**

- 检查字段完整性：是否有遗漏必填字段
- 检查格式正确性：日期格式统一、金额保留两位小数
- 检查置信度标注：低置信度字段是否已明确标记

## 四、置信度门控机制

当遇到以下情况时，本 Skill **不会**编造数据，而是输出占位符：

| 场景 | 输出行为 |
|------|----------|
| 原文中某字段缺失 | 输出 `[需核实:字段名]` |
| 字段值存在多种可能 | 输出 `[需核实:字段名]` 并附候选值列表 |
| 原文模糊（如"大约 3 号"） | 输出 `[需核实:日期]`，不推测具体日期 |
| 文件读取失败 | 输出错误码 `E1001`，不输出空结果 |

**示例：**

输入文本：`张三在三月中旬购买了价值约五千元的产品。`

输出：

```json
{
  "name": "张三 [高]",
  "purchase_date": "[需核实:日期]",
  "amount": "[需核实:金额]",
  "note": "原文为'三月中旬'和'约五千元'，无法确定精确值"
}
```

## 五、错误码体系

| 错误码 | 含义 | 提示话术 | 修正步骤 |
|--------|------|----------|----------|
| `E1001` | 文件读取失败 | "无法读取指定文件，请检查路径和权限" | 确认文件存在且可读，检查文件名拼写 |
| `E1002` | 编码不支持 | "文件编码不是 UTF-8，请转换后重试" | 使用文本编辑器另存为 UTF-8 编码 |
| `E1003` | URL 无法访问 | "目标 URL 无法访问或需要登录" | 确认 URL 可公开访问，或改为手动粘贴内容 |
| `E1004` | 字段映射冲突 | "自定义字段与自动识别字段冲突" | 检查 `fields` 参数，移除重复映射 |
| `E1005` | 批量文件命名不一致 | "批量文件命名不规范，无法匹配" | 统一文件命名格式后重试 |
| `E1006` | 单条记录超长 | "单条记录超过 5000 字符限制" | 拆分长文本为多条记录后处理 |
